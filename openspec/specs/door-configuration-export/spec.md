## Purpose

Определяет REST API, который по собранной в калькуляторе конфигурации двери (полотно с опциями, кромка, короб, наличник, добор, фурнитура) генерирует и отдаёт готовый Excel-файл со спецификацией — размерами и раздельными розничной/дилерской ценами по каждой позиции, — рассчитанными на backend теми же правилами, что и существующие этапные эндпоинты расчёта стоимости.

## Requirements

### Requirement: Эндпоинт выгрузки спецификации
Система ДОЛЖНА (SHALL) предоставлять эндпоинт `POST /api/specification/export`, принимающий: id существующего `leaf_type` (обязательно) с его опциями (размеры, цвет, исполнение зеркала, вид остекления); опционально — id вида кромки с её опциями, явный признак реверса, id короба с его опциями, id наличника с его опциями, id добора с его опциями, значение высоты полотна (для диапазонных проверок короба/наличника/добора — как в этапном расчёте короба и обрамления), список позиций фурнитуры. Состав и правила валидации этих полей ДОЛЖНЫ (SHALL) быть теми же, что и у существующих этапных эндпоинтов расчёта стоимости (`POST /api/leaf-types/{id}/price`, `POST /api/frame-types/{id}/price`, `POST /api/hardware/price`) — те же коды ошибок (404 для несуществующего `leaf_type`/`frame_type`, 400 для недопустимых или чужих id опций).

#### Scenario: Запрос без обязательного leaf_type отклоняется
- **WHEN** отправляется запрос без указания id `leaf_type` или с id, которого не существует
- **THEN** эндпоинт отвечает ошибкой 404 и не генерирует файл

#### Scenario: Недопустимая опция отклоняется так же, как в расчёте стоимости
- **WHEN** в запросе id выбранной опции (размер, цвет, кромка, наличник, добор) ссылается на компонент, отличный от указанного, либо не существует
- **THEN** эндпоинт отвечает ошибкой 400 и не генерирует файл — тем же кодом и по тем же условиям, что и соответствующий этапный эндпоинт расчёта

#### Scenario: Минимальный запрос — только полотно
- **WHEN** отправляется запрос с указанием только id `leaf_type` (без кромки, короба, наличника, добора и фурнитуры)
- **THEN** эндпоинт возвращает файл, содержащий только раздел «Полотно и опции полотна»

### Requirement: Формат ответа
Ответ эндпоинта выгрузки спецификации ДОЛЖЕН (SHALL) быть файлом в формате `.xlsx` (`Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`), с заголовком `Content-Disposition: attachment`, предлагающим браузеру сохранить файл, а не отобразить его как ответ страницы.

#### Scenario: Ответ помечен как вложение
- **WHEN** запрос выгрузки спецификации выполнен успешно
- **THEN** ответ содержит заголовок `Content-Disposition: attachment` с именем файла и тело в формате `.xlsx`

### Requirement: Разделы файла спецификации
Файл спецификации ДОЛЖЕН (SHALL) содержать до четырёх разделов с компонентами, в следующем порядке, включая в файл только те разделы, для которых в запросе присутствуют соответствующие данные:
1. «Полотно и опции полотна» — всегда присутствует (полотно обязательно); включает строку полотна, строки выбранных опций полотна (см. «Выбранные опции полотна в файле») и, если кромка указана в запросе, строку кромки.
2. «Короб и обрамление» — присутствует, если в запросе указан id короба; включает строку короба и, если у короба есть позиции frame_post (состав стоек), отдельную строку на каждую позицию.
3. «Наличники и доборы» — присутствует, если в запросе указан id наличника и/или id добора; включает строку на каждый из них.
4. «Фурнитура» — присутствует, если в запросе указана хотя бы одна позиция фурнитуры; включает отдельную строку на каждую позицию (без объединения одинаковых).

После разделов с компонентами файл, если к цене полотна применена хотя бы одна надбавка, ДОПОЛНИТЕЛЬНО ЗАВЕРШАЕТСЯ (SHALL) разделом «Надбавки к цене полотна» (см. соответствующее требование) — под всей таблицей расчётов, а не внутри раздела полотна.

#### Scenario: Раздел «Короб и обрамление» отсутствует без короба
- **WHEN** запрос не содержит id короба
- **THEN** файл не содержит раздела «Короб и обрамление» и раздела «Наличники и доборы»

#### Scenario: Раздел «Наличники и доборы» показывает только присутствующие компоненты
- **WHEN** запрос содержит id короба и id наличника, но не id добора
- **THEN** раздел «Наличники и доборы» содержит только строку наличника

#### Scenario: Состав короба выгружается построчно
- **WHEN** запрос содержит id короба, для которого каталог отдаёт непустой список позиций frame_post
- **THEN** раздел «Короб и обрамление» содержит отдельную строку для короба и по одной строке на каждую позицию frame_post — так же, как эти позиции показываются в разбивке результата расчёта (см. door-configurator-ui, «Отображение позиций короба», включая исключение длины для позиции «Комплект зарезных стоек»)

### Requirement: Содержимое строки спецификации
Каждая строка раздела 1–3 (полотно, кромка, короб, позиции состава короба, наличник, добор) ДОЛЖНА (SHALL) содержать полное наименование компонента (`name` выбранного типа — без сокращения до `short_name`, в отличие от отображения в интерфейсе калькулятора), итоговую и базовую (до применения наценок) розничную и дилерскую цену, рассчитанные теми же правилами (включая надбавки), что и в соответствующем этапном эндпоинте расчёта стоимости, — и, где для этого компонента применимо, значения его размеров в мм (длина и/или высота и/или толщина — в зависимости от того, какие из них применимы для этого типа компонента, включая высоту короба, если она выбирается из каталога или зеркалируется от высоты полотна, — объединённые в одно значение через `*`, например `900*2400*44`) и выбранный цвет, если он выбран. Строки раздела 4 (фурнитура) ДОЛЖНЫ (SHALL) содержать наименование категории и типа фурнитуры, цветовой вариант, количество и цену (розничную и дилерскую) с учётом количества — как в ответе `POST /api/hardware/price`; у фурнитуры и у позиций состава короба базовая цена всегда совпадает с итоговой (наценки к ним не применяются). Если для строки не найдена цена (нет подходящей `configuration_price`), строка ДОЛЖНА (SHALL) присутствовать в файле с прочерком вместо цены (в обеих парах колонок — базовой и итоговой), а не быть пропущена.

#### Scenario: Строка полотна содержит размеры, цвет и цену
- **WHEN** для полотна в запросе указаны длина, высота и цвет, и для них найдена цена
- **THEN** строка полотна в файле содержит наименование модели полотна, объединённые размеры в мм, наименование цвета и раздельно итоговую (с учётом применённых надбавок) и базовую розничную и дилерскую цену

#### Scenario: Высота короба показывается, если применима
- **WHEN** короб в запросе — из числа выбирающих высоту из каталога либо зеркалирующих её от высоты полотна
- **THEN** строка короба в файле содержит эту высоту в мм

#### Scenario: Компонент без применимого размера не показывает размеры
- **WHEN** строка соответствует компоненту, для которого размер не применим (например, короб без выбираемой высоты)
- **THEN** ячейка размеров этой строки остаётся пустой, а не содержит нулевые или произвольные значения

#### Scenario: Ненайденная цена отображается прочерком
- **WHEN** для выбранных опций компонента не найдено подходящей строки `configuration_price`
- **THEN** строка этого компонента присутствует в файле, а ячейки базовой и итоговой цены содержат прочерк вместо числа

#### Scenario: Позиция фурнитуры содержит категорию, тип, цвет и количество
- **WHEN** запрос содержит позицию фурнитуры с количеством больше 1
- **THEN** строка фурнитуры в файле содержит наименование категории и типа фурнитуры, цветовой вариант, указанное количество и цену с учётом количества

### Requirement: Выбранные опции полотна в файле
Раздел «Полотно и опции полотна» ДОЛЖЕН (SHALL) содержать, сразу под строкой полотна и до строки кромки (если она есть), отдельную строку на каждую заметную выбранную опцию полотна: тип открывания — только если запрос указывает признак реверса (значение «Реверс»; при отсутствии признака отдельная строка не добавляется, поскольку «Прямое» — значение по умолчанию); исполнение зеркала — если оно выбрано, с наименованием конкретного исполнения; вид остекления — если он выбран, с наименованием конкретного вида остекления (включая базовое «Прозрачное», без наценки). У этих строк нет ни размеров, ни собственной цены — только наименование.

#### Scenario: Реверс, исполнение зеркала и вид остекления показаны отдельными строками
- **WHEN** в запросе указан признак реверса, исполнение зеркала и вид остекления
- **THEN** сразу под строкой полотна файл содержит три дополнительные строки — тип открывания «Реверс», конкретное исполнение зеркала, конкретный вид остекления

#### Scenario: Без реверса строка типа открывания отсутствует
- **WHEN** в запросе не указан признак реверса
- **THEN** файл не содержит строки типа открывания под полотном

### Requirement: Итоговая сумма в файле
Файл ДОЛЖЕН (SHALL) содержать раздел «Итоговая сумма» после всех разделов с компонентами (включая «Фурнитура», если она присутствует) и до раздела «Надбавки к цене полотна» (если он присутствует) — без строки заголовков колонок общей раскладки (Наименование/Измерения/Цвет/Количество), а с колонками «Итоговая цена» и «Итоговая цена дилер», расположенными в тех же колонках листа, что и «Итоговая цена, ₽» и «Цена дилер, ₽» в разделах с компонентами (чтобы суммы визуально стояли строго под соответствующими колонками цены). Значения ДОЛЖНЫ (SHALL) быть суммой итоговых (не базовых) цен всех строк файла, для которых найдена цена (полотно, кромка, короб и его позиции состава, наличник, добор, фурнитура) — строки без найденной цены в сумму не входят, тем же принципом, что и в существующих этапных эндпоинтах расчёта стоимости.

#### Scenario: Итоговая сумма стоит между фурнитурой и надбавками
- **WHEN** запрос содержит фурнитуру и надбавки к цене полотна
- **THEN** раздел «Итоговая сумма» в файле расположен сразу после раздела «Фурнитура» и перед разделом «Надбавки к цене полотна»

#### Scenario: Ненайденная цена не входит в итоговую сумму
- **WHEN** для одного из компонентов конфигурации не найдена цена
- **THEN** значения раздела «Итоговая сумма» не включают этот компонент, как если бы его цена была нулевой

### Requirement: Надбавки к цене полотна в файле
Если к цене полотна применена хотя бы одна надбавка (за нестандартную длину/высоту, исполнение зеркала, вид остекления, реверс), файл ДОЛЖЕН (SHALL) содержать отдельный завершающий раздел «Надбавки к цене полотна» — под всеми разделами компонентов, а не внутри раздела полотна — с отдельной строкой на каждую применённую надбавку: наименованием и процентом, теми же формулировками, что и в разбивке «Надбавки к цене полотна» результата расчёта на фронте. У строки надбавки нет собственной цены (сама надбавка уже учтена в цене строки полотна) — ячейки цены и размеров ДОЛЖНЫ (SHALL) оставаться пустыми, не содержать прочерк (прочерк означает именно ненайденную цену компонента, а не неприменимость поля). Раздел ДОЛЖЕН (SHALL) НЕ содержать строку заголовков колонок (Наименование/Измерения/Цвет/Количество/цены), применимую к разделам с компонентами, — она не несёт смысла для строк, у которых есть только наименование и процент; строки надбавок идут сразу за заголовком раздела.

#### Scenario: Применённые надбавки перечислены в завершающем разделе
- **WHEN** к цене полотна применены надбавка за нестандартный размер и надбавка за реверс
- **THEN** под всеми разделами компонентов файл содержит раздел «Надбавки к цене полотна» с двумя строками — по одной на каждую надбавку, с её названием и процентом

#### Scenario: Без надбавок завершающий раздел отсутствует
- **WHEN** к цене полотна не применена ни одна надбавка
- **THEN** файл не содержит раздела «Надбавки к цене полотна»
