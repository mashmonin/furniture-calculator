## Purpose

Определяет справочник декоративных элементов (плинтус и другие подобные позиции в будущем) и REST API для его чтения — независимо от каталога конфигураций дверей, по аналогии с hardware-catalog.

## Requirements

### Requirement: Структура decorative_element_category
Decorative_element_category ДОЛЖНА (SHALL) иметь непустое человекочитаемое название (name) и непустой код (code), уникальный в пределах справочника.

#### Scenario: Категория требует name и code
- **WHEN** строка decorative_element_category вставляется без name или без code
- **THEN** база данных отклоняет вставку

### Requirement: Структура decorative_element_type
Decorative_element_type ДОЛЖЕН (SHALL) ссылаться ровно на одну decorative_element_category и иметь непустое название (name), код (code, уникальный в пределах справочника), длину в миллиметрах (length_mm), розничную (retail_price) и дилерскую (dealer_price) цену — все пять полей обязательны. Дополнительно decorative_element_type МОЖЕТ (MAY) иметь ширину (width_mm) и толщину (thickness_mm) в миллиметрах — оба поля необязательны (nullable) и задаются только там, где эти размеры имеют смысл для категории. Тип описывает готовую позицию целиком (например, «Плинтус Модо», длина 2400 мм) — в отличие от фурнитуры, у decorative_element_type нет собственных цветовых вариантов с отдельными ценами.

#### Scenario: Тип требует категорию, name, code, длину и обе цены
- **WHEN** строка decorative_element_type вставляется без ссылки на decorative_element_category, без name, без code, без length_mm, без retail_price или без dealer_price
- **THEN** база данных отклоняет вставку

#### Scenario: У одной категории может быть несколько типов
- **WHEN** для одной decorative_element_category вставляются несколько строк decorative_element_type с разными name/code
- **THEN** все строки сохраняются и все ссылаются на эту категорию

#### Scenario: Ширина и толщина необязательны
- **WHEN** строка decorative_element_type вставляется без width_mm и без thickness_mm
- **THEN** база данных принимает вставку, width_mm и thickness_mm сохраняются как NULL

### Requirement: Владение decorative_element_option
Decorative_element_option ДОЛЖЕН (SHALL) ссылаться ровно на один decorative_element_type и ровно один leaf_type — какой декоративный элемент допустим для какой модели полотна (т.е. для какой коллекции, поскольку каждый leaf_type принадлежит ровно одной коллекции). Комбинация decorative_element_type и leaf_type ДОЛЖНА (SHALL) быть уникальной.

#### Scenario: Запись decorative_element_option требует leaf_type и decorative_element_type
- **WHEN** строка decorative_element_option вставляется без ссылки на leaf_type или без ссылки на decorative_element_type
- **THEN** база данных отклоняет вставку

#### Scenario: Декоративный элемент не может повторяться для одного полотна
- **WHEN** для одного и того же leaf_type вставляется вторая строка decorative_element_option с уже существующим decorative_element_type
- **THEN** база данных отклоняет вставку

#### Scenario: Один и тот же декоративный элемент допустим для нескольких моделей полотна
- **WHEN** для одного decorative_element_type вставляются строки decorative_element_option для нескольких разных leaf_type
- **THEN** все строки сохраняются независимо

### Requirement: Плинтус «Модо» и «Модо облегчённый» доступны для всех коллекций, кроме «Фантом»
Каталог ДОЛЖЕН (SHALL) содержать decorative_element_category «Плинтус» и ровно два decorative_element_type в её составе: «Плинтус Модо» (длина 2400 мм, retail_price 2611, dealer_price 1492) и «Плинтус Модо облегчённый» (длина 2400 мм, retail_price 2611, dealer_price 1492). Для каждого из этих двух типов ДОЛЖНА (SHALL) существовать строка decorative_element_option для каждого leaf_type, чья коллекция отлична от «Фантом» (`LC-009`), и НЕ ДОЛЖНО (SHALL NOT) существовать ни одной строки decorative_element_option, ссылающейся на leaf_type коллекции «Фантом».

#### Scenario: Плинтус доступен для полотна не-Фантом коллекций
- **WHEN** запрашивается список допустимых decorative_element_option для leaf_type любой коллекции, кроме «Фантом»
- **THEN** в списке присутствуют оба типа плинтуса — «Плинтус Модо» и «Плинтус Модо облегчённый»

#### Scenario: Плинтус недоступен для полотна коллекции «Фантом»
- **WHEN** запрашивается список допустимых decorative_element_option для leaf_type коллекции «Фантом»
- **THEN** список пуст

### Requirement: «Блок А», «База А», «Блок В», «База В» и «База В КОМПЛАНАР» доступны для коллекций «Элегант» и «Гармония»
Каталог ДОЛЖЕН (SHALL) содержать decorative_element_category «Блок и база» и ровно пять decorative_element_type в её составе:

| Тип | length_mm | dealer_price | retail_price |
|---|---|---|---|
| «Блок А» | 90 | 1154 | 2021 |
| «База А» | 252 | 1830 | 3203 |
| «Блок В» | 91 | 1154 | 2021 |
| «База В» | 200 | 1830 | 3203 |
| «База В КОМПЛАНАР» | 200 | 1830 | 3203 |

Для каждого из этих пяти типов ДОЛЖНА (SHALL) существовать строка decorative_element_option для каждого leaf_type, чья коллекция — «Элегант» (`LC-003`) или «Гармония» (`LC-004`), и НЕ ДОЛЖНО (SHALL NOT) существовать ни одной строки decorative_element_option, ссылающейся на leaf_type любой другой коллекции.

#### Scenario: Блок и база доступны для полотна «Элегант» и «Гармония»
- **WHEN** запрашивается список допустимых decorative_element_option для leaf_type коллекции «Элегант» или «Гармония»
- **THEN** в списке присутствуют все пять типов — «Блок А», «База А», «Блок В», «База В» и «База В КОМПЛАНАР»

#### Scenario: Блок и база недоступны для полотна остальных коллекций
- **WHEN** запрашивается список допустимых decorative_element_option для leaf_type любой коллекции, кроме «Элегант» и «Гармония»
- **THEN** ни один из пяти типов категории «Блок и база» в списке не присутствует

### Requirement: Ширина и толщина типов категории «Блок и база»
Каждый decorative_element_type категории «Блок и база» (`DEC-002`) ДОЛЖЕН (SHALL) иметь заполненные width_mm и thickness_mm со следующими значениями:

| Тип | width_mm | thickness_mm |
|---|---|---|
| «Блок А» | 90 | 30 |
| «База А» | 90 | 30 |
| «Блок В» | 91 | 30 |
| «База В» | 91 | 31 |
| «База В КОМПЛАНАР» | 91 | 31 |

Для decorative_element_type категории «Плинтус» (`DEC-001`) width_mm и thickness_mm остаются NULL.

#### Scenario: Блок и база хранят ширину и толщину
- **WHEN** запрашивается строка decorative_element_type с кодом одним из `DET-003`…`DET-007`
- **THEN** её width_mm и thickness_mm равны значениям из таблицы выше

#### Scenario: Плинтус не имеет ширины и толщины
- **WHEN** запрашивается строка decorative_element_type с кодом `DET-001` или `DET-002`
- **THEN** её width_mm и thickness_mm равны NULL

### Requirement: Получение каталога декоративных элементов
Система ДОЛЖНА (SHALL) предоставлять эндпоинт, возвращающий полный каталог декоративных элементов в виде списка категорий; для каждой категории — данные (id, code, name) и список её типов; для каждого типа — id, code, name, длину (length_mm), розничную и дилерскую цену. Каталог не зависит от какой-либо door_configuration, leaf_type или коллекции и не принимает параметров запроса — фильтрация по допустимости для конкретной коллекции (см. «Владение decorative_element_option») выполняется на фронтенде по каталогу конфигураций конфигуратора (см. door-configurator-ui), так же, как это уже устроено для colour_option и mirror_finish_option.

#### Scenario: Каталог возвращает полную иерархию
- **WHEN** запрашивается каталог декоративных элементов и в базе есть категория с двумя типами
- **THEN** в ответе присутствует эта категория с обоими типами, включая длину и обе цены каждого типа

#### Scenario: Пустой каталог
- **WHEN** запрашивается каталог декоративных элементов и в базе нет ни одной категории
- **THEN** эндпоинт возвращает пустой список с кодом 200, а не ошибку

### Requirement: Допустимые декоративные элементы для leaf_type в каталоге конфигураций
Каталог конфигураций (см. door-configuration-api, «Получение каталога конфигураций») ДОЛЖЕН (SHALL) для leaf-компонента каждой door_configuration включать список допустимых decorative_element_type (определяется наличием строки decorative_element_option для пары этот leaf_type + тип) — id, name и код категории. Для компонентов, отличных от leaf (frame, edge, doorCasing, frameExtensions), список ДОЛЖЕН (SHALL) быть пустым.

#### Scenario: Полотно не-Фантом коллекции показывает допустимые декоративные элементы
- **WHEN** запрашивается каталог конфигураций и leaf_type данной door_configuration имеет строки decorative_element_option
- **THEN** в ответе для leaf-компонента этой конфигурации присутствует список этих декоративных элементов

#### Scenario: Полотно коллекции «Фантом» не показывает декоративные элементы
- **WHEN** запрашивается каталог конфигураций и leaf_type данной door_configuration принадлежит коллекции «Фантом»
- **THEN** в ответе для leaf-компонента этой конфигурации список декоративных элементов пуст
