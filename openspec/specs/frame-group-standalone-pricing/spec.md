## Purpose

Определяет REST API, который рассчитывает стоимость короба и, опционально, наличника и добора по их типам — независимо от полотна, кромки и фурнитуры, и без необходимости заранее знать согласованную `door_configuration`, объединяющую эти компоненты с конкретным полотном.

## Requirements

### Requirement: Расчёт стоимости короба, наличника и добора по типу короба
Система ДОЛЖНА (SHALL) предоставлять эндпоинт расчёта стоимости, принимающий id существующего `frame_type` и набор выбранных клиентом опций короба: id `colour_option`. Эндпоинт МОЖЕТ (MAY) дополнительно принимать id типа наличника (`door_casing_type`) с его опциями (id `liner_dimension_option` для длины, количество) и id типа добора (`frame_extensions_type`) с его опциями (id `liner_dimension_option` для длины, количество) — по тем же правилам, что и при расчёте по `door_configuration`. Полотно, кромка, фурнитура и декоративные элементы эндпоинтом не рассматриваются, даже если присутствуют в запросе.

Указанный id `door_casing_type` ДОЛЖЕН (SHALL) ссылаться на тип наличника, для которого существует хотя бы одна строка `door_configuration` с этим `frame_type` и этим `door_casing_type`; иначе — ошибка 400. Аналогично, указанный id `frame_extensions_type` ДОЛЖЕН (SHALL) ссылаться на тип добора, для которого существует хотя бы одна строка `door_configuration` с этим `frame_type` и этим `frame_extensions_type`; иначе — ошибка 400.

#### Scenario: Расчёт стоимости короба без наличника и добора
- **WHEN** отправляется запрос расчёта с id существующего `frame_type` без указанных типов наличника и добора
- **THEN** эндпоинт возвращает результат с найденной (если есть подходящая строка `configuration_price` и/или позиции `frame_post`) или не найденной ценой короба, без ошибки, и без записей о наличнике/доборе в разбивке

#### Scenario: Несуществующий тип короба
- **WHEN** отправляется запрос расчёта с id `frame_type`, которого не существует
- **THEN** эндпоинт отвечает ошибкой 404 и не выполняет расчёт

#### Scenario: Опция короба не принадлежит указанному типу короба
- **WHEN** в запросе id выбранной `colour_option` ссылается на компонент, отличный от указанного `frame_type`
- **THEN** эндпоинт отвечает ошибкой 400 и не выполняет расчёт

#### Scenario: Наличник и добор принимаются и считаются вместе с коробом
- **WHEN** в запросе указаны id типа наличника и/или id типа добора, для которых существует door_configuration с этим frame_type, и их опции
- **THEN** запрос обрабатывается без ошибки валидации формата запроса, наличник и/или добор учитываются в расчёте по тем же правилам, что и при расчёте по door_configuration (включая количество)

#### Scenario: Наличник, недопустимый для указанного короба, отклоняется
- **WHEN** указанный id типа наличника существует, но не существует ни одной строки door_configuration с этим frame_type и этим door_casing_type
- **THEN** эндпоинт отвечает ошибкой 400 и не выполняет расчёт

#### Scenario: Добор, недопустимый для указанного короба, отклоняется
- **WHEN** указанный id типа добора существует, но не существует ни одной строки door_configuration с этим frame_type и этим frame_extensions_type
- **THEN** эндпоинт отвечает ошибкой 400 и не выполняет расчёт

#### Scenario: Несуществующий тип наличника или добора недопустим
- **WHEN** указанный id типа наличника или добора не существует ни в одной строке соответствующего справочника
- **THEN** эндпоинт отвечает ошибкой 400 и не выполняет расчёт

#### Scenario: Декоративные элементы в запросе игнорируются
- **WHEN** в запросе присутствует список позиций декоративных элементов
- **THEN** эндпоинт игнорирует его — в разбивке результата нет записей о декоративных элементах, а итоговая сумма их не включает

### Requirement: Учёт высоты полотна в валидациях короба, наличника и добора
Поскольку эндпоинт не получает опций полотна напрямую, запрос МОЖЕТ (MAY) явно указывать уже известное клиенту значение высоты полотна (числовое значение в мм). Все существующие правила, зависящие от высоты полотна при расчёте по `door_configuration` (диапазон высоты короба «НЕО»/«Компланар», точное совпадение высоты короба «Фантом» с высотой полотна, диапазон длины наличника/добора, ограниченный высотой полотна), ДОЛЖНЫ (SHALL) применяться так же, используя это значение вместо значения, вычисленного из опций полотна. Если значение не передано, а выбранный тип короба/наличника/добора требует его для валидации, ДОЛЖНА (SHALL) возвращаться та же ошибка 400, что и при расчёте по `door_configuration`, когда высота полотна не выбрана.

#### Scenario: Диапазон высоты короба проверяется по переданному значению
- **WHEN** выбран короб, чья высота ограничена диапазоном высоты полотна (см. door-configuration-api), и в запросе передано значение высоты полотна вне этого диапазона
- **THEN** эндпоинт отвечает ошибкой 400 и не выполняет расчёт — так же, как при расчёте по door_configuration с той же высотой полотна

#### Scenario: Без переданной высоты полотна для короба, которому она не требуется, ошибки нет
- **WHEN** выбранный короб не входит ни в один набор коробов, зависящих от высоты полотна, и высота полотна в запросе не передана
- **THEN** расчёт короба выполняется без ошибки

#### Scenario: Отсутствие высоты полотна для короба, которому она требуется, отклоняется
- **WHEN** выбран короб, чья высота обязана совпадать с высотой полотна или лежать в её диапазоне, а значение высоты полотна в запросе не передано
- **THEN** эндпоинт отвечает ошибкой 400 и не выполняет расчёт — та же ошибка, что и при расчёте по door_configuration без выбранной высоты полотна

### Requirement: Состав ответа расчёта стоимости короба и обрамления
Ответ эндпоинта ДОЛЖЕН (SHALL) содержать итоговую розничную и дилерскую цену (короб и, если запрошены, наличник и добор вместе) и разбивку с одной записью для короба и, если их id были указаны в запросе, отдельными записями для наличника и добора (каждая — найденная цена либо отметка, что не найдена). Цена короба, наличника и добора в этой разбивке ДОЛЖНА (SHALL) учитывать наценку за нестандартную длину/высоту погонажа по тем же правилам, что и при расчёте по door_configuration (см. door-configuration-api, «Наценка за нестандартную длину/высоту короба, наличника и добора»); запись компонента в разбивке ДОЛЖНА (SHALL) содержать его базовую цену (до этой наценки) наряду с итоговой, по тем же правилам, что и в ответе основного расчёта стоимости (см. door-configuration-api, «Базовая цена компонента в ответе расчёта стоимости»).

#### Scenario: Успешный расчёт короба
- **WHEN** для указанного `frame_type` найдена подходящая цена (или позиции frame_post)
- **THEN** ответ содержит итоговую сумму и запись о цене короба в разбивке

#### Scenario: Короб без найденной цены
- **WHEN** для указанного `frame_type` не найдено ни подходящей строки `configuration_price`, ни позиций `frame_post`
- **THEN** эндпоинт отвечает кодом 200, запись о коробе в разбивке отмечена как без найденной цены

#### Scenario: Наличник и добор указываются в разбивке отдельными записями
- **WHEN** в запросе указаны и наличник, и добор, для обоих найдена подходящая цена
- **THEN** в разбивке присутствуют три записи — короб, наличник и добор, каждая со своей ценой, а итоговая сумма равна их сумме

#### Scenario: Наценка за нестандартный погонаж отражена в цене короба
- **WHEN** для указанного `frame_type` выбрана (каталожная либо, для короба «Фантом», переданная явно через высоту полотна) высота, для которой существует строка pogonazh_surcharge_rule этого frame_type
- **THEN** итоговая цена короба в разбивке включает эту наценку, а базовая цена компонента равна цене без неё

#### Scenario: Наценка за нестандартный погонаж отражена в цене наличника и добора
- **WHEN** для указанного door_casing_type/frame_extensions_type выбрана каталожная опция длины, для которой существует строка pogonazh_surcharge_rule этого владельца
- **THEN** итоговая цена соответствующего компонента в разбивке включает эту наценку, а базовая цена компонента равна цене без неё
