## Purpose

Определяет справочник фурнитуры (замки, цилиндры, петли, дополнительная фурнитура, крепление плинтуса, ручки для раздвижных дверей) и REST API для его чтения — независимо от каталога конфигураций дверей.

## Requirements

### Requirement: Получение каталога фурнитуры
Система ДОЛЖНА (SHALL) предоставлять эндпоинт, возвращающий полный каталог фурнитуры в виде списка категорий; для каждой категории — данные (id, code, name) и список её типов фурнитуры; для каждого типа — данные (id, code, name), единица измерения и список его цветовых вариантов; для каждого цветового варианта — id, название цвета, розничная (retail) и дилерская (dealer) цена. Каталог не зависит от какой-либо door_configuration и не принимает параметров запроса.

#### Scenario: Каталог возвращает полную иерархию
- **WHEN** запрашивается каталог фурнитуры и в базе есть категория с типом фурнитуры, имеющим два цветовых варианта
- **THEN** в ответе присутствует эта категория с этим типом, включая единицу измерения типа и оба цветовых варианта с их id, названием цвета и ценами

#### Scenario: Тип фурнитуры с единственным цветовым вариантом
- **WHEN** запрашивается каталог фурнитуры и тип фурнитуры имеет только один цветовой вариант
- **THEN** в ответе для этого типа присутствует список из одного цветового варианта, запрос не завершается ошибкой

#### Scenario: Пустой каталог
- **WHEN** запрашивается каталог фурнитуры и в базе нет ни одной категории фурнитуры
- **THEN** эндпоинт возвращает пустой список с кодом 200, а не ошибку

### Requirement: Уникальность и обязательность цены цветового варианта фурнитуры
Каждый цветовой вариант фурнитуры (hardware_option) ДОЛЖЕН (SHALL) иметь ровно одну розничную и одну дилерскую цену — по этим же значениям он участвует в расчёте стоимости (см. door-configuration-api, «Учёт фурнитуры в расчёте стоимости изделия»). Цветовой вариант однозначно идентифицируется своим id при выборе в расчёте.

#### Scenario: Цена варианта фурнитуры используется как есть
- **WHEN** для позиции фурнитуры в расчёте стоимости выбран id существующего цветового варианта
- **THEN** используются ровно розничная и дилерская цена, хранящиеся у этого варианта в каталоге фурнитуры

### Requirement: Прайс-лист типа фурнитуры в каталоге
Для каждого типа фурнитуры в ответе каталога фурнитуры система ДОЛЖНА (SHALL) включать прайс-лист (id, code, name — название файла), которому принадлежит этот тип. Цветовые варианты отдельного прайс-листа не содержат — он общий для типа.

#### Scenario: Тип фурнитуры содержит прайс-лист
- **WHEN** запрашивается каталог фурнитуры и тип фурнитуры принадлежит price_list `PL-001`
- **THEN** в ответе для этого типа присутствует прайс-лист с code `PL-001` и name `hausdoors_emal_i_shpon_rf_07_09_2026`

#### Scenario: Типы из разных прайс-листов различаются
- **WHEN** запрашивается каталог фурнитуры и существуют типы из двух разных price_list
- **THEN** у каждого типа указан прайс-лист, которому он принадлежит
