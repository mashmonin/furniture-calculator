## Purpose

Справочник прайс-листов (источников данных каталога): в какой файл прайса попала каждая коллекция дверей и каждый тип фурнитуры.

## Requirements

### Requirement: Структура price_list
Price_list ДОЛЖЕН (SHALL) иметь обязательные поля code (уникальное, формата `PL-NNN`) и name — название файла прайс-листа (например, `hausdoors_emal_i_shpon_rf_07_09_2026`). Название файла хранится без префикса «Прайс-лист:», подпись добавляется в интерфейсе.

#### Scenario: Прайс-лист требует code и name
- **WHEN** строка price_list вставляется без code или без name
- **THEN** база данных отклоняет вставку

#### Scenario: Code прайс-листа уникален
- **WHEN** вставляется второй price_list с уже существующим code
- **THEN** база данных отклоняет вставку

#### Scenario: Начальный прайс-лист
- **WHEN** запрашивается справочник прайс-листов после применения миграций
- **THEN** в нём есть запись `PL-001` с name `hausdoors_emal_i_shpon_rf_07_09_2026`

### Requirement: Принадлежность коллекции прайс-листу
Каждая collection ДОЛЖНА (SHALL) ссылаться ровно на один price_list. Источник модели полотна и door_configuration определяется через коллекцию её leaf_type. Все коллекции одного сервиса ДОЛЖНЫ (SHALL) принадлежать одному прайс-листу.

#### Scenario: Коллекция без прайс-листа недопустима
- **WHEN** строка collection вставляется без ссылки на price_list
- **THEN** база данных отклоняет вставку

#### Scenario: Существующие коллекции принадлежат начальному прайс-листу
- **WHEN** запрашиваются коллекции `LC-001`…`LC-009` после применения миграций
- **THEN** каждая из них ссылается на price_list `PL-001`

### Requirement: Принадлежность типа фурнитуры прайс-листу
Каждый hardware_type ДОЛЖЕН (SHALL) ссылаться ровно на один price_list. Цветовые варианты (hardware_option) наследуют источник от своего типа. Типы фурнитуры из разных прайс-листов НЕ ДОЛЖНЫ (SHALL NOT) пересекаться: один и тот же тип принадлежит одному прайс-листу.

#### Scenario: Тип фурнитуры без прайс-листа недопустим
- **WHEN** строка hardware_type вставляется без ссылки на price_list
- **THEN** база данных отклоняет вставку

#### Scenario: Существующая фурнитура принадлежит начальному прайс-листу
- **WHEN** запрашиваются все типы фурнитуры после применения миграций
- **THEN** каждый из них ссылается на price_list `PL-001`

### Requirement: Защита прайс-листа от удаления
Price_list, на который ссылается хотя бы одна collection или hardware_type, НЕ ДОЛЖЕН (SHALL NOT) удаляться.

#### Scenario: Удаление используемого прайс-листа отклоняется
- **WHEN** выполняется удаление price_list, на который ссылается collection или hardware_type
- **THEN** база данных отклоняет удаление

### Requirement: Прайс-лист «Эмаль Лайт»
В справочнике price_list ДОЛЖНА (SHALL) существовать запись `PL-002` с name `hausdoors_emal_layt_tsfo_07_09_2026`. Коллекции MONO, QUADRO, VENEZIA и REFLEX ДОЛЖНЫ (SHALL) ссылаться на этот прайс-лист; остальные коллекции продолжают ссылаться на `PL-001`.

#### Scenario: Прайс-лист «Эмаль Лайт» заведён
- **WHEN** запрашивается справочник прайс-листов после применения миграций
- **THEN** в нём есть запись `PL-002` с name `hausdoors_emal_layt_tsfo_07_09_2026`

#### Scenario: Новые коллекции принадлежат PL-002
- **WHEN** запрашиваются коллекции MONO, QUADRO, VENEZIA и REFLEX
- **THEN** каждая из них ссылается на price_list `PL-002`
