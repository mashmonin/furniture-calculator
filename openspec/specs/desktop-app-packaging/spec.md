## Purpose

Позволяет распространять приложение как самостоятельный desktop-продукт для macOS: пользователь устанавливает один файл и получает работающее приложение без ручной установки Java, СУБД или иных внешних зависимостей.

## Requirements

### Requirement: Автономная установка без внешних зависимостей
Система SHALL распространяться как единый установщик macOS (`.dmg`), после установки которого приложение запускается без необходимости отдельно устанавливать Java Runtime или сервер базы данных.

#### Scenario: Запуск на чистой машине
- **WHEN** пользователь без установленной Java и без запущенного сервера БД устанавливает и запускает приложение
- **THEN** приложение успешно запускается и становится пригодным для работы

### Requirement: Отдельное окно приложения
Система SHALL открывать пользовательский интерфейс в собственном нативном окне, а не в системном браузере — без адресной строки, вкладок и прочих элементов управления браузера.

#### Scenario: Запуск приложения
- **WHEN** пользователь запускает установленное приложение
- **THEN** открывается отдельное окно с интерфейсом приложения и иконкой приложения, без элементов управления браузера

### Requirement: Локальное хранение данных
Система SHALL хранить все данные конфигурации в локальной файловой базе данных, не требующей отдельно запущенного сервера СУБД.

#### Scenario: Первый запуск на новой машине
- **WHEN** пользователь запускает приложение первый раз на машине, где не установлен и не запущен PostgreSQL
- **THEN** приложение самостоятельно инициализирует локальное хранилище данных и становится готовым к работе

### Requirement: Сохранность пользовательских данных при обновлении
Пользовательские данные SHALL храниться вне каталога установки приложения, в стандартном для ОС пользовательском каталоге, и SHALL оставаться доступными после установки более новой версии поверх текущей.

#### Scenario: Обновление поверх существующей установки
- **WHEN** пользователь устанавливает более новую версию приложения поверх уже установленной версии
- **THEN** ранее сохранённые данные конфигурации остаются доступны после обновления

### Requirement: Замена версии при повторной установке
Установка нового `.dmg` с более новой версией SHALL заменять существующую установку той же версии приложения, а не создавать вторую независимую копию приложения в системе.

#### Scenario: Повторная установка новой версии
- **WHEN** пользователь устанавливает `.dmg` с более новой версией, имея уже установленную предыдущую версию приложения
- **THEN** в системе остаётся одна установленная копия приложения — обновлённая версия

### Requirement: Уведомление о доступном обновлении
При запуске система SHALL проверять наличие более новой опубликованной версии и, если она есть, SHALL уведомлять пользователя об этом с указанием, откуда скачать обновление. Проверка не SHALL блокировать запуск приложения и не SHALL прерывать работу при недоступности проверки.

#### Scenario: Доступна более новая версия
- **WHEN** приложение запускается и опубликована версия новее текущей
- **THEN** пользователю показывается уведомление о доступном обновлении со ссылкой на скачивание

#### Scenario: Установлена актуальная версия
- **WHEN** приложение запускается и текущая версия совпадает с последней опубликованной
- **THEN** уведомление об обновлении не показывается

#### Scenario: Проверка обновления недоступна
- **WHEN** приложение запускается без доступа к сети или сервис проверки версии не отвечает
- **THEN** приложение запускается в обычном режиме без сообщения об ошибке проверки обновления
