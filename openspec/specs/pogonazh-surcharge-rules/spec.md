## Purpose

Определяет справочник бизнес-правил фабрики о наценках за нестандартную длину/высоту погонажных элементов конфигурации — короба, наличника и добора, — привязанный к конкретному владельцу (frame_type/door_casing_type/frame_extensions_type), в отличие от dimension-surcharge-rules, который намеренно не зависит от владельца.

## Requirements

### Requirement: Структура pogonazh_surcharge_rule
Pogonazh_surcharge_rule ДОЛЖЕН (SHALL) ссылаться ровно на одного владельца — либо frame_type, либо door_casing_type, либо frame_extensions_type (ровно одна из трёх ссылок задана, остальные две — NULL), и хранить числовое значение размера (value) в миллиметрах и процент наценки (surcharge_percent); оба поля обязательны. Комбинация владельца и value ДОЛЖНА (SHALL) быть уникальной.

#### Scenario: Правило требует ровно одного владельца
- **WHEN** строка pogonazh_surcharge_rule вставляется без ссылки ни на frame_type, ни на door_casing_type, ни на frame_extensions_type, либо со ссылками сразу на два или три из них
- **THEN** база данных отклоняет вставку

#### Scenario: Правило требует value и surcharge_percent
- **WHEN** строка pogonazh_surcharge_rule вставляется без value или без surcharge_percent
- **THEN** база данных отклоняет вставку

#### Scenario: Значение не может повторяться для одного владельца
- **WHEN** для одного и того же frame_type (или door_casing_type, или frame_extensions_type) вставляется вторая строка pogonazh_surcharge_rule с уже существующим value
- **THEN** база данных отклоняет вставку

#### Scenario: Один и тот же value допустим для разных владельцев
- **WHEN** для разных владельцев (например, разных door_casing_type) вставляются строки pogonazh_surcharge_rule с одинаковым value
- **THEN** все строки сохраняются независимо друг от друга

### Requirement: Отсутствие правила означает базовое (без наценки) значение
Для конкретного владельца и конкретного значения размера, для которого нет ни одной строки pogonazh_surcharge_rule, наценка за нестандартную длину/высоту погонажа НЕ ДОЛЖНА (SHALL NOT) применяться — такое значение считается базовым. Наличие строки pogonazh_surcharge_rule для (владелец, value) означает, что это значение нестандартно, и наценка равна surcharge_percent этой строки.

#### Scenario: Значение без правила — базовое
- **WHEN** для владельца (например, frame_type «НЕО») выбрано значение размера, для которого нет строки pogonazh_surcharge_rule
- **THEN** значение считается базовым, наценка за нестандартный погонаж не применяется

#### Scenario: Значение с правилом — нестандартное
- **WHEN** для владельца выбрано значение размера, совпадающее с value строки pogonazh_surcharge_rule этого владельца
- **THEN** значение считается нестандартным, применяется surcharge_percent этой строки

### Requirement: Независимость от dimension_surcharge_rule
Pogonazh_surcharge_rule — самостоятельный справочник, не связанный с dimension_surcharge_rule: оба могут ссылаться на одно и то же числовое значение размера, но означают разные бизнес-правила (dimension_surcharge_rule — наценка за нестандартный размер самого полотна, применяемая только к цене leaf-компонента; pogonazh_surcharge_rule — наценка за нестандартную длину/высоту погонажа, применяемая к цене короба/наличника/добора). Если одно и то же значение одновременно совпадает со строкой dimension_surcharge_rule и со строкой pogonazh_surcharge_rule подходящего владельца, обе наценки ДОЛЖНЫ (SHALL) применяться независимо, каждая к своему компоненту.

#### Scenario: Одно и то же значение порождает две независимые наценки
- **WHEN** для конфигурации с коробом «Фантом» выбрана высота полотна, совпадающая одновременно со значением dimension_surcharge_rule (наценка за нестандартный размер полотна) и со значением pogonazh_surcharge_rule этого frame_type (наценка за нестандартный погонаж)
- **THEN** наценка dimension_surcharge_rule применяется к цене leaf-компонента, а наценка pogonazh_surcharge_rule — к цене frame-компонента, независимо друг от друга
