## Purpose

Определяет REST API для выгрузки в один Excel-файл сразу всех позиций заказа, собранных в корзине (см. order-cart-ui), — сводного листа по всем позициям и подробного листа детализации по каждой, переиспользуя ту же расчётную логику, что и выгрузка одиночной спецификации (см. door-configuration-export).

## ADDED Requirements

### Requirement: Эндпоинт выгрузки заказа целиком
Система ДОЛЖНА (SHALL) предоставлять эндпоинт `POST /api/specification/export-order`, принимающий непустой список позиций заказа. Каждая позиция ДОЛЖНА (SHALL) содержать: то же тело, что принимает `POST /api/specification/export` (см. door-configuration-export, «Эндпоинт выгрузки спецификации») — id `leaf_type` с опциями и опционально кромку, короб, наличник, добор, фурнитуру; количество (целое число, не меньше 1); отображаемое наименование позиции (используется в заголовке её листа детализации и в строке сводного листа). Валидация каждой позиции ДОЛЖНА (SHALL) следовать тем же правилам, что и у `POST /api/specification/export` (см. door-configuration-export, «Эндпоинт выгрузки спецификации») — 404 для несуществующего `leaf_type`, 400 для недопустимых id опций.

#### Scenario: Пустой список позиций отклоняется
- **WHEN** отправляется запрос с пустым списком позиций
- **THEN** эндпоинт отвечает ошибкой 400 и не генерирует файл

#### Scenario: Невалидная позиция в списке отклоняет весь запрос
- **WHEN** список содержит несколько позиций, и хотя бы одна из них ссылается на несуществующий `leaf_type` или недопустимую опцию
- **THEN** эндпоинт отвечает той же ошибкой (404 или 400 в зависимости от причины), что и `POST /api/specification/export` для этой позиции, и не генерирует файл — частичная выгрузка (без невалидной позиции) не выполняется

#### Scenario: Количество меньше 1 отклоняется
- **WHEN** у одной из позиций указано количество 0 или отрицательное
- **THEN** эндпоинт отвечает ошибкой 400 и не генерирует файл

### Requirement: Формат ответа выгрузки заказа
Ответ эндпоинта выгрузки заказа ДОЛЖЕН (SHALL) быть файлом в формате `.xlsx` (`Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`) с заголовком `Content-Disposition: attachment`, тем же соглашением об имени файла, что и у выгрузки одиночной спецификации (`Заказ-от-<дата>.xlsx`, см. door-configuration-export, «Формат ответа»).

#### Scenario: Ответ помечен как вложение
- **WHEN** запрос выгрузки заказа выполнен успешно
- **THEN** ответ содержит заголовок `Content-Disposition: attachment` с именем файла вида `Заказ-от-<дата>.xlsx` и тело в формате `.xlsx`

### Requirement: Лист-сводка заказа
Файл заказа ДОЛЖЕН (SHALL) содержать первым лист-сводку со строкой на каждую позицию заказа, в том же порядке, в котором позиции переданы в запросе: порядковый номер, отображаемое наименование позиции, количество, итоговая розничная цена за единицу (сумма цен всех компонентов этой позиции — та же величина, что была бы в разделе «Итоговая сумма» её листа детализации, см. door-configuration-export, «Итоговая сумма в файле») и сумма по позиции (цена за единицу × количество). Последняя строка сводки ДОЛЖНА (SHALL) содержать итог по заказу — сумму столбца «Сумма» по всем позициям.

#### Scenario: Сводка содержит строку на каждую позицию и итог
- **WHEN** заказ состоит из двух позиций
- **THEN** лист-сводка содержит две строки с данными по каждой позиции и завершающую строку с итогом по заказу — суммой их сумм

### Requirement: Лист детализации по позиции
Для каждой позиции заказа файл ДОЛЖЕН (SHALL) содержать отдельный лист детализации, называющийся по номеру и отображаемому наименованию позиции (например, «1. Вертикаль 01»), с тем же составом разделов, строк и колонок, что и файл выгрузки одиночной спецификации для этой же конфигурации (см. door-configuration-export, «Разделы файла спецификации», «Содержимое строки спецификации», «Выбранные опции полотна в файле», «Итоговая сумма в файле», «Надбавки к цене полотна в файле») — цены в листе детализации указаны за одну единицу изделия, без умножения на количество позиции (умножение на количество показано только в листе-сводке).

#### Scenario: Лист детализации соответствует одиночной выгрузке той же конфигурации
- **WHEN** позиция заказа содержит ту же конфигурацию (полотно, кромка, короб, наличник, добор, фурнитура), что была бы отправлена в `POST /api/specification/export`
- **THEN** лист детализации этой позиции содержит те же разделы, строки и цены (за единицу), что и файл, полученный от `POST /api/specification/export` для той же конфигурации

#### Scenario: Название листа включает номер и наименование позиции
- **WHEN** вторая позиция заказа имеет отображаемое наименование «Вертикаль 02»
- **THEN** её лист детализации называется «2. Вертикаль 02»

### Requirement: Переиспользование расчёта позиции заказа
Расчёт цены каждой позиции заказа (и для листа-сводки, и для её листа детализации) ДОЛЖЕН (SHALL) использовать ту же расчётную логику, что и `POST /api/specification/export` (`DoorConfigurationPricingService.resolveSpecificationComponents`) — без отдельной, дублирующей реализации расчёта или собственных правил округления/надбавок для выгрузки заказа.

#### Scenario: Изменение правил расчёта одинаково влияет на обе выгрузки
- **WHEN** правило расчёта цены или надбавки меняется на уровне `DoorConfigurationPricingService`
- **THEN** это изменение одинаково отражается и в выгрузке одиночной спецификации, и в каждом листе детализации выгрузки заказа — без необходимости менять код выгрузки заказа отдельно
