## MODIFIED Requirements

### Requirement: Расчёт стоимости по текущему выбору
Система ДОЛЖНА (SHALL) предоставлять действие «Рассчитать стоимость», доступное только когда выбрана конфигурация. При активации действия система ДОЛЖНА (SHALL) отправить id выбранной конфигурации, текущий выбор опций по каждому её компоненту (компоненты и оси без выбранного значения передаются как не выбранные) и текущий список выбранных позиций фурнитуры (см. «Выбор позиций фурнитуры»), и отобразить результат: итоговую розничную и дилерскую цену (с учётом фурнитуры), разбивку по компонентам — с найденной ценой компонента либо отметкой, что цена не найдена, — и разбивку по позициям фурнитуры (см. «Отображение фурнитуры в результате расчёта»). После получения ответа (успешного результата либо сообщения об ошибке расчёта) система ДОЛЖНА (SHALL) автоматически прокрутить страницу так, чтобы соответствующий блок (результат расчёта либо сообщение об ошибке) стал видимым — так пользователь замечает, что расчёт произошёл, даже если до этого он находился в другом месте длинной страницы.

#### Scenario: Расчёт недоступен без выбранной конфигурации
- **WHEN** ни одна конфигурация не выбрана
- **THEN** действие «Рассчитать стоимость» недоступно для активации

#### Scenario: Расчёт без выбранных опций
- **WHEN** конфигурация выбрана, но ни одна опция размеров или цвета не выбрана, и активируется расчёт стоимости
- **THEN** запрос расчёта отправляется с id конфигурации без выбранных опций компонентов

#### Scenario: Успешный расчёт по всем компонентам
- **WHEN** backend возвращает результат расчёта, в котором цена найдена для всех компонентов конфигурации
- **THEN** страница показывает итоговую розничную и дилерскую цену и разбивку с ценой для каждого компонента

#### Scenario: Частичный расчёт
- **WHEN** backend возвращает результат расчёта, в котором для одного или нескольких компонентов цена не найдена
- **THEN** страница показывает итоговую цену, возвращённую backend, и отмечает в разбивке компоненты, для которых цена не найдена, не пересчитывая итог самостоятельно

#### Scenario: Ошибка расчёта
- **WHEN** запрос расчёта стоимости завершается ошибкой (сетевой сбой или ответ с кодом ошибки, включая 404 и 400)
- **THEN** страница показывает сообщение об ошибке расчёта и сохраняет текущий выбор конфигурации, опций и позиций фурнитуры без изменений

#### Scenario: Повторный расчёт после изменения выбора
- **WHEN** после отображения результата расчёта пользователь меняет выбор опции и повторно активирует расчёт стоимости
- **THEN** ранее показанный результат заменяется новым результатом расчёта по актуальному выбору

#### Scenario: Автопрокрутка к успешному результату
- **WHEN** активирован расчёт стоимости, и backend возвращает результат (полный или частичный)
- **THEN** страница автоматически прокручивается так, чтобы блок результата (итоговые цены и разбивка) стал видимым

#### Scenario: Автопрокрутка к сообщению об ошибке
- **WHEN** активирован расчёт стоимости, и запрос завершается ошибкой
- **THEN** страница автоматически прокручивается так, чтобы сообщение об ошибке стало видимым

#### Scenario: Повторный расчёт снова прокручивает к результату
- **WHEN** пользователь повторно активирует расчёт стоимости после изменения выбора (см. «Повторный расчёт после изменения выбора»)
- **THEN** страница снова автоматически прокручивается к новому результату, даже если пользователь успел прокрутить страницу в другое место после предыдущего расчёта

#### Scenario: Расчёт с фурнитурой без выбранной конфигурации остаётся недоступным
- **WHEN** добавлены одна или несколько позиций фурнитуры, но конфигурация не выбрана
- **THEN** действие «Рассчитать стоимость» остаётся недоступным для активации

## ADDED Requirements

### Requirement: Загрузка каталога фурнитуры
При открытии страницы, наряду с каталогом конфигураций, система ДОЛЖНА (SHALL) загрузить каталог фурнитуры (категории, типы и их цветовые варианты с ценами) через эндпоинт получения каталога фурнитуры и использовать его для построения блока выбора позиций фурнитуры (см. «Выбор позиций фурнитуры»).

#### Scenario: Каталог фурнитуры загружается вместе с каталогом конфигураций
- **WHEN** страница открывается
- **THEN** наряду с каталогом конфигураций загружается каталог фурнитуры

#### Scenario: Ошибка загрузки каталога фурнитуры не блокирует остальной функционал
- **WHEN** запрос каталога фурнитуры завершается ошибкой
- **THEN** страница продолжает работать как обычно (выбор конфигурации, каскад опций, расчёт стоимости без фурнитуры), но блок выбора фурнитуры показывает сообщение об ошибке загрузки вместо списка позиций

### Requirement: Выбор позиций фурнитуры
Независимо от выбора конфигурации двери система ДОЛЖНА (SHALL) предоставлять блок выбора фурнитуры со списком позиций. Пользователь ДОЛЖЕН (SHALL) иметь возможность добавить новую позицию (выбор категории, затем типа фурнитуры этой категории, затем цветового варианта этого типа — каждый следующий выбор доступен только после предыдущего, аналогично каскадному выбору опций компонентов конфигурации) и указать для неё количество (числовое поле, по умолчанию 1). Пользователь ДОЛЖЕН (SHALL) иметь возможность удалить ранее добавленную позицию и добавить более одной позиции одновременно, в том числе с одинаковым цветовым вариантом. В запрос расчёта стоимости передаются только полностью заполненные позиции (с выбранным цветовым вариантом); незавершённая позиция (без выбранного варианта) в запрос не включается.

#### Scenario: Добавление позиции фурнитуры
- **WHEN** пользователь добавляет позицию фурнитуры и последовательно выбирает категорию, тип и цветовой вариант
- **THEN** позиция отображается с выбранным цветовым вариантом и полем количества со значением 1

#### Scenario: Тип фурнитуры недоступен до выбора категории
- **WHEN** для новой позиции фурнитуры категория ещё не выбрана
- **THEN** выбор типа фурнитуры для этой позиции недоступен

#### Scenario: Цветовой вариант недоступен до выбора типа
- **WHEN** для позиции фурнитуры выбрана категория, но не выбран тип фурнитуры
- **THEN** выбор цветового варианта для этой позиции недоступен

#### Scenario: Смена категории сбрасывает тип и цвет позиции
- **WHEN** пользователь меняет категорию у позиции фурнитуры, для которой уже был выбран тип и/или цветовой вариант
- **THEN** выбранный тип и цветовой вариант этой позиции сбрасываются

#### Scenario: Добавление нескольких позиций
- **WHEN** пользователь добавляет две позиции фурнитуры с разными цветовыми вариантами
- **THEN** обе позиции отображаются одновременно, независимо друг от друга

#### Scenario: Удаление позиции фурнитуры
- **WHEN** пользователь удаляет ранее добавленную позицию фурнитуры
- **THEN** эта позиция больше не отображается и не включается в следующий расчёт стоимости

#### Scenario: Незавершённая позиция не передаётся в расчёт
- **WHEN** пользователь добавил позицию фурнитуры, выбрал для неё категорию и тип, но не выбрал цветовой вариант, и активирует расчёт стоимости
- **THEN** эта позиция не включается в отправляемый запрос расчёта стоимости

#### Scenario: Одинаковый цветовой вариант в нескольких позициях допустим
- **WHEN** пользователь добавляет две позиции фурнитуры с одним и тем же цветовым вариантом
- **THEN** обе позиции сохраняются как независимые и обе передаются в запрос расчёта стоимости

### Requirement: Отображение фурнитуры в результате расчёта
В результате расчёта стоимости, наряду с разбивкой по компонентам конфигурации, система ДОЛЖНА (SHALL) показывать отдельную строку для каждой позиции фурнитуры из выполненного расчёта — с названием категории, типа и цветового варианта, количеством и стоимостью позиции (розничной и дилерской, с учётом количества). Итоговая розничная и дилерская цена результата ДОЛЖНА (SHALL) включать стоимость всех показанных позиций фурнитуры.

#### Scenario: Позиция фурнитуры показывается в разбивке
- **WHEN** стоимость рассчитана для запроса, содержащего одну позицию фурнитуры с количеством 3
- **THEN** в разбивке результата отображается отдельная строка с названием этой фурнитуры, количеством 3 и её стоимостью с учётом количества

#### Scenario: Несколько позиций фурнитуры показываются по отдельности
- **WHEN** стоимость рассчитана для запроса, содержащего несколько позиций фурнитуры
- **THEN** в разбивке результата каждая позиция отображается отдельной строкой

#### Scenario: Без выбранной фурнитуры разбивка по фурнитуре не показывается
- **WHEN** стоимость рассчитана для запроса без позиций фурнитуры
- **THEN** разбивка результата не содержит строк фурнитуры
