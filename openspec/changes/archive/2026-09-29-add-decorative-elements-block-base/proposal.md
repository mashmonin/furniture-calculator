## Why

В каталоге декоративных элементов сейчас есть только категория «Плинтус». Фабрика хочет продавать ещё пять самостоятельных позиций — «Блок А», «База А», «Блок В», «База В» и «База В КОМПЛАНАР» — как новую отдельную категорию декоративных элементов, доступную для коллекций «Элегант» и «Гармония».

## What Changes

- Новая категория decorative_element_category «Блок и база» (код `DEC-002`) с пятью decorative_element_type:
  - «Блок А» — длина 90 мм, дилерская цена 1154, розничная 2021
  - «База А» — длина 252 мм, дилерская цена 1830, розничная 3203
  - «Блок В» — длина 91 мм, дилерская цена 1154, розничная 2021
  - «База В» — длина 200 мм, дилерская цена 1830, розничная 3203
  - «База В КОМПЛАНАР» — длина 200 мм, дилерская цена 1830, розничная 3203
- Для всех пяти типов — decorative_element_option для каждого leaf_type коллекций «Элегант» (`LC-003`) и «Гармония» (`LC-004`); для leaf_type остальных коллекций эти типы недоступны.
- Данные вносятся новым Liquibase changeset'ом (аналогично `0107-decorative-elements-plinth.yaml`) — существующая структура таблиц `decorative_element_category`/`decorative_element_type`/`decorative_element_option` не меняется.
- Никаких изменений в backend-сервисах, REST API, UI конфигуратора, корзине или экспорте не требуется: каталог декоративных элементов, расчёт их стоимости, блок выбора на экране конфигуратора, отображение в корзине и в выгрузке уже реализованы универсально (по категориям/типам из каталога, без привязки к конкретной категории) в рамках `decorative-element-catalog` и связанных возможностей.

## Capabilities

### New Capabilities
_(нет)_

### Modified Capabilities
- `decorative-element-catalog`: добавляется требование о новой категории «Блок и база» — пять типов с длиной и ценами, доступных для leaf_type коллекций «Элегант» и «Гармония».

## Impact

- Backend: новый Liquibase changeset (`0108-decorative-elements-block-base.yaml`) с insert-данными новой категории, пяти типов и decorative_element_option для leaf_type коллекций «Элегант» и «Гармония». Изменений кода нет — существующий каталог-эндпоинт, расчёт стоимости, экспорт и UI уже читают декоративные элементы по категориям/типам из БД без хардкода конкретных категорий.
- Frontend: изменений не требуется — блок «Декоративные элементы» конфигуратора уже отображает все категории/типы, пришедшие из каталога.
- Данные: наименования, длина и цены пяти новых позиций — по значениям, указанным пользователем; применимость к коллекциям «Элегант»/«Гармония» — также по ответу пользователя. Допущение: «База В КОМПЛАНАР» доступна для тех же leaf_type (Элегант/Гармония), что и остальные четыре позиции — модель decorative_element_option привязывает применимость только к leaf_type, без отдельной оси по типу короба (frame_type), поэтому ограничение «только для компланарного короба» технически не выражается и не вводится этим изменением; название «КОМПЛАНАР» в позиции остаётся как есть (описательное, из прайс-листа фабрики).
