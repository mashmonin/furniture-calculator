## Why

Сейчас в базе 45 моделей полотна (`leaf_type`), и первый шаг каскадного выбора конфигуратора отображает их одним плоским списком без группировки. Группировка по коллекции ("ВЕРТИКАЛЬ", "АТМОСФЕРА" и т.д.) уже фактически существует — она "зашита" текстом в `name` и диапазоны `code` в данных миграций, — но не нормализована в схеме и не видна пользователю как отдельный шаг выбора. Явный справочник коллекций и промежуточный шаг выбора коллекции перед выбором конкретной модели полотна уменьшит когнитивную нагрузку на пользователя при выборе модели.

## What Changes

- Добавить новый справочник `collection` (id, name, code) — по образцу существующих справочных таблиц (`leaf_type`, `frame_type` и т.п.).
- Добавить обязательную связь `leaf_type.collection_id → collection.id`: каждая модель полотна ДОЛЖНА принадлежать ровно одной коллекции.
- Заполнить справочник `collection` девятью значениями ("Вертикаль", "Атмосфера", "Элегант", "Гармония", "Свобода", "Геометрия", "Сияние", "Сибирь", "Фантом") и проставить `collection_id` всем 45 существующим строкам `leaf_type` по диапазонам их `code`.
- Расширить ответ REST API каталога конфигураций (`GET /api/door-configurations`): данные leaf-компонента должны дополнительно включать данные его коллекции (id, code, name).
- Изменить каскад выбора на фронтенде: перед шагом выбора модели полотна добавить новый первый шаг — выбор коллекции. Выбор коллекции сужает список моделей полотна на следующем шаге до моделей этой коллекции; последующие шаги каскада (короб, наличник, кромка, удлинители) не меняются.

## Capabilities

### New Capabilities
- `door-collection-catalog`: определяет структуру справочника `collection` и обязательную связь каждого `leaf_type` ровно с одной `collection`.

### Modified Capabilities
- `door-configuration-api`: ответ эндпоинта получения каталога конфигураций (`GET /api/door-configurations`) дополняется данными коллекции для leaf-компонента каждой конфигурации.
- `door-configurator-ui`: перед существующим первым шагом (выбор модели полотна) добавляется новый шаг выбора коллекции, сужающий варианты следующего шага; порядок и поведение остальных шагов каскада не меняются.

## Impact

- **Backend**: новая Liquibase-миграция (таблица `collection`, данные, `addColumn collection_id` на `leaf_type` + backfill + `NOT NULL`); новая JPA-сущность `Collection` (или аналогичное имя, не конфликтующее с `java.util.Collection`), связь `LeafType.collection` (`@ManyToOne`); расширение DTO каталога (`ComponentCatalogDto`/`ReferenceDto` для leaf) данными коллекции.
- **Frontend**: новый шаг каскада перед выбором полотна в `App.tsx` (`buildCascadeSteps`), расширение типов каталога (`frontend/src/api/types.ts`) полем `collection` у leaf-компонента.
- **База данных**: новая таблица `collection`, новый столбец `leaf_type.collection_id` с FK и `NOT NULL`.
