## MODIFIED Requirements

### Requirement: Загрузка каталога конфигураций
При открытии страницы система ДОЛЖНА (SHALL) загрузить весь каталог door_configuration через существующий эндпоинт `GET /api/door-configurations` и использовать его как единственный источник данных для последующего каскадного выбора компонентов, не выполняя дополнительных запросов к backend на этом этапе.

#### Scenario: Каталог успешно загружен
- **WHEN** страница открывается и backend возвращает непустой список конфигураций
- **THEN** отображается первый шаг каскадного выбора — выбор коллекции полотна

#### Scenario: Каталог пуст
- **WHEN** страница открывается и backend возвращает пустой список конфигураций
- **THEN** страница показывает сообщение об отсутствии доступных конфигураций и не отображает ни одного шага выбора

#### Scenario: Ошибка загрузки каталога
- **WHEN** запрос каталога конфигураций завершается ошибкой (сетевой сбой или ответ с кодом ошибки)
- **THEN** страница показывает сообщение об ошибке загрузки и не отображает ни одного шага выбора

## ADDED Requirements

### Requirement: Выбор коллекции полотна
Система ДОЛЖНА (SHALL) отображать шаг выбора коллекции перед шагом выбора модели полотна. Варианты этого шага — все различные collection, которым принадлежит хотя бы один leaf_type, встречающийся среди door_configuration загруженного каталога. После выбора коллекции шаг выбора модели полотна ДОЛЖЕН (SHALL) показывать только те leaf_type выбранной коллекции, что встречаются хотя бы в одной door_configuration каталога; остальные шаги каскада (короб, наличник, кромка, удлинители) продолжают сужаться по ранее установленным правилам, начиная с выбранной модели полотна.

#### Scenario: Первый шаг показывает все коллекции
- **WHEN** каталог загружен и пользователь ещё не сделал ни одного выбора
- **THEN** шаг выбора коллекции показывает все различные collection, которым принадлежит хотя бы один leaf_type, встречающийся в каталоге

#### Scenario: Выбор коллекции сужает список моделей полотна
- **WHEN** пользователь выбрал коллекцию
- **THEN** шаг выбора модели полотна показывает только те leaf_type этой коллекции, что встречаются в door_configuration каталога

#### Scenario: Изменение коллекции сбрасывает выбор полотна и последующих шагов
- **WHEN** пользователь меняет ранее выбранную коллекцию после того, как модель полотна или последующие шаги каскада уже были выбраны
- **THEN** выбор модели полотна и всех последующих шагов каскада сбрасывается и пересчитывается заново на основе новой выбранной коллекции, а ранее показанные опции размеров/цвета и результат расчёта стоимости, если они были показаны, скрываются
