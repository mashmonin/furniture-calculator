## Why

Сейчас клиент может выбрать длину и высоту полотна только из фиксированного каталожного списка (400/600/700/800 мм по длине, 2000/2100 мм по высоте) — цена полотна при этом всегда одна и та же вне зависимости от выбранного стандартного размера (`configuration_price` полотна не ссылается на length/height вовсе). Фабрика умеет производить полотно и в других, нестандартных размерах, но каждый такой размер увеличивает стоимость на определённый процент, зависящий от конкретного значения. Сейчас в системе нет ни способа ввести такой размер, ни места хранить и применять эти наценки — нужен отдельный, явно выделенный слой бизнес-правил фабрики поверх обычного каталога допустимых конфигураций.

## What Changes

- Добавить справочник бизнес-правил `dimension_surcharge_rule` — плоская таблица (тип размера, значение в мм, процент наценки), задаваемая через Liquibase. Начальные данные — таблица наценок за нестандартную длину/высоту полотна:
  - Длина: 450/500/550/650/750/850/950/1000 мм → +20%; 900 мм → +10%.
  - Высота: 2200/2300 мм → +20%; 1900/1950/2050/2150/2400 мм → +30%; 2500/2600/2700 мм → +50%.
- В запросе расчёта стоимости для компонента `leaf` добавить возможность передать произвольное значение длины/высоты (в мм) вместо ссылки на каталожный `lengthOptionId`/`heightOptionId`. Система ДОЛЖНА (SHALL):
  - если произвольное значение совпадает со стандартным каталожным размером этого полотна — считать так же, как обычный выбор (наценки нет);
  - если совпадает с одной из строк `dimension_surcharge_rule` — применить соответствующий процент к найденной цене полотна (retail и dealer отдельно);
  - если не совпадает ни с тем, ни с другим — отклонить расчёт ошибкой 400 (фабрика не производит такой размер).
- Наценка за размер и существующая надбавка за реверс (+10%) применяются к цене полотна независимо и перемножаются (складываются мультипликативно, не аддитивно).
- Frontend: у полей длины и высоты полотна, помимо существующего списка стандартных вариантов, появляется отдельное поле «Другое значение» (числовой ввод в мм) — взаимоисключающее со стандартным выбором.

## Capabilities

### New Capabilities
- `dimension-surcharge-rules`: справочник бизнес-правил фабрики — плоская таблица наценок за конкретные нестандартные значения длины/высоты, независимая от каталога допустимых конфигураций (`door-configuration-catalog`).

### Modified Capabilities
- `door-configuration-api`: эндпоинт расчёта стоимости принимает произвольное значение длины/высоты для полотна вместо id каталожной опции, ищет подходящее правило наценки и применяет его к цене полотна; определены ошибки для несовпадающего или конфликтующего ввода.
- `door-configurator-ui`: у длины и высоты полотна появляется отдельный числовой ввод произвольного значения, взаимоисключающий с выбором из стандартного списка.

## Impact

- **БД**: новая таблица `dimension_surcharge_rule` (liner_dimension_type_id, value, surcharge_percent) + начальные данные наценок за длину/высоту полотна.
- **Backend**: новая сущность `DimensionSurchargeRule` + репозиторий; `ComponentSelectionDto`/`PricingRequestDto` — новые опциональные поля для произвольного значения длины/высоты; `DoorConfigurationPricingService` — логика поиска и применения наценки для leaf-компонента, валидация конфликтующего/нераспознанного ввода.
- **Frontend**: `App.tsx` — числовой ввод «Другое значение» для длины/высоты полотна, взаимоисключающий со стандартным списком; `PricingRequestDto`/`ComponentSelectionDto` (типы) — новые поля.
- Область действия — только компонент `leaf` (полотно); длина/высота остальных компонентов (кромка, короб, наличник, добор) не затрагиваются.
