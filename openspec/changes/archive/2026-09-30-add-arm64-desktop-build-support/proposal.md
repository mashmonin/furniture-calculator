## Why

Текущая desktop-сборка (`jlink` + `jpackage`, см. change `add-desktop-app-packaging`) даёт `.dmg` под архитектуру машины, на которой она собрана, — сейчас это Intel (x86_64). На Apple Silicon (M1/M2/M3/M4) такой `.dmg` тоже запустится, но через Rosetta 2, не нативно. Кросс-компиляция невозможна в принципе: `jlink`/`jpackage` всегда встраивают JRE под архитектуру запускающей машины, поэтому нативный arm64-дистрибутив можно собрать только реально запустив сборку на Apple Silicon Mac. Эта задача — не собрать такой `.dmg` прямо сейчас (для этого нужна отдельная arm64-машина), а подготовить проект так, чтобы при запуске уже существующей команды `./gradlew desktopAppImage` на Apple Silicon Mac всё отработало без доработок и результат не путался с x86_64-сборкой.

## What Changes

- Выходные файлы desktop-сборки (`.dmg`, `.app`) получают в имени архитектуру процессора (например, суффикс `mac-x86_64` / `mac-aarch64`), чтобы сборки под разные архитектуры не перезаписывали друг друга в `build/desktop/` и было явно видно, какая есть какая.
- Архитектура определяется автоматически (через системное свойство JVM `os.arch`), без хардкода — как уже делает плагин `org.openjfx.javafxplugin` при выборе classifier'а JavaFX-jar'ов.
- **BREAKING** (только для локальной сборки, не для пользователей): имя `.dmg`-файла меняется (теперь содержит архитектуру) — если есть скрипты/документация, ссылающиеся на старое имя файла без архитектуры, их нужно обновить.
- Задокументировать (design.md) полный список требований для сборки на Apple Silicon Mac (JDK 21 arm64, Xcode Command Line Tools, Node.js) и способ проверить, что получившийся `.dmg` действительно нативный arm64, а не x86_64/universal.
- Настройка GitHub Actions CI для автоматической сборки обеих архитектур — вне рамок этого изменения (нет GitHub-remote у репозитория на момент написания).
- Универсальный (universal2) бинарник, работающий нативно на обеих архитектурах в одном `.dmg`, — вне рамок этого изменения (сложнее в разы: требует ручной сборки universal JRE через `lipo`, jpackage не поддерживает это из коробки); при необходимости может быть отдельным изменением позже.

## Capabilities

### New Capabilities
_Нет новых capability — это уточнение существующей упаковки, а не новая функциональность._

### Modified Capabilities
- `desktop-app-packaging`: уточняется, что установщик распространяется отдельно под каждую поддерживаемую архитектуру процессора (Intel x86_64 и Apple Silicon arm64) — пользователь должен установить `.dmg`, соответствующий архитектуре его Mac, а не единый универсальный файл для всех.

## Impact

- **Backend**: `backend/build.gradle` — таски `desktopFxLibs`, `desktopJlinkRuntime`, `desktopAppImage` (имена выходных директорий/файлов теперь учитывают архитектуру).
- **Документация**: design.md текущего изменения — чек-лист подготовки Apple Silicon Mac к сборке и проверки результата.
- Существующая x86_64-сборка (задача 4 change `add-desktop-app-packaging`) не меняется по поведению — только именование выходных файлов.
