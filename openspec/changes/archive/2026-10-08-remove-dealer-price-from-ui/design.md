## Context

Дилерская цена (`dealerPrice`, `totalDealerPrice`, `baseDealerPrice`) приходит из API и выводится на фронтенде в нескольких местах: `ConfiguratorScreen.tsx` (блок «Дилерская цена» в колонке результата, цена стоек короба «retail / dealer (дилер)», цена наличника/добора), `ComponentBreakdownList.tsx` (итог компонента, базовая цена, фурнитура, декоративные элементы — формат «retail / dealer (дилер)»), `CartScreen.tsx` (столбцы «Цена дилер»/«Сумма дилер» детализации, итог «Итого» детализации, «Итого по заказу … (дилер)»), `HardwareServiceScreen.tsx` (столбец «Цена дилер» записи каталога). Те же поля заполняют снимок расчёта и построчную детализацию, которые корзина хранит в `localStorage` (`cart.ts`, `CartDetailRow`).

## Goals / Non-Goals

**Goals:** ни один экран фронтенда не показывает дилерскую цену; розничная цена и форматирование остаются как есть.

**Non-Goals:** удаление дилерских данных из API, расчёта, типов, снимка расчёта и сохранённой корзины; изменения Excel-выгрузки заказа.

## Decisions

**1. Убираем только отображение.** Поля `dealerPrice`/`dealerSum`/`totalDealerPrice` остаются в типах, расчёте и снимках: Excel-выгрузка и расчёты (`withHardware` в `cart.ts` пересчитывает и дилерские суммы) продолжают их использовать, а удаление из моделей затронуло бы backend-контракт и уже сохранённые корзины пользователей без пользы. Альтернатива — вычистить поле из всего стека: большой объём, риск несовместимости `localStorage`, дилерские цены в Excel всё равно нужны.

**2. Excel-выгрузка не меняется (допущение).** Просьба — «на фронте»; `Выгрузить заказ` формирует служебный файл с розничной и дилерской ценой для менеджера, а КП (клиентский документ) уже без дилерских цен. Если Excel тоже должен быть без дилерских цен, это отдельная правка backend (`OrderExportService`/`SpecificationExportService`) и спеки `order-export-api` / `door-configuration-export`.

**3. Форматы строк.** «розница / дилер (дилер)» → «розница»; блок `app-pricing__dealer-block` и его стили в `App.css` удаляются; в детализации корзины пропадают два столбца и дилерское слагаемое строки «Итого» (в ней остаётся сумма клиенту); в `CartScreen` убирается `orderDealerTotal`. Подписи столбцов «Цена клиенту»/«Сумма клиенту» и «Цена розница» не переименовываются (слово «клиенту» остаётся осмысленным).

**4. Спеки.** Правятся все требования, где упоминалась дилерская цена на экранах (модифицируются с полным текстом); два требования («Акцентное оформление колонки результата расчёта», «Сводка и итог по заказу») заменены новыми (REMOVED + ADDED с другим названием), потому что их сценарии про дилерскую цену нельзя оставить под прежними именами; ссылки на них из других требований обновлены; требование «Хранение корзины в localStorage» не меняется — корзина по-прежнему хранит расчёт с обеими ценами.

## Risks / Trade-offs

- В `localStorage` и в DOM-данных дилерская цена остаётся (невидима в UI, но доступна через инструменты разработчика) → допустимо: «убрать отображение»; если нужна именно скрытность данных, потребуется убрать её и из ответов API.
- Excel-выгрузка содержит дилерские цены → отмечено в допущениях; решение пользователя.
- Пропущенное место отображения → в задачах поиск по `dealer`/«дилер» по всему `frontend/src` перед завершением.

## Migration Plan

Миграций нет; сохранённые корзины продолжают работать без изменений. Откат — возврат правок отображения.
