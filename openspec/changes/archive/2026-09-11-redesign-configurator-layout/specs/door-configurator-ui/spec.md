## REMOVED Requirements

### Requirement: Расчёт стоимости по текущему выбору
**Reason**: Ручной запуск расчёта через кнопку «Рассчитать стоимость» и последующая автопрокрутка к результату заменяются автоматическим debounced-расчётом с постоянно видимой sticky-панелью результата (см. change redesign-configurator-layout) — отдельное действие пользователя и прокрутка к результату больше не нужны.
**Migration**: См. новое требование «Автоматический расчёт стоимости по текущему выбору» — эквивалентное по цели (получить актуальную цену по текущему выбору) поведение, но без кнопки и без автопрокрутки.

## ADDED Requirements

### Requirement: Автоматический расчёт стоимости по текущему выбору
Система ДОЛЖНА (SHALL) автоматически рассчитывать стоимость по текущему выбору — без отдельного действия пользователя вроде кнопки «Рассчитать стоимость». Пока конфигурация не определена однозначно, расчёт не запускается и sticky-панель результата (см. «Sticky-панель результата расчёта») не показывает ни результат, ни ошибку. Как только конфигурация определена, и при каждом последующем изменении, влияющем на запрос расчёта (выбор/сброс опции компонента, изменение количества, выбор/сброс исполнения зеркала, изменение переключателя «Реверс» или коллекции, приводящее к новой конфигурации, изменение состава или количества позиций фурнитуры), система ДОЛЖНА (SHALL) через короткую паузу после последнего изменения (debounce) отправить id выбранной конфигурации, текущий выбор опций по каждому компоненту (компоненты и оси без выбранного значения передаются как не выбранные) и текущий список выбранных позиций фурнитуры (см. «Выбор позиций фурнитуры»), и отобразить результат в sticky-панели: итоговую розничную и дилерскую цену (с учётом фурнитуры), разбивку по компонентам — с найденной ценой компонента либо отметкой, что цена не найдена, — и разбивку по позициям фурнитуры (см. «Отображение фурнитуры в результате расчёта»). Если новое изменение происходит до истечения паузы, отложенный запрос откладывается заново от момента этого изменения (обычный debounce), а не отправляется несколько раз подряд.

#### Scenario: Расчёт не запускается без выбранной конфигурации
- **WHEN** ни одна конфигурация не выбрана
- **THEN** запрос расчёта стоимости не отправляется, а sticky-панель не показывает ни результат, ни ошибку

#### Scenario: Автоматический запуск при определении конфигурации
- **WHEN** текущий каскадный выбор впервые однозначно определяет конкретную конфигурацию
- **THEN** после паузы debounce автоматически отправляется запрос расчёта стоимости с текущим выбором опций, без какого-либо действия пользователя

#### Scenario: Расчёт без выбранных опций
- **WHEN** конфигурация определена, но ни одна опция размеров или цвета не выбрана
- **THEN** запрос расчёта отправляется с id конфигурации без выбранных опций компонентов

#### Scenario: Изменение опции запускает новый расчёт после паузы
- **WHEN** после отображения результата расчёта пользователь меняет выбор опции, количество или позицию фурнитуры
- **THEN** после паузы debounce отправляется новый запрос расчёта по актуальному выбору, и ранее показанный результат заменяется новым

#### Scenario: Повторное изменение до истечения паузы откладывает запрос заново
- **WHEN** пользователь меняет выбор второй раз, не дождавшись истечения паузы debounce после первого изменения
- **THEN** запрос по первому изменению не отправляется, а пауза перед отправкой отсчитывается заново от второго изменения

#### Scenario: Успешный расчёт по всем компонентам
- **WHEN** backend возвращает результат расчёта, в котором цена найдена для всех компонентов конфигурации
- **THEN** sticky-панель показывает итоговую розничную и дилерскую цену и разбивку с ценой для каждого компонента

#### Scenario: Частичный расчёт
- **WHEN** backend возвращает результат расчёта, в котором для одного или нескольких компонентов цена не найдена
- **THEN** sticky-панель показывает итоговую цену, возвращённую backend, и отмечает в разбивке компоненты, для которых цена не найдена, не пересчитывая итог самостоятельно

#### Scenario: Ошибка расчёта
- **WHEN** запрос расчёта стоимости завершается ошибкой (сетевой сбой или ответ с кодом ошибки, включая 404 и 400)
- **THEN** sticky-панель показывает сообщение об ошибке расчёта вместо результата, а текущий выбор конфигурации, опций и позиций фурнитуры сохраняется без изменений

#### Scenario: Устаревший ответ игнорируется
- **WHEN** отправлено два запроса расчёта подряд (из-за быстрых последовательных изменений после уже прошедшей паузы debounce), и ответ на более ранний запрос приходит позже ответа на более поздний
- **THEN** sticky-панель отражает только результат более позднего запроса; более ранний (устаревший) ответ, пришедший после него, не изменяет показанный результат

#### Scenario: Расчёт с фурнитурой без выбранной конфигурации не запускается
- **WHEN** добавлены одна или несколько позиций фурнитуры, но конфигурация не выбрана
- **THEN** запрос расчёта стоимости не отправляется

### Requirement: Трёхколоночная раскладка приложения
Система ДОЛЖНА (SHALL) отображать основной экран в виде трёх визуально различимых колонок: узкой левой колонки для выбора сервиса, центральной колонки с основной рабочей панелью ввода данных двери и фурнитуры, и правой колонки с результатом расчёта. Левая и правая колонки ДОЛЖНЫ (SHALL) визуально отличаться фоном от центральной колонки (более светлый/нейтральный тон центра против затонированных боковых колонок), чтобы зрительно разграничивать назначение каждой колонки.

#### Scenario: Экран показывает три колонки
- **WHEN** страница открыта
- **THEN** одновременно видны три колонки: выбор сервиса, рабочая панель и результат расчёта, каждая визуально обособлена

### Requirement: Колонка выбора сервиса
Левая колонка ДОЛЖНА (SHALL) отображать список доступных сервисов; на данный момент единственный сервис — «Межкомнатные двери», ДОЛЖЕН (SHALL) отображаться выбранным по умолчанию. Поскольку других сервисов нет, выбор в этой колонке не меняет отображаемую рабочую панель.

#### Scenario: Единственный сервис отображается выбранным
- **WHEN** страница открыта
- **THEN** в левой колонке виден пункт «Межкомнатные двери», отмеченный как текущий выбранный

### Requirement: Группировка рабочей панели по аккордеону
Центральная колонка ДОЛЖНА (SHALL) группировать содержимое рабочей панели в три независимых, изначально развёрнутых раздела аккордеона: «Полотно» (переключатели «Реверс» и «Нужно зеркало», выбор исполнения зеркала, выбор коллекции, шаг и опции компонента «Полотно», шаг и опции компонента «Кромка»), «Короб и обрамление» (шаг и опции компонента «Короб» с составом его стоек, шаг и опции компонента «Наличник», шаг и опции компонента «Добор») и «Фурнитура» (блок выбора позиций фурнитуры). Каждый раздел ДОЛЖЕН (SHALL) сворачиваться и разворачиваться независимо от остальных; ни один раздел не ДОЛЖЕН (SHALL NOT) блокироваться или скрываться в зависимости от состояния выбора в других разделах — доступность конкретных шагов и опций внутри раздела по-прежнему определяется существующей каскадной логикой (см. «Каскадный выбор компонента конфигурации» и связанные требования).

#### Scenario: Все три раздела развёрнуты по умолчанию
- **WHEN** страница открыта и каталог конфигураций загружен
- **THEN** разделы «Полотно», «Короб и обрамление» и «Фурнитура» видны развёрнутыми одновременно

#### Scenario: Разделы сворачиваются и разворачиваются независимо
- **WHEN** пользователь сворачивает один из трёх разделов
- **THEN** остальные два раздела остаются в своём текущем состоянии (развёрнутом или свёрнутом) без изменений

#### Scenario: Раздел «Короб и обрамление» доступен для раскрытия до выбора полотна
- **WHEN** полотно ещё не выбрано
- **THEN** раздел «Короб и обрамление» всё равно можно развернуть; каскадные шаги внутри него отображаются по действующим правилам (пусто или ограниченно, если каскад ещё не определил доступные типы)

### Requirement: Sticky-панель результата расчёта
Правая колонка ДОЛЖНА (SHALL) оставаться видимой на экране (закреплённой) при прокрутке центральной колонки, пока правая колонка целиком помещается в высоту окна просмотра. Она ДОЛЖНА (SHALL) показывать результат расчёта стоимости (см. «Автоматический расчёт стоимости по текущему выбору») либо, до определения конфигурации, нейтральное пустое состояние без результата и без ошибки.

#### Scenario: Панель результата остаётся видна при прокрутке
- **WHEN** центральная колонка достаточно длинная, чтобы требовалась прокрутка, и пользователь прокручивает её
- **THEN** правая колонка с результатом расчёта остаётся видимой на экране

#### Scenario: Пустое состояние до выбора конфигурации
- **WHEN** конфигурация ещё не определена
- **THEN** правая колонка показывает нейтральное пустое состояние, не показывая ни результат, ни сообщение об ошибке

### Requirement: Приглушённое отображение предыдущего результата во время пересчёта
Пока новый запрос расчёта стоимости ожидает ответа (включая время паузы debounce после изменения), sticky-панель ДОЛЖНА (SHALL) продолжать показывать ранее полученный результат расчёта в визуально приглушённом виде (менее контрастно, чем актуальный результат), а не скрывать его полностью. Как только приходит ответ на актуальный запрос (успешный результат или ошибка), приглушённое отображение ДОЛЖНО (SHALL) замениться обычным отображением нового результата или сообщения об ошибке.

#### Scenario: Предыдущий результат виден приглушённым при ожидании нового расчёта
- **WHEN** пользователь меняет опцию после того, как результат расчёта уже был показан, и новый запрос ещё не завершён (включая паузу debounce)
- **THEN** ранее показанный результат остаётся видимым в приглушённом виде, не пропадая полностью

#### Scenario: Приглушённое отображение заменяется новым результатом
- **WHEN** приходит ответ на актуальный запрос расчёта
- **THEN** приглушённое отображение заменяется обычным отображением нового результата или сообщения об ошибке
