## Why

Change `add-leaf-panel-type` добавил на backend классификацию полотна по типу (глухое / остеклённое / с зеркалом) и уже отдаёт её в ответе каталога конфигураций (`GET /api/door-configurations`, поле `panelType` leaf-компонента), но сознательно не трогал frontend. Сейчас это значение нигде не видно пользователю конфигуратора — TypeScript-тип каталога его не описывает, ни один компонент его не читает.

## What Changes

- В `ComponentCatalogDto` (frontend/src/api/types.ts) добавить поле `panelType`, отражающее уже существующее поле API (значения `'BLIND' | 'GLAZED' | 'MIRRORED' | null`).
- В карточке «Параметры выбранного полотна» конфигуратора отображать тип текущего выбранного полотна как человекочитаемую подпись (глухое / остеклённое / с зеркалом) — только для чтения, без возможности фильтрации или выбора по этому признаку (это не сужает каталог, как коллекция или исполнение зеркала, — просто справочная информация о выбранном полотне).
- Функциональность расчёта стоимости, состав запроса и сужение каталога этим изменением не затрагиваются — чисто отображение уже присутствующих в ответе API данных.

(нет)

### Modified Capabilities

- `door-configurator-ui`: карточка параметров выбранного полотна дополняется отображением типа полотна (глухое/остеклённое/с зеркалом) для текущей выбранной конфигурации.

## Impact

- **Backend**: изменений нет (API уже отдаёт нужное поле, добавлено в change `add-leaf-panel-type`).
- **Frontend**: `api/types.ts` — новое поле `panelType` в `ComponentCatalogDto`; `App.tsx` — отображение подписи с типом полотна в карточке «Параметры выбранного полотна» и словарь соответствия кодов человекочитаемым подписям.
