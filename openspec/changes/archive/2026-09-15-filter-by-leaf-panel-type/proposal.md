## Why

Change `add-leaf-panel-type` добавил классификацию полотна по типу (глухое/остеклённое/с зеркалом), а `show-leaf-panel-type` — чисто информационное отображение этого типа рядом с выбором коллекции. Признак наличия зеркала при этом продолжает жить отдельно, как переключатель «Нужно зеркало» — старый, независимый от типа полотна механизм сужения каталога. Это дублирование: у полотна уже есть тип «с зеркалом», но каталог сужается по отдельному boolean-признаку, а не по нему. По Figma-макету (`node #6:57`) переключателя «Нужно зеркало» в потоке больше нет вовсе — вместо него сужение по признаку зеркала выполняет сам переключатель «Тип полотна», и «Глухое» показано предвыбранным сегментом.

## What Changes

- **BREAKING (поведение UI)**: переключатель «Нужно зеркало» убирается из потока. Вместо него сегментированный переключатель «Тип полотна» (уже отображается рядом с «Коллекция» с change `show-leaf-panel-type`, но пока чисто информационно) становится настоящим сужающим псевдо-шагом каскада — аналогично «Реверсу»: по умолчанию выбрано «Глухое» (если оно есть среди доступных вариантов), явный клик по «Зеркальное» сужает каталог до полотен этого типа и раскрывает шаг выбора конкретного исполнения зеркала (без изменений в самом этом шаге и в расчёте стоимости — id/наценки/API запроса расчёта не меняются).
- Шаг «Тип полотна» скрывается, если среди согласованных с реверсом door_configuration встречается только одно значение типа полотна — точно так же, как сейчас скрывается «Реверс», если у всех конфигураций одинаковый is_reverse.
- **Уточнение (по обратной связи после первой реализации)**: «Глухое» — не отдельная непересекающаяся категория моделей, а базовое исполнение, доступное любому полотну, включая те, что дополнительно поддерживают зеркало. Поэтому выбор «Глухое» НЕ сужает каталог (доступны все коллекции/модели, согласованные с реверсом); сужают только «Зеркальное» и «С остеклением» — до моделей, которые дополнительно это поддерживают. Классификация leaf_type в БД (`panel_type`) не меняется — меняется только то, что означает выбор «Глухое» на фронте.
- Вариант «С остеклением» в этом переключателе появится сам собой, когда в каталоге появится хотя бы один leaf_type с этим типом (см. Impact) — этот change не добавляет остеклённые модели и не вводит для них наценку или справочник видов остекления; это осознанно отложено на будущий change.
- Выбор коллекции, как и раньше, сужается по уже выбранному типу полотна (было — по «Нужно зеркало»); остальной каскад (модель, кромка, короб, наличник, добор) не меняется.
- Backend, расчёт стоимости, API — без изменений: это чисто фронтенд-миграция механизма сужения, наценка и выбор конкретного исполнения зеркала продолжают работать как прежде.

## Capabilities

### Modified Capabilities

- `door-configurator-ui`: переключатель «Нужно зеркало» заменяется настоящим сужением по «Тип полотна»; шаг выбора конкретного исполнения зеркала раскрывается по выбору типа «Зеркальное» вместо переключателя; выбор коллекции сужается по типу полотна вместо признака зеркала.

## Impact

- **Backend**: изменений нет.
- **Frontend**: `App.tsx` — удаляются `mirrorFinishEnabled`/`MIRROR_FINISH_NEEDED_LABEL`/переключатель «Нужно зеркало»; `resolveMirrorFinishStep`/`filterByMirrorFinish` заменяются на аналог `resolveReverseStep` для типа полотна (`resolvePanelTypeStep` — вычисляет видимость/значение по умолчанию из реверс-суженных конфигураций); `OptionGroup` «Тип полотна» (добавлен в `show-leaf-panel-type`) получает реальные `selectedId`/`onChange` вместо no-op; `collectionOptions` считаются от конфигураций, суженных по типу полотна.
- Будущее (вне рамок этого change): справочник видов остекления, наценка за остекление и появление реальных leaf_type с типом «остеклённое» — самостоятельный change, после которого вариант «С остеклением» в этом переключателе станет доступен сам собой, без доработки самого переключателя.
