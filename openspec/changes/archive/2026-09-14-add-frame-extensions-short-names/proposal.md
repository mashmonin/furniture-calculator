## Why

Краткое наименование (`short_name`) уже реализовано как общий контракт для всех справочников `CatalogType` (см. `catalog-reference-short-name`) и заполнено итеративно только для `edge_type`. Сейчас нужно продолжить заполнение — на этот раз для `frame_extensions_type` (доборы), где ширина в скобках названия («100 мм», «140 мм» и т.д.) неудобна для компактных мест интерфейса и уже сейчас отображается как есть (см. группу «Тип» карточки «Добор»).

## What Changes

- Заполнить `short_name` для всех строк `frame_extensions_type` семейств «Добор ТС» (`FET-004`–`FET-007`) и «Добор КОМПЛАНАР» (`FET-008`–`FET-013`) — значением, равным числу миллиметров из названия строки:
  - «Добор ТС 100 мм» → «100», «Добор ТС 140 мм» → «140», «Добор ТС 190 мм» → «190», «Добор ТС 400 мм» → «400»
  - «Добор КОМПЛАНАР 100 мм» → «100», «Добор КОМПЛАНАР 140 мм» → «140», «Добор КОМПЛАНАР 190 мм» → «190», «Добор КОМПЛАНАР 400 мм» → «400», «Добор КОМПЛАНАР 600 мм» → «600», «Добор КОМПЛАНАР 800 мм» → «800»
- Остальные строки `frame_extensions_type` (`FET-001`–`FET-003` — укрупнённые группы «ДОБОРЫ ДЛЯ КОРОБА…», не входящие в набор конкретных ширин) этим изменением не затрагиваются — `short_name` для них остаётся `NULL`.
- Никаких изменений в бэкенд-коде, DTO или фронтенде не требуется — колонка `short_name` и её отдача через `ReferenceDto.shortName` уже реализованы; меняются только данные (новый Liquibase changeset).

## Capabilities

(нет)

### Modified Capabilities
- `catalog-reference-short-name`: добавляется требование о конкретных значениях `short_name` для строк `frame_extensions_type` семейств «Добор ТС» и «Добор КОМПЛАНАР».

## Impact

- **БД**: новый Liquibase changeset — `update` десяти строк `frame_extensions_type` (по их `code`, `FET-004`–`FET-013`) с проставлением `short_name`.
- **Backend/Frontend**: без изменений кода — фронтенд уже использует `shortName ?? name` там, где показывает тип добора (см. `displayName` в `App.tsx`), поэтому новые краткие имена подхватятся автоматически после применения миграции.
