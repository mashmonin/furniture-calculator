## Why

Наличники «Эво», «Авеню», «Ария» и «Аура» (в том числе варианты для системы «КОМПЛАНАР РЕВЕРС») короба «Компланар» физически подходят не при любой высоте полотна — как и добор «ТС» и наличники «Модо»/«Онда» (см. `link-dobor-ts-length-to-leaf-height`, `link-modo-onda-casing-length-to-leaf-height`), каждому диапазону высоты полотна соответствует ровно одна допустимая длина наличника, а для части диапазонов конкретный наличник вообще недоступен. Сейчас в каталоге у всех этих наличников есть только одна опция длины (2100 мм, ось «Длина», без диапазона) без привязки к высоте полотна, поэтому клиент может собрать физически невозможную конфигурацию.

## What Changes

- Backend: уже обобщённое правило «длина обязательна + совместима с диапазоном высоты полотна» (`requireLengthWithinLeafRange`, введено в `link-modo-onda-casing-length-to-leaf-height`) распространяется на `DoorCasingType` с кодами `DCT-001` (Эво), `DCT-002`/`DCT-005` (Авеню / Авеню для системы КОМПЛАНАР РЕВЕРС), `DCT-006`/`DCT-007` (Аура / Аура для системы КОМПЛАНАР РЕВЕРС), `DCT-008`/`DCT-009` (Ария / Ария для системы КОМПЛАНАР РЕВЕРС) — множество `LENGTH_RANGE_DOOR_CASING_TYPE_CODES` расширяется этими 7 кодами (к уже входящим `DCT-003`/`DCT-004`). Сама логика метода не меняется — переиспользуется как есть.
- Для перечисленных наличников длина становится обязательной и ограничивается диапазоном высоты полотна:
  - 1900–2100 → длина 2250 мм (Эво, Авеню, Ария, Аура)
  - 2150–2250 → длина 2400 мм для Эво; 2700 мм для Авеню, Ария, Аура
  - 2300 (точка) → длина 2700 мм (Эво, Авеню, Ария, Аура)
  - 2350–2550 → длина 2700 мм (Эво, Авеню, Ария, Аура)
  - 2600–2850 → длина 3000 мм только для Эво; Авеню, Ария, Аура в этом диапазоне недоступны (опций нет)
  - 2900–2950 → Эво, Авеню, Ария, Аура недоступны (опций нет)
  - Высота полотна вне перечисленных диапазонов (например, 2101–2149, 2251–2299, 2551–2599, 2851–2899, от 2951) не покрывается ни одной опцией длины — как и для добора «ТС»/наличников «Модо»/«Онда», это означает недоступность наличника при такой высоте (ошибка валидации при расчёте, исчезновение из каскада на фронтенде), а не отдельный особый случай, требующий дополнительного описания.
  - Правило одинаково для обычного и реверс-варианта наличника (`DCT-002`/`DCT-005`, `DCT-006`/`DCT-007`, `DCT-008`/`DCT-009`) — реверс не меняет допустимые длины, только каталожный код наличника.
- Новая Liquibase-миграция: единственная существующая опция длины (value=2100, без диапазона) для каждого из 7 кодов переиспользуется под первый диапазон (value=2250, диапазон [1900, 2100]); добавляются новые опции длины по правилам выше — отдельно для Эво и отдельно для группы Авеню/Ария/Аура (включая их реверс-варианты, у каждого кода — собственные строки `liner_dimension_option`, как и сегодня). Уникальный индекс `uk_liner_dimension_option_door_casing_type` уже расширен диапазонными колонками в `link-modo-onda-casing-length-to-leaf-height` (миграция 0069 из этой же ветки разработки) — повторно менять не требуется.
- Цена наличников Эво/Авеню/Ария/Аура (включая реверс-варианты) перестаёт зависеть от выбранной длины — по тому же принципу, что и добор «ТС», наличники «Модо»/«Онда» (длина только гейтит допустимость выбора, а не формирует цену). Новая миграция обнуляет `length_option_id` в существующих строках `configuration_price` для этих 7 кодов.
- Frontend: список доступных длин наличника фильтруется по высоте полотна для всех 7 кодов через уже обобщённые `lengthRangeOptions`/`lengthRangeCoversHeight` — меняется только состав константы `LENGTH_RANGE_DOOR_CASING_TYPE_CODES`; выбор длины сбрасывается при смене высоты полотна; наличник исключается из каскадного выбора, если высота полотна уже выбрана и не покрывается ни одним диапазоном длины этого конкретного наличника.
- Правило гейтится исключительно кодом `DoorCasingType`, без отдельной проверки короба или признака реверса: в сегодняшнем каталоге коды `DCT-001`, `DCT-002`, `DCT-005`, `DCT-006`, `DCT-007`, `DCT-008`, `DCT-009` встречаются только в конфигурациях с коробом «Компланар» (`FT-002`, включая конфигурации с `is_reverse = true`) — ни разу с «НЕО» или «ФАНТОМ» (проверено по всем миграциям, ссылающимся на эти коды `door_casing_type`). Гейт по коду корректно ограничивает правило коробом «Компланар» тем же способом, каким гейт по коду `DCT-003`/`DCT-004` уже ограничивает предыдущее правило коробом «НЕО».

### Modified Capabilities

- `door-configuration-api`: добавляется требование о совместимости диапазона длины наличников «Эво»/«Авеню»/«Ария»/«Аура» (включая реверс-варианты) с высотой полотна и требование об обязательности длины для этих наличников — по аналогии с уже существующими требованиями для добора «ТС» и наличников «Модо»/«Онда».
- `door-configurator-ui`: добавляется требование об условной фильтрации длины этих наличников по высоте полотна и об исключении их из каскада при несовместимой высоте полотна — по аналогии с существующим требованием для наличников «Модо»/«Онда».

`door-configuration-catalog` не меняется на уровне спецификации: требования «Атрибуты liner_dimension_option» и «Структура configuration_price» уже сформулированы универсально для любого владельца и оси — новые данные и обнуление `length_option_id` укладываются в уже описанное поведение без изменения текста требований (тот же вывод, что и в `link-modo-onda-casing-length-to-leaf-height`).

## Impact

- **Backend**: `DoorConfigurationPricingService` — расширение константы `LENGTH_RANGE_DOOR_CASING_TYPE_CODES` семью новыми кодами (`DCT-001`, `DCT-002`, `DCT-005`, `DCT-006`, `DCT-007`, `DCT-008`, `DCT-009`); логика `requireLengthWithinLeafRange`/`validateHeightWithinLeafRange` не меняется.
- **БД**: обновление существующих строк `liner_dimension_option` (value 2100→2250, диапазон [1900, 2100]) и `configuration_price` (`length_option_id = NULL`) для 7 кодов наличников; новые строки `liner_dimension_option` под диапазоны 2150–2250, 2300, 2350–2550 (все 7 кодов) и 2600–2850 (только Эво).
- **Frontend**: `frontend/src/App.tsx` — расширение константы `LENGTH_RANGE_DOOR_CASING_TYPE_CODES`; остальной код (`lengthRangeOptions`, `lengthRangeCoversHeight`, фильтрация каскада, сброс выбора при смене высоты полотна) переиспользуется без изменений.
- **Тесты**: `DoorConfigurationPricingServiceTest` — новые кейсы по аналогии с кейсами наличников «Модо»/«Онда», включая проверку разных допустимых длин для Эво и для группы Авеню/Ария/Аура в одном и том же диапазоне высоты, реверс-вариантов наличника и точки 2300; `TestEntities` не требует новых перегрузок (`doorCasingType(id, code)` уже введена).
- Наличники «Модо»/«Онда» (`DCT-003`, `DCT-004`), добор «ТС», короба «НЕО»/«Компланар» (высота) и другие компоненты поведение не меняют.
