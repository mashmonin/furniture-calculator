## Why

Три несвязанных, но мелких доработки интерфейса конфигуратора, собранные пользователем в одну задачу «общие исправления»:

1. Поля «Другое значение длины/высоты (мм)» полотна сейчас меняются по единице (шаг 1) — неудобно при вводе значений с клавиатурными стрелками/колесом мыши, когда шаг фабрики по этим осям — десятки миллиметров.
2. Группа «Цвет» полотна отображается тем же рядом кнопок, что и остальные оси размеров — при большом числе цветов в коллекции ряд кнопок становится громоздким; выпадающий список компактнее.
3. У наличника (`door_casing_type`) единственная опция его собственного размера (2100 мм, есть у всех 9 существующих типов наличника) в каталоге исторически заведена на оси «Высота» (`DT-002`), из-за чего на фронтенде она отображается в группе «Высота» — хотя по смыслу это длина погонажного наличника, а не высота дверного проёма. Нужно, чтобы этот параметр отображался и передавался как «Длина» (`DT-001`).

## What Changes

- Frontend: полям «Другое значение длины (мм)» и «Другое значение высоты (мм)» полотна (`leaf`) задаётся шаг `+50` (кнопки стрелок / прокрутка колеса меняют значение на 50, а не на 1). Остальных полей (в т.ч. `InputNumber` «Количество») это не касается.
- Frontend: группа «Цвет» полотна (`leaf`) отображается как выпадающий список (`antd Select`) с единственным выбором вместо ряда кнопок; допускает очистку выбора. Группа «Цвет» у остальных компонентов (короб, кромка, наличник, добор) не меняется — остаётся рядом кнопок, как раньше.
- Данные каталога: единственная опция размера наличника (`liner_dimension_option`, value=2100, сейчас `liner_dimension_type_id` = id `DT-002`) переносится на ось `DT-001` для всех 9 существующих `door_casing_type` (`DCT-001`–`DCT-009`); соответствующие строки `configuration_price` наличника переносятся с `height_option_id` на `length_option_id`. **Чисто данные** — механизм каталога (`liner_dimension_option`/`configuration_price`) уже владельце- и осе-агностичен, а фронтенд уже рендерит группы «Длина»/«Высота» по факту наличия опций нужной оси в каталоге (см. design.md) — после переноса данных наличник автоматически появится в группе «Длина» и пропадёт из группы «Высота», без изменений в коде.

### Modified Capabilities

- `door-configurator-ui`: группа «Цвет» полотна получает отдельное требование (выпадающий список вместо кнопок); требование о произвольном значении длины/высоты полотна дополняется деталью о шаге `+50`.

Перенос оси наличника (пункт 3) не требует изменения `door-configuration-api` или `door-configuration-catalog`: их требования уже сформулированы обобщённо по владельцу/оси (см. design.md) и не называют, какую именно ось использует конкретный тип компонента — перенос данных укладывается в уже описанное поведение.

## Impact

- **Frontend**: `frontend/src/App.tsx` (шаг `InputNumber` для длины/высоты полотна; рендер группы «Цвет» для `leaf` через новый вариант компонента), `frontend/src/components/OptionGroup.tsx` (или новый соседний компонент — см. design.md) — добавление режима отображения «выпадающий список».
- **БД**: новая Liquibase-миграция — `UPDATE liner_dimension_option` (перенос оси наличника DT-002→DT-001) и `UPDATE configuration_price` (перенос ссылки height_option_id→length_option_id) для всех строк с `door_casing_type_id IS NOT NULL`.
- **Backend**: изменений нет — `DoorConfigurationPricingService` уже работает с `lengthOption`/`heightOption` для наличника обобщённо, без привязки к конкретной оси.
- **Тесты**: фронтенд — ручная проверка (шаг ввода, выпадающий список, наличник в группе «Длина»); backend-тестов, специфичных для наличника, не затрагивается (ни `DoorConfigurationPricingServiceTest`, ни `TestEntities` не завязаны на конкретную ось наличника).
- Кромка, короб, добор и их существующая логика диапазонов — не затрагиваются.
