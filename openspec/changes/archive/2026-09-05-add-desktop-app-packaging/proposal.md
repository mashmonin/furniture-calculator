## Why

Сейчас приложение запускается только как связка «Spring Boot backend + PostgreSQL в Docker + браузерный доступ к React SPA» — это удобно для разработки, но непригодно для конечного пользователя, у которого нет ни своего сервера, ни Docker, ни понимания, как всё это поднять. Нужен способ раздать приложение как обычный десктопный продукт: скачал установщик — получил рабочее приложение с иконкой в доке, без внешних зависимостей.

## What Changes

- Backend упаковывается в нативный установщик macOS (`.dmg`) через `jpackage` с урезанным JRE (`jlink`) — пользователю не нужно ставить Java отдельно.
- Приложение открывается в отдельном нативном окне (JavaFX `WebView`), а не в системном браузере — со своей иконкой и жизненным циклом, без адресной строки браузера.
- **BREAKING** (только для десктоп-сборки, не для серверного развёртывания): база данных для десктоп-режима меняется с PostgreSQL на встроенную файловую БД (H2) — приложению больше не нужен отдельно запущенный сервер БД. Серверное/облачное развёртывание с PostgreSQL остаётся отдельным, независимым профилем и не убирается.
- Liquibase-миграции адаптируются под диалект H2 (PostgreSQL-специфичный SQL, если такой есть в существующих changeset'ах, потребует H2-совместимой альтернативы или per-dialect changeset'ов).
- Пользовательские данные (файл БД H2, настройки) хранятся в стандартном пользовательском каталоге ОС (`~/Library/Application Support/...`), вне каталога установки приложения, — чтобы обновление приложения их не затрагивало.
- Добавляется механизм проверки версии: при старте приложение сверяет текущую версию с последней опубликованной и показывает уведомление о доступном обновлении со ссылкой на скачивание. Автоматическая установка обновления — вне рамок этого изменения.
- Настраивается стабильный идентификатор приложения (bundle ID) для `jpackage`, чтобы повторная установка `.dmg` корректно заменяла предыдущую версию.
- Целевая платформа первой версии — только macOS; Windows и Linux — вне рамок этого изменения.

## Capabilities

### New Capabilities
- `desktop-app-packaging`: упаковка приложения в нативный desktop-дистрибутив (macOS `.dmg`) с embedded JRE, запуск backend и открытие UI в отдельном нативном окне (JavaFX WebView), хранение пользовательских данных в файловой БД (H2) в стандартном каталоге ОС, проверка версии и уведомление об обновлениях.

### Modified Capabilities
_Нет изменений в требованиях существующих capability — REST API и поведение UI не меняются, меняется только способ доставки и хранения данных для desktop-профиля._

## Impact

- **Backend**: новый Gradle-таск/конфигурация для `jlink` + `jpackage`; новый Spring-профиль (например, `desktop`) с datasource на H2 вместо PostgreSQL; ревизия Liquibase changelog'ов на предмет PostgreSQL-специфичного SQL; добавление эндпоинта/механизма проверки версии.
- **Frontend**: без изменений в коде — прод-сборка (`npm run build`) уже используется, просто раздаётся backend'ом внутри desktop-приложения вместо dev-сервера.
- **Новая зависимость**: JavaFX (модули `javafx.controls`, `javafx.web`, `javafx.graphics`) для окна WebView.
- **Инфраструктура сборки**: новый пайплайн для сборки `.dmg` на macOS (не пересекается с текущим `docker-compose.yml`, который остаётся для серверной/dev-конфигурации с PostgreSQL).
- **Существующее серверное развёртывание с PostgreSQL не затрагивается** — это отдельный профиль, а не замена.
