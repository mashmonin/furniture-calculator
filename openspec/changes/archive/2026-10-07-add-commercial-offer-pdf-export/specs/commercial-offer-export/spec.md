## Purpose

Формирование клиентского коммерческого предложения (КП) в формате PDF по позициям заказа из корзины: фирменное оформление HAUSDOORS, изображение двери выбранного цвета, характеристики и таблица комплектации с клиентскими ценами.

## ADDED Requirements

### Requirement: Эндпоинт выгрузки КП
Система ДОЛЖНА (SHALL) предоставлять эндпоинт `POST /api/specification/export-offer`, принимающий тот же непустой список позиций заказа, что и `POST /api/specification/export-order` (см. order-export-api, «Эндпоинт выгрузки заказа целиком»), и подчиняющийся тем же правилам валидации (404 для несуществующего `leaf_type`, 400 для недопустимых id опций, пустого списка и количества меньше 1). При невалидном запросе файл НЕ ДОЛЖЕН (SHALL NOT) формироваться.

#### Scenario: Успешная выгрузка КП
- **WHEN** отправляется корректный непустой список позиций
- **THEN** эндпоинт отвечает PDF-файлом с `Content-Type: application/pdf` и заголовком `Content-Disposition: attachment` с именем вида `КП-<номер заказа>.pdf` (кириллица кодируется по RFC 5987; номер заказа — см. «Структура страниц КП»)

#### Scenario: Пустой список отклоняется
- **WHEN** отправляется запрос с пустым списком позиций
- **THEN** эндпоинт отвечает ошибкой 400 и не формирует файл

#### Scenario: Невалидная позиция отклоняет весь запрос
- **WHEN** хотя бы одна позиция ссылается на несуществующий `leaf_type` или недопустимую опцию
- **THEN** эндпоинт отвечает той же ошибкой (404 или 400), что и `export-order`, и не формирует частичный файл

### Requirement: Структура страниц КП
PDF ДОЛЖЕН (SHALL) состоять из страниц формата A4 по образцу заказа HAUSDOORS: каждая позиция заказа начинается с новой страницы, в порядке запроса; обложки и страницы контактов нет. Шапка каждой страницы ДОЛЖНА (SHALL) содержать логотип HAUSDOORS, строку «Номер заказа» и строку «Дата и время заказа» (формат `дд.ММ.гггг чч:мм`), оформленные тонкими разделительными линиями. Номер заказа ДОЛЖЕН (SHALL) формироваться по моменту выгрузки в формате `ггммддччмм` и совпадать с номером в имени файла. Текстовые описания моделей и покрытий НЕ ДОЛЖНЫ (SHALL NOT) выводиться.

#### Scenario: Одна позиция — одна страница
- **WHEN** выгружается КП по заказу из двух позиций, каждая из которых помещается на страницу
- **THEN** документ содержит две страницы, на каждой — шапка с логотипом, номером и датой заказа

#### Scenario: Номер заказа совпадает с именем файла
- **WHEN** КП сформировано 07.10.2026 в 12:49
- **THEN** в шапке указан номер `2610071249`, а файл называется `КП-2610071249.pdf`

### Requirement: Страница позиции
Страница позиции ДОЛЖНА (SHALL) содержать: изображение двери (см. «Подбор изображения двери») слева; справа — строки характеристик «Модель» (наименование позиции с атрибутами конфигурации), «Цвет» (цвет полотна, если задан), «Размер» (полотно в формате «ширина*высота*толщина», мм, например `900*2200*44`; толщина — если выбрана), «Количество», а при нескольких позициях в заказе — «Позиция N из M»; ниже — таблицу комплектации с колонками «Наименование», «Размер», «Цвет», «К-во», «Цена», «Стоимость» (цвет — в отдельной колонке, а не в наименовании; шрифт таблицы уменьшен), где первой строкой идёт полотно с размером «ширина*высота*толщина», далее — каждый применимый компонент (кромка, короб, наличник, добор, фурнитура, декоративные элементы) с цветом, количеством и клиентской (розничной) ценой; под таблицей — крупную строку «Итоговая цена:» (цена за единицу × количество позиции). Дилерские цены НЕ ДОЛЖНЫ (SHALL NOT) попадать в КП. Таблица, не помещающаяся на странице, ДОЛЖНА (SHALL) переноситься на следующую страницу с повтором заголовка колонок и шапки страницы.

#### Scenario: Только клиентские цены
- **WHEN** выгружается КП по позиции, у которой дилерская и клиентская цены различаются
- **THEN** в документе присутствуют только клиентские цены, дилерских значений нет

#### Scenario: Итоговая цена учитывает количество
- **WHEN** клиентская цена позиции за единицу — 17 761 ₽, количество — 2
- **THEN** «Итоговая цена» показывает 35 522 ₽, а в характеристиках указано «Количество 2 шт.»

#### Scenario: Длинная таблица переносится
- **WHEN** комплектация позиции не помещается на одну страницу
- **THEN** продолжение таблицы выводится на следующей странице с повторённой строкой заголовков колонок

### Requirement: Итог по заказу
Если в заказе больше одной позиции, КП ДОЛЖНО (SHALL) завершаться строкой «Итого по заказу» — суммой значений «Итоговая цена» всех позиций — на последней странице, в формате «123 456 ₽». При одной позиции отдельная строка не выводится (итог совпадает с «Итоговой ценой»).

#### Scenario: Итог суммирует все позиции
- **WHEN** заказ состоит из позиций на 35 522 ₽ и 17 761 ₽
- **THEN** на последней странице выводится «Итого по заказу 53 283 ₽»

#### Scenario: Одна позиция без отдельного итога
- **WHEN** заказ состоит из одной позиции
- **THEN** строка «Итого по заказу» не выводится

### Requirement: Подбор изображения двери
Система ДОЛЖНА (SHALL) подбирать изображение двери из каталога изображений по модели и цвету полотна позиции (лицевая сторона для двусторонней покраски). Изображения поставляются вместе с приложением (в т.ч. в desktop-дистрибутиве) и поддерживают форматы JPEG и WebP. Если для сочетания «модель + цвет» изображения нет, страница позиции ДОЛЖНА (SHALL) выводиться без изображения (с пометкой «Изображение недоступно»), а выгрузка — завершаться успешно.

#### Scenario: Изображение найдено
- **WHEN** у позиции модель и цвет полотна, для которых в каталоге изображений есть файл
- **THEN** этот файл выводится на странице позиции

#### Scenario: Изображения нет
- **WHEN** для модели и цвета позиции в каталоге изображений нет файла
- **THEN** страница позиции выводится без изображения (с пометкой «Изображение недоступно»), ошибка не возвращается, остальные позиции не затрагиваются

### Requirement: Корректность кириллицы и ₽
Все тексты КП, включая символ «₽», ДОЛЖНЫ (SHALL) отображаться без замены на «?» и пустые квадраты на любой платформе (в т.ч. в desktop-сборках macOS и Windows); шрифт поставляется вместе с приложением и не зависит от шрифтов ОС.

#### Scenario: Кириллица в desktop-сборке
- **WHEN** КП выгружается из desktop-приложения на машине без установленных шрифтов с кириллицей
- **THEN** все русские тексты и символ «₽» в PDF отображаются корректно
