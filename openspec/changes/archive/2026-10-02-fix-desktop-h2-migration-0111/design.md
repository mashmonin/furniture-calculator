## Context

`changes/0111-mirror-boolean-for-blind-leaf.yaml` содержит три changeset'а: `0111-1` (UPDATE `panel_type`), `0111-2` (пересоздание CHECK на `leaf_type.panel_type`) и `0111-3` (функция `plpgsql` + `BEFORE INSERT OR UPDATE` триггер на `mirror_finish_option`, запрещающий ссылаться на `leaf_type` с `panel_type <> 'BLIND'`). На H2 (`MODE=PostgreSQL`) падает только `0111-3`: `CREATE FUNCTION … LANGUAGE plpgsql` не поддерживается. Профиль `desktop` задаёт `liquibase.contexts: desktop`, а `db.changelog-master.yaml` уже разводит несовместимые файлы по контекстам `!desktop` / `desktop`, подставляя версии из `changes-desktop-overrides/`.

Требование к данным (спека `door-configuration-catalog`, «Владение mirror_finish_option»): вставка `mirror_finish_option` для остеклённого `leaf_type` отклоняется БД.

## Goals / Non-Goals

**Goals:**
- Десктопная БД (H2) проходит весь changelog без ошибок.
- Правило «зеркало только у глухих полотен» продолжает гарантироваться БД и на H2.

**Non-Goals:**
- Переписывать применённые changeset'ы (`0111` остаётся как есть).
- Добавлять в релизный workflow прогон тестов (см. Open Questions).

## Decisions

1. **Принцип «без процедурной логики в БД».** Целостность — только декларативными ограничениями; триггеры и `plpgsql` не используются. Причина: код миграций должен одинаково выполняться на PostgreSQL и H2 (desktop) без override-файлов для логики. Записывается в `CLAUDE.md`.
2. **Составной внешний ключ вместо триггера, общий для обеих БД.** Новый changeset `0114`: `UNIQUE (id, panel_type)` на `leaf_type`; в `mirror_finish_option` — колонка `leaf_panel_type VARCHAR(20) NOT NULL DEFAULT 'BLIND'` с `CHECK (leaf_panel_type = 'BLIND')` и FK `(leaf_type_id, leaf_panel_type) → leaf_type(id, panel_type)`. Вставка со ссылкой на остеклённый `leaf_type` нарушает FK — то же наблюдаемое поведение, что у триггера. Альтернативы: (а) Java-триггер H2 — противоречит принципу; (б) валидация в приложении — противоречит ранее принятому решению (БД как источник целостности, change `mirror-boolean-for-blind-leaf`).
3. **Удаление триггера — отдельным changeset'ом `0114`, а не правкой `0111`.** `0111-3` уже применён к PostgreSQL, применённые changeset'ы не редактируются. На PostgreSQL `0114` сначала снимает триггер и функцию (changeSet с `dbms: postgresql`), затем общая часть добавляет FK.
4. **Override `0111` для desktop пропускает `0111-3`.** H2 не поддерживает `plpgsql`; триггера там не было и не будет, правило обеспечит `0114`. Файл содержит `0111-1` и `0111-2` без изменений.
5. **Разделение include по контекстам** — как у `0105`/`0097`; `0114` без контекста (выполняется всегда).

## Risks / Trade-offs

- [Дополнительная колонка `leaf_panel_type` есть только на H2 → расхождение схем] → задокументировать в комментарии override-файла; JPA-сущности её не маппят (`ddl-auto: validate` не проверяет лишние колонки) — проверить тестом.
- [Не только `0111` несовместим с H2: следующие changeset'ы на H2 не проверялись] → прогнать полный changelog на H2 и исправить найденное в рамках задач, при существенном расширении — вынести отдельным change.
- [Уже выпущенные десктопные версии могут не стартовать] → определить затронутые версии и выпустить исправленную сборку (вне этого change).
