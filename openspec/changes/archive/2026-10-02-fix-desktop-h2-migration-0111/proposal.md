## Why

Десктопное приложение работает на локальной H2 (профиль `desktop`), а changeset `0111-3` (`0111-mirror-boolean-for-blind-leaf.yaml`) создаёт PostgreSQL-функцию на `plpgsql` и триггер — H2 их не поддерживает. Миграция падает с синтаксической ошибкой, поэтому на H2 не проходят ни она, ни все следующие за ней (`0112`, `0113`), и десктопное приложение не может инициализировать БД и запуститься. Это уже видно по падающим `DesktopProfileTest` и `DesktopLauncherBackendStartupTest`. Релизный workflow (`macos-release.yml`) тесты не запускает — только `desktopAppImage`, поэтому CI «зелёный», а поломка доезжает до собранных дистрибутивов.

## What Changes

- Принцип проекта: в БД нет процедурной логики (триггеры, функции `plpgsql`), целостность обеспечивается декларативными ограничениями (PK/FK/UNIQUE/CHECK). Принцип записывается в `CLAUDE.md`.
- Для профиля `desktop` добавляется H2-совместимый вариант `0111` в `changes-desktop-overrides/` (по паттерну `0006`, `0054`, `0094`, `0097`, `0105`): `0111-1` и `0111-2` без изменений, `0111-3` (триггер) пропускается. Оригинальный `changes/0111-…` не редактируется.
- Новый общий (для PostgreSQL и H2) changeset `0114`: правило «mirror_finish_option ссылается только на leaf_type с panel_type = BLIND» обеспечивается составным внешним ключом; на PostgreSQL триггер и функция из `0111-3` удаляются. Схемы обеих БД становятся одинаковыми.
- В `db.changelog-master.yaml` include `0111` разделяется по контекстам `!desktop` / `desktop`, подключается `0114`.
- Проверяется, что весь changelog (включая `0112` и `0113`) проходит на H2: тесты `DesktopProfileTest` и `DesktopLauncherBackendStartupTest` снова зелёные.

## Impact

- Backend: новый `changes-desktop-overrides/0111-mirror-boolean-for-blind-leaf.yaml`, новый `changes/0114-…yaml`, правка `db.changelog-master.yaml`; `CLAUDE.md` (принцип).
- Десктопные сборки: пользователи, поставивших версии после появления `0111`, не могли запустить приложение — после исправления приложение стартует (проверить, какие выпущенные версии затронуты).
- PostgreSQL: триггер и функция `0111-3` удаляются, правило сохраняется составным FK (внешнее поведение то же). API и frontend: без изменений.
