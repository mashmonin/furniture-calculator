## Why

У кромки (edge_type) допустимая «высота» — не независимая величина, а диапазон совместимости с фактической высотой уже выбранного полотна (например, «Полотно Н до 2100 мм», «Полотно Н 2150–2400 мм»). Сейчас liner_dimension_option хранит только одну точечную величину (value) и никак не выражает диапазон, поэтому нет никакой связи между высотой кромки и высотой полотна: пользователь в теории может выбрать несовместимую пару, и это никак не проверяется.

## What Changes

- Добавить в liner_dimension_option необязательный столбец min_value: для диапазонных опций (высота кромки) value становится верхней границей диапазона, min_value — нижней (NULL означает открытую нижнюю границу — «до X мм»). Для существующих точечных осей (длина/высота/толщина полотна и т.п.) min_value не заполняется — обратная совместимость без изменения существующих constraint'ов.
- Расширить расчёт стоимости (`POST /api/door-configurations/{id}/price`): при валидации выбранной клиентом liner_dimension_option для оси «Высота» edge-компонента дополнительно проверять, что диапазон [min_value, value] этой опции покрывает фактическое значение высоты, выбранной клиентом для leaf-компонента той же конфигурации. Несовпадение — ошибка 400 (по аналогии с уже существующей проверкой «опция не принадлежит компоненту»).
- Изменить конфигуратор: группа кнопок «Высота» для кромки на шаге «Выберите опции» скрыта, пока не выбрана высота полотна; после выбора высоты полотна группа показывает только те опции высоты кромки, чей диапазон покрывает выбранную высоту (обычно ровно одну — существующее правило «даже единственный вариант требует явного клика» продолжает применяться без изменений).

## Capabilities

### Modified Capabilities
- `door-configuration-catalog`: структура liner_dimension_option дополняется необязательным диапазоном (min_value/value) вместо только точечного значения.
- `door-configuration-api`: расчёт стоимости дополняется проверкой совместимости диапазона высоты кромки с выбранной высотой полотна.
- `door-configurator-ui`: группа «Высота» кромки становится условной (скрыта до выбора высоты полотна) и фильтруется по совместимости с ней.

## Impact

- **Backend**: новая Liquibase-миграция (addColumn `min_value` на `liner_dimension_option`, nullable — без данных в этом изменении, см. Open Questions в design.md); изменение сущности `LinerDimensionOption` и `DoorConfigurationPricingService` (новая проверка диапазона для edge-компонента, требующая доступа к выбору leaf-компонента внутри валидации edge).
- **Frontend**: типы каталога дополняются полем `minValue` для `LinerDimensionOptionDto`; в `App.tsx` рендер группы «Высота» для edge-компонента становится условным и зависит от выбора высоты leaf-компонента.
- **База данных**: `liner_dimension_option` получает новый nullable столбец. Реальные диапазоны высоты и цены для существующих 2 edge_type (ET-001, ET-002) этим изменением не наполняются — механизм и данные разделены (пользователь предоставит конкретные значения диапазонов и цен отдельно).
