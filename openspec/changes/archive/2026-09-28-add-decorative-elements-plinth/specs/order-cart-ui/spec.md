## MODIFIED Requirements

### Requirement: Кнопка «Посмотреть» открывает конфигурацию в конфигураторе
Столбец «Действия» ДОЛЖЕН (SHALL), наряду с «Удалить», содержать действие «Посмотреть». По нажатию система ДОЛЖНА (SHALL) переключить приложение на экран конфигуратора «Эмаль и шпон» (см. door-configurator-ui), заполнить его каскад выбора (тип полотна, коллекцию, полотно и все его опции, кромку, короб, наличник, добор, декоративные элементы, фурнитуру, реверс) точно так, как он был в момент добавления этой позиции в корзину — используя данные, сохранённые в позиции (см. «Хранение корзины в localStorage»), без нового обращения к backend, — и перевести конфигуратор в режим редактирования именно этой позиции (см. «Живая синхронизация конфигурации, открытой из корзины»). «Посмотреть» НЕ ДОЛЖНО (SHALL NOT) разворачивать вложенную таблицу детализации строки — это отдельное действие (см. «Разворачиваемая детализация позиции корзины»).

#### Scenario: «Посмотреть» открывает конфигуратор с заполненным каскадом
- **WHEN** пользователь нажимает «Посмотреть» у позиции корзины
- **THEN** приложение показывает экран конфигуратора, каскад выбора и введённые опции полностью соответствуют тому, что было выбрано при добавлении этой позиции в корзину, и по ним показан рассчитанный результат

#### Scenario: «Посмотреть» восстанавливает добавленные декоративные элементы
- **WHEN** позиция корзины содержала одну или несколько позиций декоративных элементов на момент добавления, и пользователь нажимает «Посмотреть»
- **THEN** блок «Декоративные элементы» конфигуратора показывает те же позиции (тип и количество), что были на момент добавления

### Requirement: Живая синхронизация конфигурации, открытой из корзины
Пока конфигуратор находится в режиме редактирования позиции корзины (открыт по «Посмотреть», см. выше), любое изменение конфигурации (тип полотна, коллекция, полотно и его опции, кромка, короб, наличник, добор, декоративные элементы, фурнитура, реверс, четверть) ДОЛЖНО (SHALL) автоматически, без дополнительного действия пользователя и без обращения к backend, обновлять эту же позицию корзины — её наименование, параметры, данные для выгрузки, снимок цены и построчную детализацию (см. «Хранение корзины в localStorage»); количество позиции синхронизация не трогает. Пока действует режим редактирования, кнопка «Добавить в корзину» (см. door-configurator-ui) ДОЛЖНА (SHALL) быть недоступна для нажатия — новую отдельную позицию в этом режиме создать нельзя, изменения и так сохраняются в открытую. Режим редактирования ДОЛЖЕН (SHALL) заканчиваться нажатием кнопки «Очистить» (см. door-configurator-ui, «Кнопка «Очистить» в панели результата расчёта») — после него конфигуратор возвращается к обычному режиму «добавить новую позицию», а кнопка «Добавить в корзину» снова становится доступна. Если открытая позиция удаляется из корзины (действием «Удалить», см. «Удаление позиции из корзины») до завершения редактирования, режим редактирования ДОЛЖЕН (SHALL) завершиться сам — синхронизировать после этого уже некуда.

#### Scenario: Изменение в конфигураторе сразу обновляет открытую позицию корзины
- **WHEN** пользователь открыл позицию корзины через «Посмотреть» и меняет в конфигураторе цвет полотна (или любую другую опцию)
- **THEN** без дополнительных действий пользователя эта же позиция корзины (наименование, параметры, снимок цены, детализация) обновляется в соответствии с новым выбором, а количество позиции остаётся прежним

#### Scenario: Кнопка «Добавить в корзину» недоступна в режиме редактирования
- **WHEN** конфигуратор находится в режиме редактирования позиции, открытой через «Посмотреть»
- **THEN** кнопка «Добавить в корзину» недоступна для нажатия

#### Scenario: «Очистить» завершает режим редактирования
- **WHEN** пользователь, находясь в режиме редактирования позиции корзины, нажимает «Очистить»
- **THEN** конфигуратор возвращается к обычному режиму «добавить новую позицию» (форма пуста, как при обычном «Очистить»), кнопка «Добавить в корзину» становится доступна снова, а дальнейшие изменения конфигурации больше не отражаются в ранее открытой позиции

#### Scenario: Удаление открытой позиции завершает режим редактирования
- **WHEN** пользователь, находясь в режиме редактирования позиции корзины, удаляет именно эту позицию из корзины (например, вернувшись на экран корзины и нажав «Удалить»)
- **THEN** режим редактирования завершается, кнопка «Добавить в корзину» становится доступна — следующее нажатие «Добавить в корзину» создаст новую отдельную позицию из текущего состояния конфигуратора

#### Scenario: Изменение декоративных элементов сразу обновляет открытую позицию корзины
- **WHEN** пользователь открыл позицию корзины через «Посмотреть» и добавляет, удаляет или меняет количество позиции декоративного элемента в конфигураторе
- **THEN** без дополнительных действий пользователя эта же позиция корзины обновляется — её снимок цены и построчная детализация отражают актуальный список декоративных элементов

### Requirement: Разворачиваемая детализация позиции корзины
Под каждой строкой позиции таблица ДОЛЖНА (SHALL) всегда показывать, на всю ширину таблицы, полосу с текстом «Детализация конфигурации» и иконкой-шевроном — отдельно от действий «Посмотреть»/«Удалить» (см. «Кнопка «Посмотреть» открывает конфигурацию в конфигураторе», «Удаление позиции из корзины») и не заменяющий их. Клик по этой полосе (или по иконке) ДОЛЖЕН (SHALL) показывать под ней вложенную таблицу детализации состава позиции по компонентам со столбцами: «Элемент» (тип компонента — Полотно/Кромка/Короб/Наличник/Добор/Декоративные элементы/Фурнитура), «Наименование» (конкретная модель/позиция), «Размеры», «Цвет», «Кол-во», «Цена дилер», «Цена клиенту», «Сумма дилер», «Сумма клиенту» — цена «за единицу» и «сумма» совпадают для строк с количеством 1. Компонент «Короб» ДОЛЖЕН (SHALL) показываться ровно одной строкой на весь короб — его позиции состава (frame_post, см. door-configurator-ui, «Отображение позиций короба») в эту детализацию отдельными строками НЕ ДОЛЖНЫ (SHALL NOT) выводиться: цена строки «Короб» уже включает их сумму целиком (см. door-configuration-api, «Стоимость короба как сумма цен его стоек»), поэтому дублирование не требуется — состав короба по-прежнему виден в самом конфигураторе. Каждая позиция декоративного элемента ДОЛЖНА (SHALL) показываться отдельной строкой «Декоративные элементы» (без объединения одинаковых типов, тем же принципом, что и позиции фурнитуры), со столбцом «Размеры», содержащим длину типа в мм, и пустым столбцом «Цвет» (у decorative_element_type нет цвета). Данные строятся на фронтенде в момент добавления позиции в корзину из тех же каталожных и выбранных данных, что использует сам конфигуратор (см. «Хранение корзины в localStorage»), без нового обращения к backend при разворачивании/сворачивании. Повторный клик по полосе уже развёрнутой позиции ДОЛЖЕН (SHALL) сворачивать вложенную таблицу обратно (полоса и её текст с иконкой остаются на месте — сворачивается только таблица под ней). Детализация показывает данные ровно для одной единицы изделия — не умножается на количество позиции.

#### Scenario: Полоса «Детализация конфигурации» видна под каждой строкой
- **WHEN** в корзине есть хотя бы одна позиция
- **THEN** под строкой этой позиции, на всю ширину таблицы, видна полоса с текстом «Детализация конфигурации» и иконкой-шевроном, независимо от того, развёрнута детализация или нет

#### Scenario: Клик по полосе показывает вложенную таблицу детализации
- **WHEN** пользователь кликает по полосе «Детализация конфигурации» (или по её иконке) у позиции корзины
- **THEN** под этой полосой появляется вложенная таблица с построчной детализацией по каждому компоненту конфигурации (полотно, кромка, короб, наличник, добор, декоративные элементы, фурнитура — какие из них присутствуют в этой конфигурации), с наименованием, размерами, цветом, количеством и ценами за одну единицу; иконка меняется на противоположную (стрелка вверх)

#### Scenario: Позиции декоративных элементов показаны отдельными строками
- **WHEN** позиция корзины содержит две позиции декоративных элементов с разными типами
- **THEN** детализация показывает две отдельные строки «Декоративные элементы» — по одной на каждую позицию, каждая со своим наименованием, длиной в столбце «Размеры», количеством и ценой/суммой

#### Scenario: Состав короба не дублируется отдельными строками
- **WHEN** конфигурация содержит короб, чей список позиций frame_post из каталога содержит несколько записей (например, незарезную стойку и комплект зарезных стоек)
- **THEN** в детализации позиции короб показан ровно одной строкой «Короб» с суммарной ценой; отдельных строк на каждую позицию его состава нет

#### Scenario: Повторный клик сворачивает детализацию
- **WHEN** детализация позиции уже развёрнута, и пользователь снова кликает по полосе «Детализация конфигурации»
- **THEN** вложенная таблица детализации скрывается, а сама полоса с текстом и иконкой (уже в исходном положении) остаётся видна

#### Scenario: Позиция без сохранённой детализации показывает пояснение вместо пустой таблицы
- **WHEN** у позиции корзины нет построчной детализации (например, она была добавлена в корзину до появления этого поля хранения) и пользователь разворачивает полосу «Детализация конфигурации»
- **THEN** вместо пустой таблицы показано пояснение, что детализация недоступна для этой позиции, и что нужно добавить конфигурацию в корзину заново
