## MODIFIED Requirements

### Requirement: Расчёт стоимости короба, наличника и добора по типу короба
Система ДОЛЖНА (SHALL) предоставлять эндпоинт расчёта стоимости, принимающий id существующего `frame_type` и набор выбранных клиентом опций короба: id `colour_option`. Эндпоинт МОЖЕТ (MAY) дополнительно принимать id типа наличника (`door_casing_type`) с его опциями (id `liner_dimension_option` для длины, количество) и id типа добора (`frame_extensions_type`) с его опциями (id `liner_dimension_option` для длины, количество) — по тем же правилам, что и при расчёте по `door_configuration`. Полотно, кромка, фурнитура и декоративные элементы эндпоинтом не рассматриваются, даже если присутствуют в запросе.

Указанный id `door_casing_type` ДОЛЖЕН (SHALL) ссылаться на тип наличника, для которого существует хотя бы одна строка `door_configuration` с этим `frame_type` и этим `door_casing_type`; иначе — ошибка 400. Аналогично, указанный id `frame_extensions_type` ДОЛЖЕН (SHALL) ссылаться на тип добора, для которого существует хотя бы одна строка `door_configuration` с этим `frame_type` и этим `frame_extensions_type`; иначе — ошибка 400.

#### Scenario: Расчёт стоимости короба без наличника и добора
- **WHEN** отправляется запрос расчёта с id существующего `frame_type` без указанных типов наличника и добора
- **THEN** эндпоинт возвращает результат с найденной (если есть подходящая строка `configuration_price` и/или позиции `frame_post`) или не найденной ценой короба, без ошибки, и без записей о наличнике/доборе в разбивке

#### Scenario: Несуществующий тип короба
- **WHEN** отправляется запрос расчёта с id `frame_type`, которого не существует
- **THEN** эндпоинт отвечает ошибкой 404 и не выполняет расчёт

#### Scenario: Опция короба не принадлежит указанному типу короба
- **WHEN** в запросе id выбранной `colour_option` ссылается на компонент, отличный от указанного `frame_type`
- **THEN** эндпоинт отвечает ошибкой 400 и не выполняет расчёт

#### Scenario: Наличник и добор принимаются и считаются вместе с коробом
- **WHEN** в запросе указаны id типа наличника и/или id типа добора, для которых существует door_configuration с этим frame_type, и их опции
- **THEN** запрос обрабатывается без ошибки валидации формата запроса, наличник и/или добор учитываются в расчёте по тем же правилам, что и при расчёте по door_configuration (включая количество)

#### Scenario: Наличник, недопустимый для указанного короба, отклоняется
- **WHEN** указанный id типа наличника существует, но не существует ни одной строки door_configuration с этим frame_type и этим door_casing_type
- **THEN** эндпоинт отвечает ошибкой 400 и не выполняет расчёт

#### Scenario: Добор, недопустимый для указанного короба, отклоняется
- **WHEN** указанный id типа добора существует, но не существует ни одной строки door_configuration с этим frame_type и этим frame_extensions_type
- **THEN** эндпоинт отвечает ошибкой 400 и не выполняет расчёт

#### Scenario: Несуществующий тип наличника или добора недопустим
- **WHEN** указанный id типа наличника или добора не существует ни в одной строке соответствующего справочника
- **THEN** эндпоинт отвечает ошибкой 400 и не выполняет расчёт

#### Scenario: Декоративные элементы в запросе игнорируются
- **WHEN** в запросе присутствует список позиций декоративных элементов
- **THEN** эндпоинт игнорирует его — в разбивке результата нет записей о декоративных элементах, а итоговая сумма их не включает
