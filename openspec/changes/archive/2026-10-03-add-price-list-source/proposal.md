## Why

Каталог пополняется из разных файлов прайс-листов (сейчас — `hausdoors_emal_i_shpon_rf_07_09_2026`), и в новом файле будет не пересекающаяся с текущей фурнитура. Источник данных нигде не хранится: название прайс-листа захардкожено на фронтенде (`PRICE_LIST_LABEL` в `App.tsx`), а в БД и API его нет. Нужно хранить источник в БД, связать его с коллекциями дверей и фурнитурой, отдавать через API и показывать в шапке сервиса.

## What Changes

- Новая таблица-справочник `price_list` (источник): код (`PL-001`) и название — имя файла прайса, например `hausdoors_emal_i_shpon_rf_07_09_2026`. Начальная запись — этот файл.
- Связь с дверями: `collection.price_list_id` (обязательное). Источник модели полотна и конфигурации определяется через её коллекцию. Все 9 существующих коллекций получают `PL-001`.
- Связь с фурнитурой: `hardware_type.price_list_id` (обязательное, на уровне типа фурнитуры, а не категории или цветового варианта). Все существующие типы фурнитуры получают `PL-001`.
- Принцип «один сервис = один источник»: все коллекции одного сервиса принадлежат одному прайс-листу; сервис в БД не заводится.
- API: каталог конфигураций дверей отдаёт источник у leaf-компонента (по его коллекции); каталог фурнитуры отдаёт источник у каждого типа фурнитуры.
- Frontend: подпись «Прайс-лист: …» в шапке сервиса «Эмаль и шпон» берётся из API, а не из константы; та же логика используется для новых сервисов. В корзину и экспорт заказа источник не выводится.
- Миграция переносимая (PostgreSQL и H2), без триггеров (см. `CLAUDE.md`).

## Capabilities

### New Capabilities
- `price-list-catalog`: справочник прайс-листов (источников) и его обязательные связи с коллекциями дверей и типами фурнитуры.

### Modified Capabilities
- `door-configuration-api`: каталог конфигураций отдаёт источник у leaf-компонента.
- `hardware-catalog`: каталог фурнитуры отдаёт источник у каждого типа.
- `door-configurator-ui`: подпись прайс-листа в шапке берётся из каталога, а не из константы.

## Impact

- Backend: Liquibase changeset (таблица, колонки, начальные данные, внешние ключи), сущность `PriceList`, поле в `LeafCollection` и `HardwareType`, DTO (`ComponentCatalogDto`, `HardwareTypeDto`), сервисы каталога, тесты контроллеров.
- Frontend: тип в `api/types.ts`, шапка в `App.tsx` (замена `PRICE_LIST_LABEL`), актуализация комментария в `CartScreen.tsx`.
- API: обратно-совместимое добавление полей. Корзина, экспорт заказа и расчёт цены не меняются.
- Вне scope: декоративные элементы (`decorative_element_*`) остаются без источника.
