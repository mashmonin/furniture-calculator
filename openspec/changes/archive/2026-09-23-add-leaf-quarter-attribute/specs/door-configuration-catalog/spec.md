## REMOVED Requirements

### Requirement: Соответствие вида кромки и признака реверса
**Reason**: Четверть по периметру полотна — самостоятельная конструктивная опция, независимая от направления открывания (полотно может быть с четвертью или без неё при любом `is_reverse`, например для лучшей шумоизоляции). Жёсткая привязка вида кромки к `is_reverse` заменена соответствием кромки новому атрибуту «Четверть» (`has_quarter`), не зависящему от `is_reverse`.
**Migration**: См. новое требование «Соответствие вида кромки и атрибута «Четверть»». `is_reverse` больше не определяет и не ограничивает допустимый вид кромки строки `door_configuration`.

## ADDED Requirements

### Requirement: Атрибут «Четверть» у door_configuration
Door_configuration ДОЛЖЕН (SHALL) иметь обязательный булев атрибут «Четверть» (`has_quarter`), независимый от `is_reverse`, — является ли исполнение полотна этой конфигурации с четвертью по периметру. Значение атрибута не выводится из других полей строки (в отличие от прежнего соответствия кромки и `is_reverse`) и хранится явно.

#### Scenario: Атрибут обязателен
- **WHEN** строка `door_configuration` вставляется без значения атрибута «Четверть»
- **THEN** база данных отклоняет вставку

#### Scenario: Значение независимо от is_reverse
- **WHEN** существуют строки `door_configuration` с одинаковым значением `is_reverse`, но разными значениями атрибута «Четверть»
- **THEN** обе строки успешно сохраняются — атрибут «Четверть» не определяется и не ограничивается значением `is_reverse`

### Requirement: Заполнение атрибута «Четверть» для существующих конфигураций
Толщина полотна и четверть по периметру — независимые друг от друга опции (см. proposal.md, «Why»); наличие у модели каталожной опции толщины 59 мм (см. «Опция толщины полотна 59 мм по коллекциям») САМО ПО СЕБЕ НЕ ДОЛЖНО (SHALL NOT) ограничивать значение атрибута «Четверть» — единственное, что должно жёстко требовать четверть, это реверсивное открывание.

Для всех строк `door_configuration`, существовавших на момент введения атрибута «Четверть», значение ДОЛЖНО (SHALL) быть заполнено по следующим правилам: (1) строки с `is_reverse = true` получают «Четверть» = true; (2) строки с `is_reverse = false` получают «Четверть» = false, и для каждой такой строки ДОЛЖНА (SHALL) дополнительно существовать в каталоге её копия с тем же `leaf_type`, `frame_type`, `door_casing_type`, `frame_extensions_type` и `is_reverse = false`, но с «Четверть» = true — так, чтобы для ЛЮБОЙ модели полотна при обычном (не реверсивном) открывании в каталоге были доступны оба исполнения: с четвертью и без, независимо от того, доступна ли для этой модели опция толщины 59 мм. Строки с `is_reverse = true` не копируются — альтернатива «без четверти» для реверсивного открывания не предусмотрена.

#### Scenario: Реверсивная конфигурация помечена как с четвертью
- **WHEN** запрашивается ранее существовавшая строка `door_configuration` с `is_reverse = true`
- **THEN** её атрибут «Четверть» равен true

#### Scenario: Модель с толщиной 59 мм при обычном открывании доступна в обоих исполнениях
- **WHEN** запрашивается ранее существовавшая строка `door_configuration` с `is_reverse = false`, чей `leaf_type` имеет каталожную опцию толщины 59 мм
- **THEN** эта строка имеет атрибут «Четверть» = false, и в каталоге дополнительно существует её копия с тем же `leaf_type`/`frame_type`/`door_casing_type`/`frame_extensions_type`/`is_reverse = false`, но с атрибутом «Четверть» = true — наличие опции толщины 59 мм не лишает эту модель варианта «без четверти»

#### Scenario: Модель без опции толщины 59 мм при обычном открывании доступна в обоих исполнениях
- **WHEN** запрашивается ранее существовавшая строка `door_configuration` с `is_reverse = false`, чей `leaf_type` не имеет опции толщины 59 мм
- **THEN** эта строка имеет атрибут «Четверть» = false, и в каталоге дополнительно существует её копия с тем же `leaf_type`/`frame_type`/`door_casing_type`/`frame_extensions_type`/`is_reverse = false`, но с атрибутом «Четверть» = true

#### Scenario: Реверсивная конфигурация не получает копию без четверти
- **WHEN** запрашивается каталог конфигураций
- **THEN** среди строк, ранее существовавших с `is_reverse = true`, нет ни одной копии с атрибутом «Четверть» = false

### Requirement: Соответствие вида кромки и атрибута «Четверть»
Строка `door_configuration`, ссылающаяся на edge_type «ПРЯМАЯ КРОМКА ПО ПЕРИМЕТРУ ПОЛОТНА» (код `ET-001`), ДОЛЖНА (SHALL) иметь атрибут «Четверть» = false. Строка `door_configuration`, ссылающаяся на edge_type «КРОМКА ДЛЯ ПОЛОТНА С ЧЕТВЕРТЬЮ ПО ПЕРИМЕТРУ» (код `ET-002`), ДОЛЖНА (SHALL) иметь атрибут «Четверть» = true. Правило применяется только к строкам, где кромка участвует (edge_type задан); строки без кромки (edge_type отсутствует) этим правилом не ограничиваются — атрибут «Четверть» для них задаётся правилами заполнения (см. «Заполнение атрибута «Четверть» для существующих конфигураций»), а сама кромка для такой строки остаётся неприменимой, как и раньше.

#### Scenario: Прямая кромка доступна только конфигурациям без четверти
- **WHEN** запрашивается каталог конфигураций
- **THEN** среди `door_configuration` с edge_type «ПРЯМАЯ КРОМКА ПО ПЕРИМЕТРУ ПОЛОТНА» нет ни одной строки с атрибутом «Четверть» = true

#### Scenario: Кромка с четвертью доступна только конфигурациям с четвертью
- **WHEN** запрашивается каталог конфигураций
- **THEN** среди `door_configuration` с edge_type «КРОМКА ДЛЯ ПОЛОТНА С ЧЕТВЕРТЬЮ ПО ПЕРИМЕТРУ» нет ни одной строки с атрибутом «Четверть» = false

#### Scenario: Реверсивная конфигурация может иметь прямую кромку
- **WHEN** запрашивается каталог конфигураций и среди `door_configuration` есть строка с `is_reverse = true` и атрибутом «Четверть» = false
- **THEN** эта строка МОЖЕТ (MAY) ссылаться на edge_type «ПРЯМАЯ КРОМКА ПО ПЕРИМЕТРУ ПОЛОТНА» — `is_reverse` не ограничивает выбор кромки

#### Scenario: Обычная (не реверсивная) конфигурация может иметь кромку с четвертью
- **WHEN** запрашивается каталог конфигураций и среди `door_configuration` есть строка с `is_reverse = false` и атрибутом «Четверть» = true
- **THEN** эта строка МОЖЕТ (MAY) ссылаться на edge_type «КРОМКА ДЛЯ ПОЛОТНА С ЧЕТВЕРТЬЮ ПО ПЕРИМЕТРУ» — `is_reverse` не ограничивает выбор кромки

#### Scenario: Строка без кромки не ограничена правилом
- **WHEN** строка `door_configuration` не ссылается ни на один edge_type
- **THEN** правило соответствия кромки и атрибута «Четверть» к этой строке не применяется

### Requirement: Исключение короба «Нео» для моделей с толщиной 59 мм при исполнении «с четвертью»
Короб «Нео» (frame_type код `FT-003`) конструктивно несовместим с исполнением «с четвертью» — не с самой толщиной 59 мм как таковой (правка после проверки на фронтенде: см. proposal.md). Для leaf_type, имеющих каталожную опцию толщины 59 мм (см. «Опция толщины полотна 59 мм по коллекциям»), НЕ ДОЛЖНО (SHALL NOT) существовать ни одной строки `door_configuration`, ссылающейся на frame_type «НЕО» с атрибутом «Четверть» = true. Для строк с атрибутом «Четверть» = false короб «Нео» ДОЛЖЕН (SHALL) оставаться доступным на тех же условиях (сочетания с наличником, добором и кромкой), что и для leaf_type без опции толщины 59 мм.

#### Scenario: Короб «Нео» недоступен для модели с толщиной 59 мм при «Четверть» = true
- **WHEN** запрашивается каталог конфигураций для leaf_type, имеющего опцию толщины 59 мм
- **THEN** среди его door_configuration с атрибутом «Четверть» = true нет ни одной строки, ссылающейся на frame_type «НЕО»

#### Scenario: Короб «Нео» доступен для модели с толщиной 59 мм при «Четверть» = false
- **WHEN** запрашивается каталог конфигураций для leaf_type, имеющего опцию толщины 59 мм
- **THEN** среди его door_configuration с атрибутом «Четверть» = false есть строки, ссылающиеся на frame_type «НЕО», в тех же сочетаниях с наличником и добором, что и у leaf_type без опции толщины 59 мм

#### Scenario: Короб «Нео» остаётся доступен для прочих моделей
- **WHEN** запрашивается каталог конфигураций для leaf_type без опции толщины 59 мм, для которого ранее существовали строки с коробом «Нео»
- **THEN** эти строки остаются в каталоге без изменений, независимо от атрибута «Четверть»
