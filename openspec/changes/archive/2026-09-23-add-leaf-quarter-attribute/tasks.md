## 7. Синхронизация переключателей «Реверс» и «Четверть» (по обратной связи: «нажал на свитч реверс и свитч четверть пропал»)

`resolveHasQuarterStep` оценивался по `reverseFilteredConfigurations` (уже суженному текущим «Реверс») — при включённом «Реверс» среди суженного набора остаётся только `has_quarter=true` (альтернативы для реверса не существует), поэтому переключатель пропадал. По желанию пользователя — «Четверть» должна оставаться видимой и активной всегда; конфликт разрешается автоматическим переключением, а не скрытием.

- [x] 7.1 `resolveHasQuarterStep` теперь вызывается на полном `configurations` (как и `resolveReverseStep`), а не на `reverseFilteredConfigurations` — оба переключателя оцениваются как независимые сиблинги. Согласованный набор для последующих шагов (`hasQuarterFilteredConfigurations`) теперь фильтруется одним выражением по обоим значениям одновременно (`configuration.reverse === resolvedReverse && configuration.hasQuarter === resolvedHasQuarter`), а не последовательно через промежуточную переменную.
- [x] 7.2 `handleReverseChange(true)` дополнительно вызывает `setHasQuarterSelection(true)` — включение «Реверс» принудительно включает «Четверть» (комбинация «Реверс»=true + «Четверть»=false не существует в каталоге).
- [x] 7.3 `handleHasQuarterChange(false)` дополнительно вызывает `setReverseSelection(false)`, когда `resolvedReverse === true` — выключение «Четверть» при включённом «Реверс» принудительно выключает и «Реверс», по той же причине. Обратные направления (выключение «Реверс», включение «Четверть») ничего принудительно не меняют.
- [x] 7.4 Обновлены specs (`door-configurator-ui`, требование «Переключатель «Четверть» в каскаде») и design.md — новые сценарии синхронизации, убран сценарий «переключатель скрыт из-за суженного реверсом набора» (сценарий «скрыт» остаётся только для случая, когда во ВСЁМ каталоге есть только одно значение «Четверть»).
- [x] 7.5 `npm run lint`/`npm run build` — без ошибок. Визуально в браузере не проверено (нет инструмента в этой среде, как и ранее) — проверено по коду (симметрия с уже работающим `resolveReverseStep`/`handleReverseChange`).
