## Why

Сейчас цена наличника (doorCasing) и добора (frameExtensions) в расчёте стоимости всегда считается как за одну единицу — `configuration_price`, найденная по длине/высоте/толщине/цвету, добавляется к сумме ровно один раз, независимо от того, сколько физически наличников или доборов нужно на конкретную дверь (например, при широком проёме или двусторонней облицовке требуется несколько штук). Сейчас нет способа передать количество — расчёт всегда предполагает «один», и менеджеру приходится досчитывать нужное количество вручную вне калькулятора.

## What Changes

- Для компонентов «Наличник» (doorCasing) и «Добор» (frameExtensions) добавить в запрос расчёта стоимости необязательное поле «количество» (целое число, по умолчанию 1, если не передано — сохраняет текущее поведение). Указание количества для любого другого компонента (leaf, frame, edge) ДОЛЖНО (SHALL) отклоняться ошибкой 400, по аналогии с тем, как уже отклоняется `customLengthValueMm`/`customHeightValueMm` для компонентов, отличных от leaf.
- Итоговая retail/dealer цена наличника и добора в ответе расчёта стоимости ДОЛЖНА (SHALL) равняться найденной цене `configuration_price`, умноженной на указанное количество (округление не требуется — оба множителя целые). Базовая цена компонента (см. change `redesign-door-configurator-flow`) также включает количество — для наличника/добора она всегда равна итоговой (на них не действуют надбавки за размер/реверс, как и раньше).
- Количество ДОЛЖНО (SHALL) быть положительным целым числом; ноль, отрицательное или нецелое значение — ошибка 400.
- Frontend: рядом с группами опций наличника и добора (в той же карточке компонента, сразу после выбора его типа — см. единый поток из change `redesign-door-configurator-flow`) добавить числовое поле «Количество» (antd `InputNumber`, минимум 1, по умолчанию 1), значение которого передаётся в запрос расчёта стоимости.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `door-configuration-api`: запрос расчёта стоимости принимает необязательное количество для наличника/добора; цена этих компонентов умножается на количество.
- `door-configurator-ui`: у наличника и добора появляется числовое поле «Количество» рядом с остальными их опциями.

## Impact

- **Backend**: `ComponentSelectionDto` — новое поле `quantity`; `DoorConfigurationPricingService` — валидация (quantity только для doorCasing/frameExtensions, положительное целое) и умножение найденной цены на количество для этих двух компонентов.
- **Frontend**: `App.tsx` — числовое поле «Количество» для наличника/добора, по умолчанию 1; `api/types.ts` — новое поле в `ComponentSelectionDto`.
- Область действия — только наличник и добор; полотно, кромка и короб не затрагиваются (у короба уже есть собственный список позиций `frame_post` с количеством на уровне каталога — не пересекается с этим change).
