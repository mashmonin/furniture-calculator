## ADDED Requirements

### Requirement: Количество наличника и добора в расчёте стоимости
Для компонентов doorCasing (наличник) и frameExtensions (добор) запрос расчёта стоимости МОЖЕТ (MAY) указывать количество — положительное целое число. Если количество не указано, система ДОЛЖНА (SHALL) считать его равным 1 (текущее поведение сохраняется). Если найдена подходящая строка configuration_price для этого компонента, итоговая retail_price и dealer_price ДОЛЖНЫ (SHALL) равняться цене этой строки, умноженной на указанное количество; базовая цена компонента (см. «Базовая цена компонента в ответе расчёта стоимости») равна той же величине — для этих компонентов надбавки за размер/реверс никогда не применяются. Указание количества для компонента, отличного от doorCasing и frameExtensions, ДОЛЖНО (SHALL) отклоняться ошибкой 400. Указанное количество ДОЛЖНО (SHALL) быть положительным целым числом; ноль, отрицательное значение отклоняются ошибкой 400.

#### Scenario: Количество не указано — цена как за одну единицу
- **WHEN** отправляется запрос расчёта стоимости для наличника или добора без указания количества
- **THEN** цена этого компонента равна найденной цене configuration_price без изменений, как и до появления этого требования

#### Scenario: Указанное количество умножает цену компонента
- **WHEN** отправляется запрос расчёта стоимости, где для наличника или добора указано количество N и найдена подходящая строка configuration_price
- **THEN** итоговая retail_price и dealer_price этого компонента равны retail_price/dealer_price найденной строки, умноженным на N

#### Scenario: Количество для компонента, отличного от наличника и добора, недопустимо
- **WHEN** отправляется запрос расчёта стоимости, где количество указано для leaf, frame или edge
- **THEN** эндпоинт отвечает ошибкой 400 и не выполняет расчёт

#### Scenario: Нулевое или отрицательное количество недопустимо
- **WHEN** отправляется запрос расчёта стоимости, где для наличника или добора указано количество, равное нулю или отрицательное
- **THEN** эндпоинт отвечает ошибкой 400 и не выполняет расчёт

#### Scenario: Количество не влияет на компонент без найденной цены
- **WHEN** отправляется запрос расчёта стоимости, где для наличника или добора указано количество, но подходящая строка configuration_price не найдена
- **THEN** компонент считается некалькулируемым, как и без указания количества
