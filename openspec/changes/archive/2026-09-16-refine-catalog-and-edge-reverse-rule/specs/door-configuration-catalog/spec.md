## ADDED Requirements

### Requirement: Соответствие вида кромки и признака реверса
Строка `door_configuration`, ссылающаяся на edge_type «ПРЯМАЯ КРОМКА ПО ПЕРИМЕТРУ ПОЛОТНА» (код `ET-001`), ДОЛЖНА (SHALL) иметь `is_reverse = false`. Строка `door_configuration`, ссылающаяся на edge_type «КРОМКА ДЛЯ ПОЛОТНА С ЧЕТВЕРТЬЮ ПО ПЕРИМЕТРУ» (код `ET-002`), ДОЛЖНА (SHALL) иметь `is_reverse = true`. Комбинации, нарушающие это соответствие (прямая кромка при `is_reverse = true`, кромка с четвертью при `is_reverse = false`), из каталога удалены; соответствие обеспечивается на уровне данных (Liquibase-миграциями), а не отдельным ограничением схемы БД — как и прочие комбинаторные правила этого каталога.

#### Scenario: Прямая кромка доступна только для обычных конфигураций
- **WHEN** запрашивается каталог конфигураций
- **THEN** среди `door_configuration` с edge_type «ПРЯМАЯ КРОМКА ПО ПЕРИМЕТРУ ПОЛОТНА» нет ни одной строки с `is_reverse = true`

#### Scenario: Кромка с четвертью доступна только для реверсивных конфигураций
- **WHEN** запрашивается каталог конфигураций
- **THEN** среди `door_configuration` с edge_type «КРОМКА ДЛЯ ПОЛОТНА С ЧЕТВЕРТЬЮ ПО ПЕРИМЕТРУ» нет ни одной строки с `is_reverse = false`

#### Scenario: Прочие компоненты строки остаются доступны с допустимой для неё кромкой
- **WHEN** для пары leaf_type + frame_type до этого изменения существовали строки `door_configuration` с обоими видами кромки для обоих значений `is_reverse`
- **THEN** после изменения для каждого значения `is_reverse` остаётся ровно один совместимый с ним вид кромки, а прочие компоненты (короб, наличник, добор) этой строки не затронуты
