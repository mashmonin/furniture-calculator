## ADDED Requirements

### Requirement: Допустимость нестандартных размеров в каталоге и расчёте
Для leaf-компонента каждой door_configuration в ответе каталога конфигураций система ДОЛЖНА (SHALL) включать признак допустимости нестандартных размеров его коллекции (`customDimensionsAllowed`); для остальных компонентов поле НЕ ДОЛЖНО (SHALL NOT) заполняться (null/отсутствует). Если у коллекции полотна признак равен `false`, а в запросе расчёта стоимости для leaf указано произвольное значение длины (`customLengthValueMm`) или высоты (`customHeightValueMm`), система ДОЛЖНА (SHALL) отклонить запрос как недопустимый (код 400) до любых проверок диапазона и поиска наценки; расчёт со стандартными каталожными опциями (`lengthOptionId`/`heightOptionId`) выполняется как обычно.

#### Scenario: Каталог отдаёт признак у leaf-компонента
- **WHEN** запрашивается каталог конфигураций
- **THEN** у leaf-компонента модели MONO MN 01 `customDimensionsAllowed` равен `false`, у модели существующей коллекции — `true`, а у frame, edge, doorCasing и frameExtensions поле не заполнено

#### Scenario: Произвольная ширина у полотна «Эмаль Лайт» отклоняется
- **WHEN** отправляется запрос расчёта стоимости для MONO MN 01 с произвольным значением длины 650 мм
- **THEN** эндпоинт отвечает кодом 400

#### Scenario: Произвольная высота у полотна «Эмаль Лайт» отклоняется
- **WHEN** отправляется запрос расчёта стоимости для QUADRO QU 01 с произвольным значением высоты 2150 мм
- **THEN** эндпоинт отвечает кодом 400

#### Scenario: Стандартные размеры у полотна «Эмаль Лайт» считаются
- **WHEN** отправляется запрос расчёта стоимости для MONO MN 01 с каталожными опциями длины 700 и высоты 2000
- **THEN** расчёт выполняется, цена соответствует прайсу

#### Scenario: Существующие коллекции принимают нестандартные размеры
- **WHEN** отправляется запрос расчёта стоимости для полотна коллекции с признаком `true` с допустимым произвольным значением в пределах диапазона
- **THEN** запрос обрабатывается как прежде
