## Context

Источник данных уже хранится в `price_list` (`PL-001`), коллекции привязаны к нему через `collection.price_list_id`; каталог `GET /api/door-configurations` отдаёт `leaf.priceList` у каждой конфигурации (см. archive `add-price-list-source`). Каталог строится из `door_configuration`; конфигурации «только полотно» уже существуют (132 строки). Цена полотна сейчас — одна строка `configuration_price` на `leaf_type` (для всех 45 существующих), но механизм подбора цены допускает строки с `length_option_id` и `height_option_id` (выбирается наиболее специфичная, см. `door-configuration-api`, «Сопоставление наиболее специфичной цены компонента»). Наценка за размер применяется только к произвольным значениям (`customLengthValueMm`/`customHeightValueMm`), а не к стандартным опциям. Таблица `collection_dimension_range` по умолчанию не заполняется для новых коллекций. Максимальные коды сейчас: `LC-009`, `LT-045`. Цены в прайсе: первая цифра — дилерская, вторая — розничная.

## Goals / Non-Goals

**Goals:**
- Завести прайс-лист, коллекции, модели, размеры и цены «Эмаль Лайт» точно по прайсу.
- Добавить сервис «Эмаль Лайт» на фронтенде.

**Non-Goals:**
- Цвета, толщина 59 мм, диапазон нестандартных размеров и наценки за них для новых коллекций (нестандартные размеры у них запрещены).
- Короб, наличник, добор, кромка, реверс, четверть для новых моделей.
- Таблица сервисов в БД.

## Decisions

1. **Явные цены по размерам, без наценок.** Ширины 400/600/700/800/900 и высоты 2000/2100/2200/2300 заводятся как стандартные опции `liner_dimension_option` (`DT-001`, `DT-002`) каждой новой модели. На каждую пару «ширина × высота» — своя строка `configuration_price` (`leaf_type_id`, `length_option_id`, `height_option_id`): 5 × 4 = 20 на модель, 120 всего. Значения берутся из четырёх классов прайса. Это точно до рубля. Альтернатива «базовая цена + проценты» отвергнута: дробные проценты (10,02 %, 10,87 % …) и округление дают расхождения с прайсом. Существующие общие правила наценки (900 → +10 %, 2200/2300 → +20 % и т. д.) не затрагиваются и к стандартным опциям не применяются.
1a. **Подбор цены полотна учитывает опцию высоты.** Сервис расчёта сейчас обнуляет опцию высоты для полотна (`heightOption = null` для `LeafType`), поэтому строки цены с `height_option_id` не находились. Опция высоты передаётся в подбор цены и для полотна — это соответствует требованию «Сопоставление наиболее специфичной цены компонента» и не влияет на существующие цены полотна (они высоту не указывают). Опция остаётся `null` в `ResolvedComponent`, чтобы не менять выгрузку спецификации.
2. **Классы цен.**
   - MONO MN 01 (дилер/розница, ₽): ширина 400–800: 2000 мм — 10 764/17 761, 2100–2300 — 11 934/19 691; ширина 900: 2000 — 11 843/19 541, 2100–2300 — 13 130/21 665.
   - QUADRO QU 01/02, VENEZIA VN 01/02, REFLEX RF 01 (одинаковые цены): ширина 400–800: 2000 — 11 349/18 726, 2100–2300 — 12 519/20 656; ширина 900: 2000 — 12 493/20 613, 2100–2300 — 13 780/22 737.
2a. **Только стандартные размеры — явный признак коллекции.** Колонка `collection.custom_dimensions_allowed BOOLEAN NOT NULL DEFAULT true`; у `LC-010…LC-013` — `false`. Альтернатива «нет диапазона `collection_dimension_range` = нестандартные значения запрещены» отвергнута: действующие требования прямо говорят, что без диапазона проверка пропускается, а поле «Другое значение» остаётся (то есть пришлось бы менять их семантику). Признак отдаётся в каталоге у leaf-компонента (`customDimensionsAllowed`, у остальных `null`). Расчёт цены отклоняет (400) произвольные значения длины/высоты у полотна коллекции с `false` — до любых проверок диапазона и наценок. Интерфейс не показывает сегмент «Другое» и поле «Нестандартное значение». Когда появится диапазон и наценки для «Эмаль Лайт», признак переключается на `true` отдельным изменением.
2b. **Толщина 44 мм по умолчанию.** Стандартная опция `liner_dimension_option` (`DT-003`, 44, `is_standard = true`) для шести моделей — данными. Цены полотна толщину не указывают, поэтому подходят при любом выборе; наценки у 44 нет (правила наценки заведены только для 59). «По умолчанию» реализуется в интерфейсе, а не в БД: у описания сервиса (`services.ts`) есть значение `defaultThicknessMm` (44 у «Эмаль Лайт», нет у «Эмаль и шпон»); конфигуратор сервиса при выбранной модели автоматически выбирает опцию толщины с этим значением, если толщина ещё не выбрана. Альтернатива — признак «по умолчанию» в БД/API — отвергнута как избыточная (единственный потребитель — этот сервис); у «Эмаль и шпон» поведение не меняется.
3. **Конфигурации «только полотно».** Для каждой модели одна `door_configuration` (`frame/edge/doorCasing/frameExtensions = NULL`, `is_reverse = false`, `has_quarter = false`): без неё модель не попадёт в каталог. Остальные сочетания добавит отдельное изменение.
4. **Коды:** коллекции `LC-010…LC-013`, модели `LT-046…LT-051`, прайс-лист `PL-002`; названия коллекций — латиницей (MONO, QUADRO, VENEZIA, REFLEX), моделей — как в прайсе («MONO MN 01»).
5. **Сервис = конфигурация во фронтенде.** Список сервисов (`ключ`, название меню, код прайс-листа) — константа в приложении; сервис «Эмаль и шпон» → `PL-001`, «Эмаль Лайт» → `PL-002`. Таблица сервисов в БД не заводится. Конфигуратор получает код прайс-листа сервиса и фильтрует загруженные конфигурации по `leaf.priceList.code`; шапка берёт название файла из отфильтрованного каталога.
6. **Кэш каталога.** Каталог (≈8 000 конфигураций) загружается один раз и переиспользуется при переключении сервисов (кэш на уровне `api/doorConfigurations.ts`), чтобы не перезапрашивать его при каждом переходе.
7. **Корзина.** Позиция запоминает свой сервис (`serviceKey`); тег сервиса в корзине берётся по нему; «Открыть в конфигураторе» переключает на сервис позиции. Старые позиции без поля считаются «Эмаль и шпон».

## Risks / Trade-offs

- [Прайс-лист «возможный» — цифры могут измениться] → данные заводятся отдельным changeset'ом; при обновлении прайса меняются новым changeset'ом, как делалось раньше.
- [Конфигуратор может не работать у полотна без цветов и без толщины] → прецедент — «Фантом» (без цветов); проверить расчёт и UI вручную и тестом; при необходимости — отдельный фикс.
- [Нестандартные размеры недоступны] → по требованию пользователя доступны только размеры из прайса; запрет задаёт явный признак коллекции, диапазон и наценки добавятся позже отдельным изменением.
- [Больше сервисов — больше фильтрации на клиенте] → каталог один и тот же, фильтр дешёвый; кэш из п. 6.
- [Позиции корзины, сохранённые до изменения, без `serviceKey`] → считаются «Эмаль и шпон».

## Migration Plan

Один новый Liquibase changeset с данными (INSERT), без изменения схемы; переносим на PostgreSQL и H2 (без триггеров). Откат — удаление добавленных строк в обратном порядке.
