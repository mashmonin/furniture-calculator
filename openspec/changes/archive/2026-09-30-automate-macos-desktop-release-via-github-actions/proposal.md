## Why

Сборка desktop-дистрибутива под macOS (`.dmg`) сейчас доступна только локальным скиллом `macos-arm64-release`, который умеет собрать исключительно arm64-версию и только на Apple Silicon Mac (кросс-сборка невозможна — `jlink`/`jpackage` всегда встраивают JRE архитектуры машины, на которой запущены). Чтобы выпустить обе архитектуры (arm64 и x86_64), нужны две разные физические машины и ручной прогон скилла на каждой. GitHub Actions даёт нативные раннеры обеих архитектур macOS «из коробки» — сборку и публикацию обеих версий можно запускать одной кнопкой, не находясь физически ни на одной из машин.

## What Changes

- Добавляется workflow GitHub Actions с ручным запуском (`workflow_dispatch`), принимающий версию релиза (semver) как параметр.
- По запуску workflow параллельно собирает `.dmg` под arm64 (Apple Silicon) и x86_64 (Intel) на соответствующих нативных macOS-раннерах GitHub, используя уже существующий Gradle-таск `desktopAppImage` (см. `desktop-app-packaging`, backend/build.gradle) — без изменений в самой логике сборки.
- После успешной сборки обеих архитектур workflow публикует GitHub Release с тегом `v<версия>`, к которому прикреплены оба `.dmg`-файла.
- Если релиз с таким тегом уже существует на GitHub, workflow останавливается с ошибкой до начала сборки — защита от повторной/дублирующей публикации той же версии.
- Если сборка хотя бы одной архитектуры падает, релиз не публикуется вообще (ни один файл) — не бывает наполовину опубликованного релиза с всего одной архитектурой.
- Не меняется: локальный скилл `macos-arm64-release` остаётся как есть и работает независимо — это вторая, отдельная возможность собрать релиз, не связанная с этим workflow.
- Windows и Linux — вне рамок этого изменения (см. design.md, Non-Goals); ожидается отдельный change, когда понадобится Windows-сборка.

## Capabilities

### New Capabilities
- `desktop-release-automation`: правила автоматической сборки и публикации desktop-дистрибутивов через CI (GitHub Actions) — запуск, сборка под нужные платформы/архитектуры, публикация в GitHub Releases, защита от дублирования версии и от частичной публикации.

### Modified Capabilities

(нет — существующая `desktop-app-packaging` описывает поведение самого приложения и формат дистрибутива, не то, как и где он публикуется; её требования не меняются)

## Impact

- **Новое**: `.github/workflows/<имя>.yml` — определение workflow.
- **Не затронуто**: `backend/build.gradle` (используется существующий таск `desktopAppImage` как есть, без изменений), локальный скилл `macos-arm64-release`, файл `VERSION` (workflow не коммитит и не читает его — версия передаётся явным параметром запуска, ровно как сейчас пользователь вводит её вручную при использовании скилла).
- **Требует от пользователя**: настроенный GitHub-репозиторий (уже есть) с правами на публикацию Releases для встроенного `GITHUB_TOKEN` (стандартно включено у приватных репозиториев).
