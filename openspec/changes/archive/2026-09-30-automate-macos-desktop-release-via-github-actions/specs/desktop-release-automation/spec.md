## Purpose

Описывает правила автоматической сборки и публикации desktop-дистрибутивов через CI, независимо от локальных скиллов/ручной сборки — какие платформы собираются, куда публикуется результат, и как система защищается от дублирующей или частично опубликованной версии.

## ADDED Requirements

### Requirement: Ручной запуск сборки релиза с версией как параметром
CI SHALL предоставлять запуск сборки релиза вручную (без автоматического триггера на каждый push или тег), принимающий версию релиза (semver, например `1.2.0`) как явный входной параметр запуска. CI не SHALL сам вычислять или изменять версию — источник версии всегда явный ввод пользователя в момент запуска.

#### Scenario: Запуск сборки с указанием версии
- **WHEN** пользователь вручную запускает сборку релиза и указывает версию `1.2.0`
- **THEN** CI собирает дистрибутивы именно под версию `1.2.0`, не выводя и не подставляя версию из какого-либо другого источника (git-тег, файл `VERSION` и т.п.)

### Requirement: Сборка обеих архитектур macOS
По запросу CI SHALL собрать дистрибутив под обе архитектуры процессора macOS — Apple Silicon (arm64) и Intel (x86_64) — каждую на нативном раннере соответствующей архитектуры (кросс-сборка не используется). Обе сборки SHALL выполняться в рамках одного запуска CI.

#### Scenario: Один запуск собирает обе архитектуры
- **WHEN** пользователь запускает сборку релиза
- **THEN** в рамках этого запуска собираются оба дистрибутива — под arm64 и под x86_64 — независимо друг от друга

### Requirement: Публикация только после успеха обеих сборок
CI SHALL публиковать релиз только если сборки под обе архитектуры завершились успешно. Если сборка хотя бы одной архитектуры завершилась с ошибкой, CI не SHALL публиковать релиз вовсе — не SHALL публиковать дистрибутив только одной архитектуры вместо обеих.

#### Scenario: Одна из сборок падает
- **WHEN** сборка под x86_64 завершается ошибкой, а сборка под arm64 — успешно
- **THEN** релиз не публикуется — ни x86_64-, ни arm64-дистрибутив не появляются в списке доступных для скачивания

#### Scenario: Обе сборки успешны
- **WHEN** сборки под обе архитектуры завершаются успешно
- **THEN** релиз публикуется с обоими дистрибутивами, доступными для скачивания

### Requirement: Публикация в GitHub Releases с обоими дистрибутивами
Успешный релиз SHALL публиковаться как GitHub Release с тегом вида `v<версия>`, к которому прикреплены оба собранных `.dmg`-файла — так, чтобы имя каждого файла явно указывало на архитектуру (см. `desktop-app-packaging`, Requirement: Автономная установка без внешних зависимостей).

#### Scenario: Релиз содержит оба файла с различимыми именами
- **WHEN** релиз версии `1.2.0` опубликован
- **THEN** на странице релиза `v1.2.0` доступны для скачивания два файла — один с явным указанием arm64/aarch64 в имени, другой — x86_64, оба соответствуют выбранной версии

### Requirement: Защита от повторной публикации версии
Перед началом сборки CI SHALL проверить, не опубликован ли уже релиз с этим тегом версии. Если релиз с таким тегом уже существует, CI SHALL остановиться с ошибкой до начала сборки, не запуская сборку заново и не изменяя уже опубликованный релиз.

#### Scenario: Попытка повторно собрать уже опубликованную версию
- **WHEN** пользователь запускает сборку релиза с версией, для которой релиз уже опубликован
- **THEN** CI останавливается с ошибкой до начала сборки; уже опубликованный релиз остаётся без изменений
