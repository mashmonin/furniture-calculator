## Context

История механизма зеркала в этом репозитории (см. архив `openspec/changes/archive/`):
1. `add-mirror-finish-leaf-option` — зеркало как независимый булев переключатель «Нужно зеркало», отдельный пред-коллекционный псевдо-шаг наравне с «Реверс».
2. `add-leaf-panel-type` — вводит `panel_type` (глухое/остеклённое/с зеркалом) как чистую классификацию leaf_type, без влияния на UI.
3. `filter-by-leaf-panel-type` — заменяет булев переключатель настоящим сужением каскада по `panel_type`, делая «Зеркальное» равноправным (взаимоисключающим) вариантом наравне с «Глухое» и «С остеклением»; вынужденно добавляет компенсирующее исключение «выбор «Глухое» не сужает каталог», поскольку модели, поддерживающие зеркало, классифицируются как «с зеркалом», а не «глухое».

Это изменение устраняет причину компенсирующего исключения: зеркало не остеклениеподобная конструкция, а опциональное исполнение глухого полотна. См. proposal.md для полного обоснования.

## Goals / Non-Goals

**Goals:**
- Убрать значение `panel_type = MIRRORED` как отдельную классификацию; глухие leaf_type, поддерживающие зеркало, классифицируются как «глухое».
- Добавить целостностное ограничение: `mirror_finish_option` допустим только для leaf_type с `panel_type = 'BLIND'`.
- Вернуть независимый каскадный переключатель «Нужно зеркало», но, в отличие от исходной реализации 2026-09-02, — вложенным в ветку «Глухое», а не как отдельный пред-коллекционный псевдо-шаг.
- Упростить переключатель «Тип полотна» до симметричного бинарного сужения (оба варианта одинаково сужают каталог) — убрать асимметричное исключение «Глухое не сужает каталог», введённое `filter-by-leaf-panel-type` как временная компенсация.

**Non-Goals:**
- Не меняется расчёт стоимости, справочники `mirror_finish_type`/`glazing_type`, состав запроса расчёта (кроме условия, когда именно `mirrorFinishTypeId` передаётся).
- Не вводится новый явный булев столбец «поддерживает зеркало» на leaf_type — этот признак по-прежнему выводится из наличия строк `mirror_finish_option`, как и раньше (сама задача — не про новый столбец, а про то, что зеркало перестаёт быть значением `panel_type`).
- Не переименовываются существующие требования спецификаций (`Сужение каскада по типу полотна`, `Выбор конкретного исполнения зеркала`) — их формулировки сохраняются, чтобы не порвать перекрёстные ссылки из соседних требований (`Выбор коллекции полотна», «Переключатель «Реверс» в каскаде», «Кнопка «Очистить»»), которые эту задача не трогает.

## Decisions

**Backfill вместо условной логики.** Существующие leaf_type с `panel_type = MIRRORED` (в частности ФАНТОМ 01, `LT-045`) переклассифицируются в `BLIND` прямым UPDATE в том же changeset, что сужает CHECK-ограничение. Альтернатива — вычислять эффективный тип на лету в сервисном слое — отклонена: `panel_type` уже хранимый, не производный на уровне БД для остальных значений, и добавление рантайм-логики поверх него ради одного legacy-значения усложнило бы каждый читающий запрос без выгоды.

**CHECK-ограничение на владение `mirror_finish_option`, а не приложенческая валидация.** Требование «зеркало только для глухих» кодируется как БД-триггер/CHECK (через подзапрос к `leaf_type.panel_type`, либо явный триггер, если диалект PostgreSQL не поддерживает CHECK с подзапросом — в таком случае BEFORE INSERT/UPDATE триггер) — согласуется с существующим стилем схемы (см. `chk_leaf_type_panel_type`), а не только с проверкой в Java-сервисе, чтобы данные оставались целостными независимо от точки записи.

**Название требований сохраняется, формулировки сценариев учитывают историю.** Вместо REMOVED+ADDED с новым именем для `Сужение каскада по типу полотна` и `Выбор конкретного исполнения зеркала` (что физически возможно, но рвёт формулировки-ссылки на эти названия в необновляемых этим change требованиях — `Выбор коллекции полотна» (строка 23), «Переключатель «Реверс» в каскаде» (сценарий про «Нужно зеркало»), «Кнопка «Очистить»»), выбран MODIFIED с сохранением исходных заголовков сценариев и явным переформулированием тела там, где старое поведение прямо инвертируется (например, сценарий «Явный выбор «Глухое» не сужает каталог» теперь описывает, что сужает). Альтернатива с переименованием была отклонена ради целостности перекрёстных ссылок в неизменяемых частях спецификации.

## Risks / Trade-offs

[Существующие заказы/расчёты, ссылающиеся на `panelType = MIRRORED` во фронтенд-состоянии или в кэшированных ответах каталога] → чисто read-only каталог конфигураций (не персистентные заказы), пересчитывается при каждой загрузке страницы — риска рассинхронизации с персистентными данными нет.

[Тесты, явно проверяющие текущее значение `MIRRORED` и сужение по варианту «Зеркальное»] → перечислены в proposal.md (Impact); требуют точечного обновления, а не переписывания с нуля, так как остальная каскадная механика (реверс, четверть, коллекция, кромка, короб) не меняется.

[Заголовки сценариев спецификации, сохранённые ради обратной совместимости ссылок, местами описывают инверсию прежнего поведения текстом внутри тела, а не только заголовком] → это осознанный компромисс валидатора OpenSpec (MODIFIED обязан включать каждый сценарий, который есть в текущей спеке, по заголовку); при архивации `openspec archive` заголовки перейдут в основную спеку как есть — если это будет мешать читаемости, отдельный будущий change может переформулировать заголовки как чистый рефактор спеки (без изменения поведения).

## Migration Plan

1. Liquibase changeset: сузить `chk_leaf_type_panel_type` до `('BLIND', 'GLAZED')`; `UPDATE leaf_type SET panel_type = 'BLIND' WHERE panel_type = 'MIRRORED'`; добавить ограничение на `mirror_finish_option` (владелец обязан быть `BLIND`).
2. Backend: убрать `MIRRORED` из `LeafPanelType`; убедиться, что сериализация `ComponentCatalogDto` не ломается на удалённом значении (проверить существующие snapshot/JSON-тесты).
3. Frontend: `App.tsx`/`ConfiguratorScreen.tsx` — переключатель «Тип полотна» без варианта «Зеркальное»; убрать асимметрию «Глухое не сужает»; вернуть `mirrorFinishEnabled`-состояние, зависимое от действующего значения типа полотна; `api/types.ts` — сузить тип `panelType`.
4. Откат: если потребуется — обратный changeset, восстанавливающий `MIRRORED` и повторно проставляющий его leaf_type с непустым `mirror_finish_option` (список таких leaf_type сохранён в самом changeset миграции как явный список id, чтобы откат не зависел от текущего состояния данных на момент отката).
