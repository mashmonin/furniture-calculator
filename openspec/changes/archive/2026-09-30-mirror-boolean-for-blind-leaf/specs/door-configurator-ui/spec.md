## MODIFIED Requirements

### Requirement: Выбор коллекции полотна
Система ДОЛЖНА (SHALL) отображать шаг выбора коллекции сразу после переключателя «Реверс» (см. «Переключатель «Реверс» в каскаде») и переключателя «Тип полотна» (см. «Сужение каскада по типу полотна»), перед шагом выбора модели полотна. Шаг выбора коллекции НЕ ДОЛЖЕН (SHALL NOT) отображаться, пока переключатель «Тип полотна» показан (то есть среди согласованных с реверсом door_configuration есть более одного значения panelType), но клиент ещё не кликнул по одному из его вариантов явно — в отличие от прежней версии этого требования, молчаливое разрешение resolvedPanelType в «Глухое» по умолчанию (см. «Сужение каскада по типу полотна») больше не раскрывает шаг коллекции без явного действия клиента. Если переключатель «Тип полотна» не показан (значение единственное или его вовсе нет), шаг коллекции отображается сразу. Варианты этого шага — все различные collection, которым принадлежит хотя бы один leaf_type, встречающийся среди door_configuration, согласованных с уже определённым значением реверса и выбранным типом полотна. После выбора коллекции шаг выбора модели полотна ДОЛЖЕН (SHALL) показывать только те leaf_type выбранной коллекции, что встречаются хотя бы в одной согласованной door_configuration каталога; остальные шаги каскада (кромка, короб, наличник, удлинители) продолжают сужаться по ранее установленным правилам, начиная с выбранной модели полотна.

#### Scenario: Первый шаг показывает все коллекции
- **WHEN** значение реверса определено, тип полотна выбран явно (или переключатель «Тип полотна» не показан вовсе), и клиент ещё не выбрал коллекцию
- **THEN** шаг выбора коллекции показывает все различные collection, которым принадлежит хотя бы один leaf_type, встречающийся среди door_configuration, согласованных с реверсом и выбранным типом полотна

#### Scenario: Выбор коллекции сужает список моделей полотна
- **WHEN** пользователь выбрал коллекцию
- **THEN** шаг выбора модели полотна показывает только те leaf_type этой коллекции, что встречаются в согласованных door_configuration каталога

#### Scenario: Изменение коллекции сбрасывает выбор полотна и последующих шагов
- **WHEN** пользователь меняет ранее выбранную коллекцию после того, как модель полотна или последующие шаги каскада (включая введённые опции) уже были выбраны
- **THEN** выбор модели полотна и всех последующих шагов каскада, включая введённые опции, сбрасывается и пересчитывается заново на основе новой выбранной коллекции, а ранее показанный результат расчёта стоимости, если он был показан, скрывается

#### Scenario: Коллекция скрыта до явного выбора типа полотна
- **WHEN** переключатель «Тип полотна» показан (среди согласованных с реверсом door_configuration есть более одного значения panelType), и клиент ещё не кликал ни по одному его варианту
- **THEN** шаг выбора коллекции не отображается, независимо от того, что resolvedPanelType уже молчаливо резолвится в «Глухое» по умолчанию для внутренних целей (см. «Сужение каскада по типу полотна»)

### Requirement: Сужение каскада по типу полотна
Система ДОЛЖНА (SHALL) отображать рядом с выбором коллекции сегментированный переключатель «Тип полотна» — псевдо-шаг каскада, идущий сразу после «Реверс» и до выбора коллекции, аналогичный по механике переключателю «Реверс» (см. «Переключатель «Реверс» в каскаде»), но независимый от него. В общей строке с шагом выбора коллекции переключатель «Тип полотна» ДОЛЖЕН (SHALL) отображаться первым (слева), а шаг выбора коллекции — вторым (справа). Переключатель ДОЛЖЕН (SHALL) отображаться, только если среди согласованных с текущим значением реверса door_configuration встречается более одного различного значения `panelType` их leaf_type; варианты — только те значения panelType («Глухое», «С остеклением»), что реально встречаются среди этих door_configuration.

До тех пор, пока клиент явно не кликнул по одному из вариантов переключателя, ни один вариант НЕ ДОЛЖЕН (SHALL NOT) отображаться визуально выделенным — это относится как к обычной (первой) загрузке страницы, так и к любому последующему моменту, когда выбор варианта клиентом сброшен (см. «Кнопка «Очистить» в панели результата расчёта»). Несмотря на отсутствие визуального выделения, до первого явного клика система ДОЛЖНА (SHALL) вести себя так, будто выбран вариант «Глухое», если он доступен среди встречающихся вариантов, иначе — первый из встречающихся.

Глухое и остеклённое — два взаимоисключающих конструктивных типа полотна: полотно не может быть одновременно тем и другим, и, в отличие от прежней версии этого требования, выбор «Глухое» ДОЛЖЕН (SHALL) сужать согласованные door_configuration наравне с «С остеклением» — до тех, чей leaf_type имеет соответствующее значение panelType. Зеркало не является отдельным значением этого переключателя: оно доступно как дополнительный переключатель «Нужно зеркало» (см. «Переключатель «Нужно зеркало» в каскаде») внутри варианта «Глухое» — сам переключатель «Тип полотна» об исполнениях зеркала ничего не знает.

#### Scenario: Переключатель скрыт, если у согласованных конфигураций один тип полотна
- **WHEN** среди door_configuration, согласованных с текущим значением реверса, встречается только одно значение panelType
- **THEN** переключатель «Тип полотна» не отображается, а поток продолжается сразу с этим значением, без дополнительного действия клиента

#### Scenario: Переключатель показан с «Глухое» выбранным по умолчанию, каталог не сужен
- **WHEN** среди согласованных с реверсом door_configuration встречается более одного значения panelType, включая «Глухое», и клиент ещё не кликал по переключателю «Тип полотна» (в том числе сразу после обычной загрузки страницы или после нажатия «Очистить»)
- **THEN** переключатель отображается без визуально выделенного варианта; для внутренних целей согласованные door_configuration уже ведут себя так, будто выбрано «Глухое» — то есть сужены до leaf_type с panelType «Глухое» (в отличие от прежней версии этого требования, где вариант «Глухое» не сужал каталог вовсе) — но этот выбор по умолчанию НЕ ДОЛЖЕН (SHALL NOT) раскрывать шаг выбора коллекции без явного клика (см. door-configurator-ui, «Выбор коллекции полотна», «Коллекция скрыта до явного выбора типа полотна»)

#### Scenario: Явный выбор «Глухое» не сужает каталог
- **WHEN** клиент, ранее выбравший «С остеклением», переключается обратно на «Глухое»
- **THEN** согласованные door_configuration сужаются до leaf_type с panelType «Глухое», а вслед за этим раскрывается шаг выбора коллекции (см. «Выбор коллекции полотна») — в отличие от прежней версии этого требования, явный выбор «Глухое» теперь сужает каталог точно так же, как и любой другой вариант; в верхнем ряду переключателей появляется «Нужно зеркало» (см. «Переключатель «Нужно зеркало» в каскаде»), если хотя бы один из этих leaf_type поддерживает зеркало

#### Scenario: Выбор «Зеркальное» сужает коллекции и раскрывает выбор исполнения
- **WHEN** клиент пытается выбрать вариант «Зеркальное»
- **THEN** такого варианта у переключателя «Тип полотна» больше нет — зеркало исключено из значений этого переключателя; чтобы получить зеркало, клиент выбирает «Глухое» и затем включает переключатель «Нужно зеркало» (см. «Переключатель «Нужно зеркало» в каскаде»), который и раскрывает выбор конкретного исполнения

#### Scenario: Переключение на другой вариант скрывает выбор исполнения зеркала
- **WHEN** клиент, ранее находившийся на «Глухое» с включённым переключателем «Нужно зеркало» (возможно, уже выбрав конкретное исполнение), переключается на «С остеклением»
- **THEN** переключатель «Нужно зеркало» и раскрытый им шаг выбора исполнения зеркала скрываются, их значения сбрасываются, а согласованные door_configuration и все последующие шаги (включая коллекцию) пересчитываются заново на основе нового выбранного типа полотна

#### Scenario: Изменение типа полотна сбрасывает более поздние шаги
- **WHEN** клиент меняет ранее выбранный тип полотна после того, как коллекция или последующие шаги каскада (включая введённые опции) уже были выбраны
- **THEN** выбор коллекции и всех последующих шагов, включая введённые опции, сбрасывается и пересчитывается заново на основе нового типа полотна, а ранее показанный результат расчёта стоимости, если он был показан, скрывается

#### Scenario: Изменение переключателя «Реверс» не влияет на выбор типа полотна клиентом
- **WHEN** клиент меняет положение переключателя «Реверс»
- **THEN** ранее сделанный клиентом выбор типа полотна не сбрасывается сам по себе (доступные варианты и сужение могут пересчитаться, если это влияет на то, какие door_configuration согласованы с новым значением реверса)

#### Scenario: «Тип полотна» отображается перед «Коллекцией»
- **WHEN** отображаются рядом переключатель «Тип полотна» и шаг выбора коллекции
- **THEN** переключатель «Тип полотна» расположен первым (левее) в строке, а шаг выбора коллекции — вторым (правее)

### Requirement: Выбор конкретного исполнения зеркала
Система ДОЛЖНА (SHALL) отображать шаг выбора конкретного исполнения зеркала, подписанный «Вид зеркала», только тогда, когда переключатель «Нужно зеркало» включён (см. «Переключатель «Нужно зеркало» в каскаде») — в одном ряду с каскадным шагом выбора модели полотна («Полотно»), рядом с ним, а не отдельным блоком в другом месте потока. В этой строке шаг «Вид зеркала» ДОЛЖЕН (SHALL) отображаться первым (слева), а шаг выбора модели полотна («Полотно») — вторым (справа). Варианты этого шага — все исполнения зеркала (mirror_finish_type), встречающиеся хотя бы в одной строке mirror_finish_option среди согласованных door_configuration; никакого отдельного варианта «без зеркала» в этом шаге нет — выключение переключателя «Нужно зеркало» уже покрывает этот случай. Выбор конкретного исполнения зеркала НЕ ДОЛЖЕН (SHALL NOT) сужать согласованные door_configuration и НЕ ДОЛЖЕН (SHALL NOT) сбрасывать уже сделанный выбор коллекции, модели полотна или введённых опций — он используется только в запросе расчёта стоимости (наценка за исполнение).

#### Scenario: Шаг появляется с вариантами, ничего не выбрано по умолчанию
- **WHEN** клиент включает переключатель «Нужно зеркало»
- **THEN** в одном ряду с шагом выбора модели полотна («Полотно») появляется шаг «Вид зеркала» со всеми исполнениями, встречающимися среди согласованных door_configuration, и ни один вариант не выбран

#### Scenario: Выбор исполнения не сужает каталог
- **WHEN** переключатель «Нужно зеркало» включён и клиент выбирает конкретное исполнение зеркала
- **THEN** шаг выбора коллекции и все последующие шаги продолжают показывать полный набор, согласованный с включённым переключателем «Нужно зеркало» — сужения по выбранному исполнению не происходит

#### Scenario: Изменение исполнения зеркала не сбрасывает уже сделанный выбор
- **WHEN** клиент уже выбрал коллекцию, модель полотна и, возможно, опции размеров/цвета, а затем выбирает или меняет исполнение зеркала
- **THEN** ранее выбранные коллекция, модель полотна и введённые опции сохраняются без изменений

#### Scenario: Выбранное исполнение зеркала передаётся в запрос расчёта
- **WHEN** клиент выбрал конкретное исполнение зеркала и активирует расчёт стоимости
- **THEN** в запрос расчёта стоимости для leaf-компонента передаётся id выбранного исполнения зеркала

#### Scenario: Тип полотна, отличный от «Зеркальное», не передаёт исполнение зеркала в запрос расчёта
- **WHEN** выбранный тип полотна — «С остеклением» (значение «Зеркальное» упразднено; для случая «Глухое» с выключенным переключателем «Нужно зеркало» см. «Выключенный переключатель «Нужно зеркало» не передаёт исполнение зеркала в запрос расчёта»), и активируется расчёт стоимости
- **THEN** запрос расчёта отправляется без указания исполнения зеркала для leaf-компонента

#### Scenario: Выключенный переключатель «Нужно зеркало» не передаёт исполнение зеркала в запрос расчёта
- **WHEN** переключатель «Нужно зеркало» выключен (или скрыт) и активируется расчёт стоимости
- **THEN** запрос расчёта отправляется без указания исполнения зеркала для leaf-компонента

#### Scenario: Шаг подписан «Вид зеркала»
- **WHEN** отображается шаг выбора конкретного исполнения зеркала
- **THEN** он подписан «Вид зеркала»

#### Scenario: «Вид зеркала» отображается перед «Полотно»
- **WHEN** отображается шаг «Вид зеркала» рядом с шагом выбора модели полотна
- **THEN** шаг «Вид зеркала» расположен первым (левее) в строке, а шаг выбора модели полотна («Полотно») — вторым (правее)

### Requirement: Выбор вида остекления
Система ДОЛЖНА (SHALL) отображать выпадающий список «Вид остекления» только тогда, когда выбранный тип полотна — «С остеклением» (см. «Сужение каскада по типу полотна») — в одном ряду с каскадным шагом выбора модели полотна («Полотно»), там же, где при включённом переключателе «Нужно зеркало» отображается выбор вида зеркала (см. «Выбор конкретного исполнения зеркала»). В этой строке список «Вид остекления» ДОЛЖЕН (SHALL) отображаться первым (слева), а шаг выбора модели полотна («Полотно») — вторым (справа). Варианты списка — все виды остекления (glazing_type), встречающиеся хотя бы в одной строке glazing_option среди согласованных door_configuration. Выбор конкретного вида остекления НЕ ДОЛЖЕН (SHALL NOT) сужать согласованные door_configuration — это по-прежнему остаётся отображением справочных значений и локальным выбором пользователя, но выбранный вид остекления ДОЛЖЕН (SHALL) передаваться в запрос расчёта стоимости (наценка за вид остекления, см. door-configuration-api).

#### Scenario: Список появляется рядом с выбором модели полотна, ничего не выбрано по умолчанию
- **WHEN** клиент выбирает тип полотна «С остеклением»
- **THEN** в одном ряду с шагом выбора модели полотна («Полотно») появляется выпадающий список «Вид остекления» со всеми видами, встречающимися среди согласованных door_configuration, и ни один вариант не выбран

#### Scenario: Список — выпадающий, а не ряд кнопок
- **WHEN** отображается список «Вид остекления»
- **THEN** он показывается выпадающим списком (как «Коллекция» или «Цвет»), а не рядом кнопок-сегментов (как «Вид зеркала»)

#### Scenario: Выбор вида остекления не сужает каталог
- **WHEN** выбран тип полотна «С остеклением» и клиент выбирает конкретный вид остекления
- **THEN** шаг выбора коллекции и все последующие шаги продолжают показывать полный набор, согласованный с типом полотна «С остеклением» — сужения по выбранному виду остекления не происходит

#### Scenario: Выбор вида остекления не сбрасывает уже сделанный выбор
- **WHEN** клиент уже выбрал коллекцию, модель полотна и, возможно, опции размеров/цвета, а затем выбирает (или меняет) вид остекления
- **THEN** ранее выбранные коллекция, модель полотна и введённые опции сохраняются без изменений — в отличие от смены типа полотна или коллекции, выбор вида остекления не запускает сброс каскада (см. также «Выбор конкретного исполнения зеркала», где по той же причине больше не сбрасывается каскад)

#### Scenario: Вид остекления не передаётся в запрос расчёта
- **WHEN** вид остекления не выбран, либо выбранный тип полотна — «Глухое»
- **THEN** запрос расчёта отправляется без указания вида остекления для leaf-компонента

#### Scenario: Вид остекления передаётся в запрос расчёта
- **WHEN** выбранный тип полотна — «С остеклением», клиент выбрал конкретный вид остекления и активирует расчёт стоимости
- **THEN** в запрос расчёта стоимости для leaf-компонента передаётся id выбранного вида остекления

#### Scenario: Список скрыт для остальных типов полотна
- **WHEN** выбранный тип полотна — «Глухое»
- **THEN** выпадающий список «Вид остекления» не отображается

#### Scenario: «Вид остекления» отображается перед «Полотно»
- **WHEN** отображается выпадающий список «Вид остекления» рядом с шагом выбора модели полотна
- **THEN** список «Вид остекления» расположен первым (левее) в строке, а шаг выбора модели полотна («Полотно») — вторым (правее)

## ADDED Requirements

### Requirement: Переключатель «Нужно зеркало» в каскаде

Система ДОЛЖНА (SHALL) отображать булев переключатель «Нужно зеркало» в верхнем ряду переключателей вместе с «Реверс», «Четверть» и «Двустороннее» (см. «Переключатель «Реверс» в каскаде», «Переключатель «Четверть» в каскаде»), сразу после «Четверть» — а не рядом с шагом выбора модели полотна («Полотно»). Переключатель ДОЛЖЕН (SHALL) отображаться, только когда клиент уже явно выбрал вариант «Глухое» в переключателе «Тип полотна» (см. «Сужение каскада по типу полотна») — молчаливое разрешение по умолчанию в «Глухое», при котором клиент ещё не кликнул, недостаточно, — и среди согласованных с этим выбором door_configuration есть хотя бы одна, чей leaf_type имеет строку mirror_finish_option. По умолчанию, включая обычную загрузку страницы и состояние после «Очистить», переключатель ДОЛЖЕН (SHALL) находиться в выключенном положении.

Переключатель раскрывается до выбора коллекции и модели полотна — в этом смысле он ведёт себя как продолжение «Тип полотна», а не как «Вид зеркала»/«Вид остекления», которые видны только рядом с уже выбираемой моделью. Включение переключателя ДОЛЖНО (SHALL) сузить согласованные door_configuration (в рамках уже выбранного «Глухое») до тех, чей leaf_type имеет хотя бы одну строку mirror_finish_option, раскрыть шаг «Полотно»/«Коллекция» на основе этого суженного набора и раскрыть шаг выбора конкретного исполнения зеркала (см. «Выбор конкретного исполнения зеркала»). Выключение переключателя ДОЛЖНО (SHALL) вернуть согласованные door_configuration к полному набору, согласованному с «Глухое» (без сужения по зеркалу), и скрыть шаг выбора исполнения, сбросив ранее выбранное исполнение.

#### Scenario: Переключатель скрыт для остеклённого полотна
- **WHEN** действующий тип полотна — «С остеклением»
- **THEN** переключатель «Нужно зеркало» не отображается

#### Scenario: Переключатель скрыт, пока тип полотна не выбран явно
- **WHEN** переключатель «Тип полотна» показан (более одного значения panelType встречается среди согласованных с реверсом door_configuration), и клиент ещё не кликал ни по одному его варианту — несмотря на то, что resolvedPanelType уже молчаливо резолвится в «Глухое» по умолчанию
- **THEN** переключатель «Нужно зеркало» не отображается, даже если среди этих (молчаливо суженных) door_configuration есть leaf_type, поддерживающие зеркало

#### Scenario: Переключатель скрыт, если ни один глухой leaf_type не поддерживает зеркало
- **WHEN** клиент явно выбрал «Глухое», и среди согласованных с этим выбором door_configuration ни одна не ссылается на leaf_type со строкой mirror_finish_option
- **THEN** переключатель «Нужно зеркало» не отображается

#### Scenario: Переключатель показан выключенным по умолчанию
- **WHEN** клиент явно выбрал «Глухое», среди согласованных door_configuration есть хотя бы одна с leaf_type, поддерживающим зеркало, и клиент ещё не переключал «Нужно зеркало»
- **THEN** переключатель отображается в выключенном положении (в верхнем ряду переключателей, после «Четверть»), а шаг выбора коллекции показывает полный набор, согласованный с «Глухое», без сужения по зеркалу

#### Scenario: Включение переключателя сужает коллекции и раскрывает выбор исполнения
- **WHEN** клиент включает переключатель «Нужно зеркало»
- **THEN** согласованные door_configuration сужаются до тех, чей leaf_type имеет хотя бы одну строку mirror_finish_option — в частности, шаг выбора коллекции показывает только коллекции, где есть хотя бы один такой leaf_type; в одном ряду с шагом выбора модели полотна появляется шаг «Вид зеркала» (см. «Выбор конкретного исполнения зеркала»)

#### Scenario: Выключение переключателя возвращает полный набор глухих конфигураций
- **WHEN** клиент выключает ранее включённый переключатель «Нужно зеркало»
- **THEN** согласованные door_configuration возвращаются к полному набору, согласованному с «Глухое» (включая leaf_type без поддержки зеркала); шаг «Вид зеркала» скрывается, ранее выбранное исполнение сбрасывается

#### Scenario: Изменение переключателя сбрасывает более поздние шаги
- **WHEN** клиент меняет положение переключателя «Нужно зеркало» после того, как коллекция или последующие шаги каскада (включая введённые опции) уже были выбраны
- **THEN** выбор коллекции и всех последующих шагов, включая введённые опции, сбрасывается и пересчитывается заново на основе нового положения переключателя, а ранее показанный результат расчёта стоимости, если он был показан, скрывается

#### Scenario: Переход на «С остеклением» скрывает и сбрасывает переключатель
- **WHEN** клиент, ранее включивший «Нужно зеркало» на «Глухое», переключает тип полотна на «С остеклением»
- **THEN** переключатель «Нужно зеркало» скрывается, его значение и раскрытый им выбор исполнения сбрасываются (см. «Переключение на другой вариант скрывает выбор исполнения зеркала» в «Сужение каскада по типу полотна»)

#### Scenario: Переход на «С остеклением» скрывает и сбрасывает переключатель
- **WHEN** клиент, ранее включивший «Нужно зеркало» на «Глухое», переключает тип полотна на «С остеклением»
- **THEN** переключатель «Нужно зеркало» скрывается, его значение и раскрытый им выбор исполнения сбрасываются (см. «Переключение на другой вариант скрывает выбор исполнения зеркала» в «Сужение каскада по типу полотна»)
