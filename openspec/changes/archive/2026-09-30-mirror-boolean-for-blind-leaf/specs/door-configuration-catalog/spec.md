## MODIFIED Requirements

### Requirement: Тип полотна leaf_type
Каждый leaf_type ДОЛЖЕН (SHALL) иметь ровно один тип полотна (panel_type) из фиксированного набора взаимоисключающих значений: «глухое», «остеклённое». Значение обязательно — leaf_type без указанного типа полотна не допускается.

Тип полотна — самостоятельный атрибут leaf_type, отражающий конструкцию самого полотна (сплошное или со вставкой из стекла); он не создаёт и не изменяет строки mirror_finish_type/mirror_finish_option/glazing_type/glazing_option и не влияет на их обработку. Зеркало — не самостоятельный конструктивный тип полотна, а опциональное исполнение, доступное только глухим полотнам (см. «Владение mirror_finish_option»); наличие или отсутствие строк mirror_finish_option у leaf_type НЕ ДОЛЖНО (SHALL NOT) влиять на значение его panel_type — прежнее производное значение «с зеркалом» упразднено.

#### Scenario: Leaf_type требует тип полотна
- **WHEN** строка leaf_type вставляется без значения panel_type
- **THEN** база данных отклоняет вставку

#### Scenario: Тип полотна — одно из трёх допустимых значений
- **WHEN** строка leaf_type вставляется со значением panel_type, не входящим в допустимый набор «глухое»/«остеклённое» — в том числе с прежним значением «с зеркалом», которое этим изменением исключается из набора допустимых
- **THEN** база данных отклоняет вставку

#### Scenario: Leaf_type с исполнениями зеркала классифицируется как «с зеркалом»
- **WHEN** для leaf_type существует хотя бы одна строка mirror_finish_option
- **THEN** его panel_type НЕ становится и не может стать «с зеркалом» — такого значения больше не существует; он остаётся «глухое», как и требуется для владения mirror_finish_option (см. «Владение mirror_finish_option»)

#### Scenario: Leaf_type без исполнений зеркала не может быть типа «с зеркалом»
- **WHEN** для leaf_type не существует ни одной строки mirror_finish_option
- **THEN** его panel_type равен «глухое» или «остеклённое» — значения «с зеркалом» не существует ни для одного leaf_type, независимо от наличия исполнений зеркала

### Requirement: Владение mirror_finish_option
Mirror_finish_option ДОЛЖЕН (SHALL) ссылаться ровно на один mirror_finish_type и ровно один leaf_type — какое исполнение зеркала допустимо для какой модели полотна. Комбинация mirror_finish_type и leaf_type ДОЛЖНА (SHALL) быть уникальной. В отличие от liner_dimension_option/colour_option, mirror_finish_option ДОЛЖЕН (SHALL) владеться исключительно leaf_type — ссылки на frame_type/edge_type/door_casing_type/frame_extensions_type не предусмотрены (исполнение зеркала — свойство полотна). Leaf_type, на который ссылается mirror_finish_option, ДОЛЖЕН (SHALL) иметь panel_type равный «глухое» — зеркало доступно только глухим полотнам, остеклённым не бывает.

#### Scenario: Запись mirror_finish_option требует leaf_type и mirror_finish_type
- **WHEN** строка mirror_finish_option вставляется без ссылки на leaf_type или без ссылки на mirror_finish_type
- **THEN** база данных отклоняет вставку

#### Scenario: Исполнение не может повторяться для одного полотна
- **WHEN** для одного и того же leaf_type вставляется вторая строка mirror_finish_option с уже существующим mirror_finish_type
- **THEN** база данных отклоняет вставку

#### Scenario: Одно и то же исполнение допустимо для нескольких моделей полотна
- **WHEN** для одного mirror_finish_type вставляются строки mirror_finish_option для нескольких разных leaf_type
- **THEN** все строки сохраняются независимо

#### Scenario: Mirror_finish_option недопустим для остеклённого leaf_type
- **WHEN** строка mirror_finish_option вставляется со ссылкой на leaf_type, чей panel_type равен «остеклённое»
- **THEN** база данных отклоняет вставку

### Requirement: Тип полотна в каталоге конфигураций
Для leaf-компонента каждой door_configuration в ответе каталога конфигураций система ДОЛЖНА (SHALL) включать тип полотна (panel_type) leaf_type этой конфигурации. Для остальных компонентов (frame, edge, doorCasing, frameExtensions) поле типа полотна в ответе отсутствует или равно `null`.

#### Scenario: Каталог отдаёт тип полотна leaf-компонента
- **WHEN** запрашивается каталог конфигураций
- **THEN** для leaf-компонента каждой конфигурации в ответе присутствует её тип полотна («глухое» или «остеклённое»)

#### Scenario: Остальные компоненты не имеют типа полотна
- **WHEN** запрашивается каталог конфигураций
- **THEN** для frame-, edge-, doorCasing- и frameExtensions-компонентов поле типа полотна в ответе отсутствует или равно `null`

### Requirement: Остеклённые модели коллекций Гармония, Геометрия, Свобода и Элегант
Для leaf_type со следующими кодами panel_type ДОЛЖЕН (SHALL) быть равен «остеклённое», и им ДОЛЖНЫ (SHALL) быть доступны все шесть видов остекления (строка glazing_option на каждый):
- `LT-017` (ЭЛЕГАНТ 01V), `LT-018` (ЭЛЕГАНТ 02V), `LT-019` (ЭЛЕГАНТ 021V)
- `LT-023` (ГАРМОНИЯ 01V), `LT-024` (ГАРМОНИЯ 02V), `LT-025` (ГАРМОНИЯ 021V)
- `LT-030` (СВОБОДА 01V), `LT-031` (СВОБОДА 02V), `LT-032` (СВОБОДА 021V), `LT-033` (СВОБОДА 01G)
- `LT-036` (ГЕОМЕТРИЯ 01V), `LT-037` (ГЕОМЕТРИЯ 02V)

Эти же leaf_type НЕ ДОЛЖНЫ (SHALL NOT) иметь ни одной строки mirror_finish_option — зеркало недоступно остеклённым полотнам (см. «Владение mirror_finish_option»).

#### Scenario: Перечисленные модели классифицированы как остеклённые
- **WHEN** запрашивается leaf_type с одним из перечисленных кодов
- **THEN** его panel_type равен «остеклённое», и для него существуют строки glazing_option на все шесть видов остекления

#### Scenario: Перечисленные модели недоступны с зеркалом
- **WHEN** запрашивается leaf_type с одним из перечисленных кодов
- **THEN** для него не существует ни одной строки mirror_finish_option

### Requirement: Доступность зеркала для ФАНТОМ 01
Для leaf_type ФАНТОМ 01 (`LT-045`), чей panel_type равен «глухое», ДОЛЖНЫ (SHALL) существовать строки `mirror_finish_option` для всех существующих `mirror_finish_type` («Глухое плоское полотно с зеркалом с одной стороны», «...с фацетом с одной стороны», «...серое/бронза с одной стороны») — зеркало является доступной, но не обязательной опцией исполнения этого глухого полотна.

#### Scenario: ФАНТОМ 01 показывает все исполнения зеркала
- **WHEN** запрашивается каталог конфигураций и leaf_type данной door_configuration — ФАНТОМ 01
- **THEN** в ответе для leaf-компонента присутствуют все три исполнения зеркала: «Базовое», «С фацетом» и «Серое/бронза»

#### Scenario: ФАНТОМ 01 классифицирован как полотно с зеркалом
- **WHEN** запрашивается leaf_type ФАНТОМ 01
- **THEN** его panel_type равен «глухое» (`BLIND`) — значения «с зеркалом» больше не существует; зеркало для ФАНТОМ 01 доступно как опциональное исполнение этого глухого полотна, а не как отдельная классификация
