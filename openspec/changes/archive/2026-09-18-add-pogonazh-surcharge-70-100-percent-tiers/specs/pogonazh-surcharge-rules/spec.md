## MODIFIED Requirements

### Requirement: Структура pogonazh_surcharge_rule
Pogonazh_surcharge_rule ДОЛЖЕН (SHALL) ссылаться ровно на одного владельца — либо frame_type, либо door_casing_type, либо frame_extensions_type (ровно одна из трёх ссылок задана, остальные две — NULL). Правило задаётся ровно одним из двух взаимоисключающих способов:
- **точечное правило** — задано конкретное значение размера (`value`) в миллиметрах; наценка применяется только при точном совпадении значения;
- **диапазонное правило** — `value` NULL, а вместо него задана хотя бы одна из границ диапазона: `min_value_exclusive` (нижняя граница, не включая её) и/или `max_value_inclusive` (верхняя граница, включая её); наценка применяется, если значение строго больше `min_value_exclusive` (когда он задан) и меньше-либо-равно `max_value_inclusive` (когда он задан); отсутствующая граница означает отсутствие ограничения с этой стороны.

`surcharge_percent` обязателен для правила любого вида. Комбинация владельца и `value` (для точечных правил) ДОЛЖНА (SHALL) быть уникальной.

#### Scenario: Правило требует ровно одного владельца
- **WHEN** строка pogonazh_surcharge_rule вставляется без ссылки ни на frame_type, ни на door_casing_type, ни на frame_extensions_type, либо со ссылками сразу на два или три из них
- **THEN** база данных отклоняет вставку

#### Scenario: Правило требует value и surcharge_percent
- **WHEN** строка pogonazh_surcharge_rule вставляется без границ диапазона (min_value_exclusive и max_value_inclusive не заданы), но без value или без surcharge_percent
- **THEN** база данных отклоняет вставку

#### Scenario: Диапазонное правило требует хотя бы одну границу и surcharge_percent
- **WHEN** строка pogonazh_surcharge_rule вставляется без value и одновременно без min_value_exclusive, и без max_value_inclusive (ни точка, ни диапазон), либо без surcharge_percent
- **THEN** база данных отклоняет вставку

#### Scenario: Правило не может быть одновременно точечным и диапазонным
- **WHEN** строка pogonazh_surcharge_rule вставляется с одновременно заданным value и хотя бы одной из границ диапазона (min_value_exclusive или max_value_inclusive)
- **THEN** база данных отклоняет вставку

#### Scenario: Значение не может повторяться для одного владельца
- **WHEN** для одного и того же frame_type (или door_casing_type, или frame_extensions_type) вставляется вторая точечная строка pogonazh_surcharge_rule с уже существующим value
- **THEN** база данных отклоняет вставку

#### Scenario: Один и тот же value допустим для разных владельцев
- **WHEN** для разных владельцев (например, разных door_casing_type) вставляются строки pogonazh_surcharge_rule с одинаковым value
- **THEN** все строки сохраняются независимо друг от друга

## ADDED Requirements

### Requirement: Наценка 70% и 100% для длин, требующих значительно большего расхода материала
Для значений размера погонажа, требующих существенно большего расхода материала по сравнению с уже определёнными тирами 30%/50%, `surcharge_percent` ДОЛЖЕН (SHALL) составлять 70% или 100% в зависимости от значения:
- **70%** — точечные правила: `value = 3000` мм для короба «Компланар» (frame_type FT-002); `value = 3000` мм для наличника «Эво» (door_casing_type DCT-001); `value = 3000` мм и `value = 2950` мм для добора «Компланар» (frame_extensions_type FET-008..010 и FET-011..013 соответственно); а также диапазонное правило `2400 < value ≤ 2700` для короба «Фантом» (frame_type FT-001).
- **100%** — диапазонное правило `value > 2700` (без верхней границы) для короба «Фантом» (frame_type FT-001).

Диапазонные правила короба «Фантом» дополняют, а не заменяют, уже существующие точечные правила этого владельца со значениями 2050/2150/2200/2250/2300 (30%) и 2350/2400 (50%) — диапазон начинается строго после 2400 мм и не пересекается с ними.

#### Scenario: 3000 мм для короба «Компланар» — 70%
- **WHEN** для конфигурации выбран короб «Компланар», чья вычисленная высота погонажа равна 3000 мм
- **THEN** к цене компонента frame применяется наценка 70%

#### Scenario: 3000 мм для наличника «Эво» — 70%
- **WHEN** для конфигурации выбран наличник «Эво», чья длина равна 3000 мм
- **THEN** к цене компонента doorCasing применяется наценка 70%

#### Scenario: 2950/3000 мм для добора «Компланар» — 70%
- **WHEN** для конфигурации выбран добор «Компланар», чья длина равна 2950 мм или 3000 мм (в зависимости от конкретного типа добора)
- **THEN** к цене компонента frameExtensions применяется наценка 70%

#### Scenario: Высота полотна строго больше 2400 и не больше 2700 мм для короба «Фантом» — 70%
- **WHEN** для конфигурации с коробом «Фантом» высота полотна строго больше 2400 мм и меньше-либо-равна 2700 мм (например, 2550 мм — значение, для которого нет отдельной точечной строки)
- **THEN** это значение считается нестандартным, и к цене компонента frame применяется наценка 70%, независимо от отсутствия отдельной точечной строки pogonazh_surcharge_rule для этого конкретного значения

#### Scenario: Высота полотна строго больше 2700 мм для короба «Фантом» — 100%
- **WHEN** для конфигурации с коробом «Фантом» высота полотна строго больше 2700 мм (любое значение, без верхнего предела)
- **THEN** к цене компонента frame применяется наценка 100%
