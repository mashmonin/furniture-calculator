## Context

Текущая раскладка (`frontend/src/App.tsx`, `frontend/src/App.css`) уже реализует то, что задаёт большая часть Figma-макета: трёхколоночная структура (`.app-sidebar` / `.app-main` / `.app-pricing`), аккордеон разделов через `Collapse`, карточки компонентов через `Card`, группы опций — через уже существующий `OptionGroup` (`frontend/src/components/OptionGroup.tsx`), который сам построен на `Radio.Group`/`Radio.Button`/`Select` из `antd` и уже визуально близок к прямоугольным «таблеткам» макета. Значение высоты полотна для текущего выбора уже вычисляется один раз за рендер в переменной `leafHeightValue` (`App.tsx`) и используется функциями `edgeHeightOptions`, `frameHeightRangeOptions`, `lengthRangeOptions` и т.д. для фильтрации — то есть данные для бейджей-подсказок уже есть в состоянии компонента, нового запроса к API не требуется.

Три реальных пробела относительно макета: (1) отсутствует верхняя шапка приложения; (2) фильтрация опций по высоте полотна происходит молча — нет визуальной подсказки, откуда взялось ограничение; (3) правая колонка результата — обычный список `Statistic`, без акцентной рамки и без визуально обособленного блока дилерской цены. См. proposal.md — Why/What Changes.

## Goals / Non-Goals

**Goals:**
- Добавить шапку приложения (лого + название + статичная подпись прайс-листа), не влияющую на остальную раскладку и не требующую нового состояния.
- Показать пользователю значение высоты полотна рядом с каждой карточкой, чьи шаги фильтруются по этой высоте, используя уже вычисляемый `leafHeightValue` — без новых запросов и без дублирования логики фильтрации.
- Дать колонке результата акцентную рамку и визуально обособить блок дилерской цены.
- Сделать это исключительно средствами `antd` и CSS, не вводя новых зависимостей.

**Non-Goals:**
- Не меняется структура раскладки (три колонки, аккордеон, sticky-панель) — она уже соответствует макету и не трогается.
- Не меняется бэкенд, контракт REST API и доменная модель.
- Не добавляется пункт меню «Фурнитура отдельно» и кнопка экспорта в Excel — вынесено в отдельные будущие change (см. proposal.md).
- Не переписывается `OptionGroup` — его текущий вид (Radio.Button/Select) уже соответствует стилю макета.

## Decisions

### 1. Шапка — новый лёгкий компонент, а не `antd Layout.Header`
Внедрять целиком `antd Layout`/`Layout.Header`/`Layout.Sider` вместо текущих `.app-columns`/`.app-sidebar`/`.app-main`/`.app-pricing` div'ов — это более рискованная переработка ради чисто визуального результата (Layout.Header навязывает свою модель высоты/фона, которую пришлось бы переопределять). Вместо этого — простой flex-блок над `.app-columns` (те же div-примитивы, что уже используются в `.page`), со своим CSS-классом `.app-header`, содержащий лого-плашку (цветной квадрат с иконкой из `@ant-design/icons`, например `HomeOutlined`/`AppstoreOutlined` — конкретную иконку подобрать по смыслу, макет использует условную «дверь») и `Typography.Title`/`Typography.Text` для названия и подписи прайс-листа.

### 2. Подсказка о высоте полотна — переиспользование существующего `leafHeightValue`, рендер через `Tag`
Компактный бейдж реализуется через `antd Tag` (готовый компонент «таблетки» с рамкой, ровно то, что показывает макет), помещаемый рядом с заголовком нужной карточки (`Card title` как `ReactNode`, объединяющий текст заголовка и `Tag`). Условие показа — то самое `leafHeightValue !== undefined` и принадлежность карточки к списку компонентов с фильтрацией (edge; frame, если его тип входит в `HEIGHT_RANGE_FRAME_TYPE_CODES`; doorCasing/frameExtensions, если их тип входит в соответствующие `LENGTH_RANGE_*_TYPE_CODES`), то есть переиспользуются уже существующие в `App.tsx` списки кодов типов и уже вычисленный `leafHeightValue` — никакой новой логики фильтрации не добавляется, только рендер подсказки поверх уже принятого решения "показывать/скрывать группу".

Альтернатива — вычислять видимость бейджа заново по каждому condition-компоненту отдельно — отклонена: дублировала бы существующие предикаты (`frameCoversHeight`, `lengthRangeCoversHeight` и т.п.) без пользы; вместо этого бейдж просто следует тому же `leafHeightValue !== undefined`, а перечень карточек, где он уместен, фиксирован (edge всегда; frame/doorCasing/frameExtensions — только если у текущего выбранного типа компонента есть хоть одна опция высоты/длины, отфильтрованная по этому правилу, что уже вычислено списком доступных опций для рендера самой группы).

### 3. Акцентная рамка и блок дилерской цены — CSS + оборачивание существующих `Statistic`
`.app-pricing` получает `border: 1px solid <primary>` (используя переменную/константу цвета из темы `antd`, чтобы не хардкодить hex независимо от возможной темизации). Блок дилерской цены — `Statistic` для дилерской цены оборачивается в `<div className="app-pricing__dealer-block">` с собственным фоном и небольшим padding/border-radius, розничная цена остаётся как есть (без обёртки). Никакой новой библиотеки компонентов не требуется — `Statistic` продолжает использоваться, меняется только его обрамление.

### 4. Иконка сворачивания/разворачивания раздела — `expandIconPosition="start"` у `Collapse`
Косметическая правка положения шеврона (слева от заголовка, как в макете) — штатная опция `antd Collapse` (`expandIconPosition="start"`), без кастомного рендера. Не выносится в спецификацию как отдельное требование — это деталь оформления существующего аккордеона, а не новое наблюдаемое поведение.

## Risks / Trade-offs

- [Список карточек, где уместен бейдж высоты, зависит от `component.type.code` конкретного выбранного типа, а не абстрактно от ключа компонента] → приемлемо: тот же принцип уже применяется в существующей фильтрации (`HEIGHT_RANGE_FRAME_TYPE_CODES` и т.д.), поэтому логика видимости бейджа не добавляет новой категории решений, только переиспользует существующую.
- [Хардкод текста подписи прайс-листа во фронтенде] → сознательный выбор по решению пользователя в ходе `/opsx:propose` (раздел proposal.md); зафиксировать место константы (верх `App.tsx`, рядом с другими константами вида `SERVICE_MENU_ITEMS`), чтобы обновление названия прайс-листа оставалось однострочной правкой.
