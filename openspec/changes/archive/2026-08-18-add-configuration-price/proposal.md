## Why

Каталог `door-configuration-catalog` (add-door-configuration-catalog) знает, какие комбинации типов компонентов и какие размеры/цвета допустимы, но не знает их цену. Пользователь подтвердил: цена зависит от конкретной комбинации (материал/тип компонента + размеры + цвет), а не единая на модель — значит нужна отдельная сущность, привязанная к конкретному сочетанию значений, а не к самому типу.

## What Changes

- Новая таблица `configuration_price` — retail_price и dealer_price (оба обязательны) на одну ПОЛНУЮ комбинацию: тип компонента + (опционально) конкретное значение длины, высоты, толщины + (опционально) конкретный цвет.
- Владение по типу компонента — тот же single-owner паттерн, что и у `door_configuration`/`liner_dimension_option`/`colour_option`: ровно один из leaf_type/frame_type/edge_type/door_casing_type/frame_extensions_type.
- Ссылки на размер — три отдельные необязательные колонки (длина/высота/толщина), каждая ссылается на существующую строку `liner_dimension_option` (не дублирует value). Необязательные — потому что не каждый тип компонента использует все три вида размера.
- Ссылка на цвет — необязательная колонка на существующую строку `colour_option` (не на `colour_type` напрямую) — цена может существовать только для уже разрешённого этому типу цвета.
- Комбинация владелец + длина + высота + толщина + цвет уникальна (с учётом того, что часть ссылок может быть NULL).
- Наполнение реальными ценами (например, для моделей ВЕРТИКАЛЬ) — отдельная задача после реализации схемы, в это изменение не входит.
- Единица измерения не добавляется — по решению пользователя.

## Capabilities

### Modified Capabilities
- `door-configuration-catalog`: добавляется структура `configuration_price` и требования к её владению, ссылкам на размеры/цвет и уникальности.

## Impact

- Новый Liquibase changeset в `backend/src/main/resources/db/changelog/changes/`, подключённый в `db.changelog-master.yaml`.
- Существующие таблицы `door_configuration`, `liner_dimension_option`, `colour_option` не меняются — `configuration_price` только ссылается на них.
- Java-слой по-прежнему не существует в проекте — изменение затрагивает только схему БД.
