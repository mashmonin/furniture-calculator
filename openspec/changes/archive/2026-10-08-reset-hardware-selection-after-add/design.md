## Context

`HardwareServiceScreen.tsx` хранит выбор в состоянии: `brand`, `category`, `colourFilter`, `search`, `recordId` (подсвеченная запись), `selectedItemId` (цель добавления — дверь). Первый бренд ставится автоматически после загрузки каталога (`setBrand((current) => current ?? первый)`); поле поиска (`Input.Search`) неуправляемое, поэтому его текст нельзя сбросить из состояния. Добавление: `addHardware(optionId)` → `applySelections` (расчёт фурнитуры, `onUpdateItem`, `busy`). Эффект «полёта» уже есть в `App.tsx` (кружок `.cart-fly-particle`, CSS-переменные координат, `CART_FLY_DURATION_MS = 650`, `onAnimationEnd`), но он принадлежит `App`.

## Goals / Non-Goals

**Goals:** сброс подбора после успешного добавления; частица от «+» к карточке выбранной двери; бренд пуст по умолчанию и после сброса.

**Non-Goals:** сброс выбранной двери; изменение расчёта или корзины; анимация при удалении/изменении количества.

## Decisions

**1. Сброс — после успешного расчёта.** `applySelections` получает признак «сбросить после успеха» (только для `addHardware`); в `.then` после `onUpdateItem` вызывается `resetPicker()`: `brand`, `category`, `colourFilter`, `search`, `recordId` → пусто. При ошибке выбор сохраняется, чтобы пользователь мог повторить. Альтернатива — сбрасывать сразу при клике: теряется выбор при ошибке.

**2. Поиск становится управляемым.** `Input.Search` получает `value={search}` и `onChange`, иначе сброс не очистит поле.

**3. Бренд по умолчанию пуст.** Удаляется автоподстановка первого бренда; `Select` бренда с `placeholder="Выберите бренд"`. При `brand === undefined` список `records` пуст, а в блоке «Модель» (счётчик «Модель (0)») показывается `Empty` с текстом «Выберите бренд»; «Элемент» и «Цвет» `disabled`, так как их варианты строятся от бренда. Смена бренда по-прежнему сбрасывает «Элемент» и «Цвет». Альтернатива — показывать записи всех брендов без выбора (отвергнута пользователем).

**4. Частица — локально в экране «Фурнитура».** Повторно используется CSS `.cart-fly-particle` и `cart-fly-particle-move`; константа длительности выносится из `App.tsx` в `cart.ts` (`CART_FLY_DURATION_MS`), чтобы не дублировать число. Старт — центр кнопки «+» (`event.currentTarget.getBoundingClientRect()` в момент клика), финиш — центр карточки выбранной двери (ссылка на DOM-элемент карточки по id позиции, например `data-door-id` + `querySelector`, координаты берутся в момент клика, до обновления списка в карточке). Частица стартует после успешного добавления; один экземпляр с `key`, как в `App.tsx`. Альтернатива — поднять `flight` в `App` и передавать колбэк: лишняя связность, т. к. обе точки — внутри одного экрана.

## Risks / Trade-offs

- Карточка двери может быть вне видимой области ленты (прокрутка вбок) → частица летит к её текущим экранным координатам; допустимо.
- Быстрые повторные нажатия «+» → `busy` блокирует кнопки на время расчёта (как сейчас), поэтому гонок со сбросом нет.
- Если карточка не найдена в DOM → частица не показывается, сброс всё равно выполняется.
