## Why

Короб ФАНТОМ (`frame_type`, код `FT-001`) заведён в справочнике с самого начала (`0004-item-configuration-reference-data.yaml`), но так и не был активирован: у него нет ни одной строки `door_configuration` — он не встречается ни в одном допустимом сочетании с полотном — и ни одной цены. Клиент не может выбрать этот короб в калькуляторе. При этом комплект стоек ФАНТОМ продаётся не единым набором комплектующих (как у КОМПЛАНАР/НЕО/КОМПЛАНАР РЕВЕРС — «незарезная стойка» + «комплект зарезных стоек», складываются вместе), а как один комплект («2 стойки и верх») в четырёх взаимоисключающих вариантах отделки с разной ценой — так короб ещё не продавался, и текущая модель расчёта стоимости короба (сумма всех `frame_post`, без выбора цвета) для этого не подходит.

## What Changes

- Активировать короб ФАНТОМ (`FT-001`): добавить строки `door_configuration`, сочетающие его с полотном всех уже активных коллекций (`LC-001`–`LC-008`; коллекция `LC-009` «Фантом» сама пока не активирована и не включается), базовый набор — без наличника и без добора, с обеими существующими кромками (`ET-001`, `ET-002`).
- Добавить 4 варианта отделки комплекта стоек ФАНТОМ как `colour_option`, привязанные к `frame_type` FT-001: «Хром матовый» (`CT-023`), «Черный» (`CT-025`), «Покраска по RAL» (`CT-027`) — переиспользуются из существующего справочника цветов кромки, и новый цвет «Золото/бронза» (новый `colour_type`) — с ценами через `configuration_price` (дилер/розница): 9903/16850, 11003/18722, 19806/33700, 19806/33700 соответственно. Для ФАНТОМ не заводятся строки `frame_post` — комплект стоек не раскладывается на отдельные позиции, а полностью описывается выбором цвета.
- **BREAKING (поведение расчёта)**: изменить правило стоимости короба — сейчас цена короба всегда равна сумме `frame_post` независимо от опций, у короба нет цветовых опций. Новое правило: если у `frame_type` есть допустимые цвета (`colour_option`), стоимость короба — это сумма `frame_post` (может быть 0) плюс цена наиболее специфичной подходящей строки `configuration_price` по выбранному клиентом цвету; без выбора цвета либо без подходящей строки короб считается некалькулируемым, как и другие компоненты. Для коробов без цветовых опций (КОМПЛАНАР, НЕО, КОМПЛАНАР РЕВЕРС) поведение не меняется.

Каталог (`door-configuration-api`) и UI (`door-configurator-ui`) уже сформулированы достаточно обобщённо: требование каталога «Допустимые опции размеров и цвета для каждого компонента» уже перечисляет `frame_type` как владельца `colour_option`, а требование UI «Динамический выбор опций компонентов» уже рендерит группу цвета для любого компонента (включая frame), у которого каталог отдаёт непустой список цветов. До сих пор это оставалось мёртвым путём, потому что ни у одного `frame_type` не было ни одной строки `colour_option`. Изменение спецификации нужно только для правил расчёта стоимости — остальное заработает само после наполнения данных и правки сервиса расчёта.

## Capabilities

### New Capabilities
(нет)

### Modified Capabilities
- `door-configuration-api`: правило расчёта стоимости короба меняется — короб с допустимыми цветами оценивается через `configuration_price` по выбранному цвету (в дополнение к сумме `frame_post`), с требованием выбора цвета для калькулируемости; правило для коробов без цветовых опций не меняется.

## Impact

- **Backend**: `DoorConfigurationPricingService` — убрать безусловное исключение frame-компонента из цветового ценообразования, добавить сумму `frame_post` + цветовую цену через `findMostSpecificPrice`.
- **Frontend**: изменений не требуется — существующий обобщённый рендеринг групп опций уже подставит селектор цвета для короба, как только каталог начнёт отдавать для FT-001 непустой `colourOptions`.
- **БД (данные, без изменения схемы)**: новые Liquibase-миграции — `door_configuration` для FT-001 × активные коллекции, новый `colour_type` «Золото/бронза», `colour_option` и `configuration_price` для FT-001.
- **Специфика**: коллекция `LC-009` «Фантом» (полотно) и `frame_post` для FT-001 в этом change не затрагиваются.
