## Why

В списке записей сервиса «Фурнитура» позиции различаются только текстом (модель, цвет, цены); ручки сложно узнать по названию и артикулу. Появились фотографии ручек по артикулам (папка `foto_ruchek_po_artikulam`: 1037 файлов + `список.csv` с привязкой артикул → файл), их нужно сохранить в приложении и показать в списке.

## What Changes

- Фотографии переносятся в ресурсы backend (`backend/src/main/resources/hardware-images/`), имя файла = артикул цветового варианта, где `/` заменён на `_`; при переносе уменьшаются и конвертируются в WebP (27 МБ исходных PNG/JPG не попадают в jar и desktop-дистрибутив как есть).
- Backend: в `HardwareOptionDto` появляется поле `imageUrl` (null, если для артикула нет фото); новый эндпоинт `GET /api/hardware-images/{file}` отдаёт файл с кэширующими заголовками.
- Frontend: в строке записи списка «Модель» сервиса «Фурнитура» слева показывается миниатюра фото; если фото нет — нейтральная заглушка того же размера, чтобы строки не «прыгали».
- Покрытие: фото получают 1037 из 1052 позиций прайс-листа PL-003 (ручки, петли, фиксаторы, накладки, цилиндры и др. трёх брендов); 15 позиций без файла в исходных папках (`F20D AL`, `ZL60(30x30) CP`, `VE001 SB`, `Квадрат 6х6х100` и др.) показываются с заглушкой. Фото «новинок» (артикул БД «B44-SC новинка(…)») берётся из файла артикула без суффикса.
- Изменений схемы БД нет: связь «артикул → фото» определяется по имени файла.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `hardware-catalog`: каталог отдаёт для цветового варианта ссылку на фото (если есть) и предоставляет эндпоинт получения фото.
- `hardware-service-ui`: запись каталога в сервисе «Фурнитура» показывает фото позиции или заглушку.

## Impact

- Backend: `HardwareOptionDto`, `HardwareCatalogService`, новый компонент каталога изображений (по образцу `DoorImageCatalog`), новый контроллер, ресурсы `hardware-images/`; тесты контроллера/сервиса.
- Frontend: `HardwareServiceScreen.tsx`, тип `HardwareOptionDto` (`api/`), только компоненты `antd` (`Image`/`Avatar`).
- Размер дистрибутива растёт на ~8 МБ (после уменьшения); новых зависимостей нет (WebP отдаётся как есть, декодирование на стороне браузера).
- API: добавляется необязательное поле в ответ `/api/hardware-catalog` — обратно совместимо.
