## Why

Для короба «НЕО» (`FrameType`, код `FT-003`) высота самого короба физически зависит от выбранной высоты полотна: одному диапазону высоты полотна соответствует ровно одна допустимая высота короба, а для некоторых диапазонов высоты полотна короб «НЕО» вообще недоступен. Сейчас каталог позволяет выбрать любую высоту короба независимо от высоты полотна, что даёт клиенту возможность собрать физически невозможную конфигурацию. Аналогичная проблема для кромки уже решена в `2026-08-25-link-edge-height-to-leaf-height` — этот change переносит тот же принцип на короб «НЕО».

## What Changes

- В `liner_dimension_option` добавляется новое поле `max_value` (nullable) — верхняя граница диапазона высоты полотна, для которого действует опция. В отличие от кромки, где верхней границей диапазона повторно использовалось поле `value` (там оно случайно совпадало с физической высотой), для короба «НЕО» физическая высота (2170/2400/2700 мм) не совпадает с границами диапазона высоты полотна (2100/2250/2300/2550 мм) — поэтому нужна отдельная колонка, а не переиспользование `value`.
- Валидация «высота компонента совместима с высотой полотна» на бэкенде расширяется на короб: применяется только когда у опции высоты заполнена хотя бы одна из границ диапазона (`min_value`/`max_value`), поэтому короба «Фантом» (`FT-001`) и «Компланар» (`FT-002`), у которых таких данных нет, не затрагиваются.
- Существующий уникальный индекс `uk_liner_dimension_option_frame_type` расширяется дополнительными колонками диапазона, чтобы разрешить две опции короба «НЕО» с одинаковой высотой (2400 мм), но непересекающимися диапазонами высоты полотна (2150–2250 и отдельно 2300) — см. design.md.
- Новая Liquibase-миграция с диапазонами высоты полотна → высота короба «НЕО»:
  - 1900–2100 → 2170 мм
  - 2150–2250 → 2400 мм
  - 2300 (точка) → 2400 мм
  - 2350–2550 → 2700 мм
  - 2600–2850 и 2900–2950 → короб «НЕО» недоступен (опций нет)
- Frontend: список доступных высот короба фильтруется по высоте полотна (аналог `edgeHeightOptions`), группа «Высота» для короба скрывается, пока высота полотна не выбрана; выбор высоты короба сбрасывается при смене высоты полотна.
- Backend: высота становится обязательной для frame-компонента с кодом `FT-003` — если `heightOptionId` вообще не передан, эндпоинт расчёта стоимости отвечает 400, а не пропускает проверку молча. Это закрывает дыру: без этого правила для высоты полотна, не покрытой ни одним диапазоном короба «НЕО» (например, 2600–2850, 2900–2950), можно было получить успешный расчёт с коробом «НЕО» без выбранной высоты вообще.
- Frontend: короб «НЕО» дополнительно исключается из списка доступных типов короба на шаге каскадного выбора, если высота полотна уже выбрана и не покрывается ни одним его диапазоном — как UX-дополнение поверх backend-проверки (не замена, т.к. порядок каскада не гарантирует, что высота полотна выбрана раньше типа короба).

## Capabilities

### New Capabilities

### Modified Capabilities

- `door-configuration-api`: добавляется требование о совместимости диапазона высоты короба «НЕО» с высотой полотна (по аналогии с существующим требованием для кромки).
- `door-configurator-ui`: добавляется требование об условном отображении и фильтрации высоты короба «НЕО» по высоте полотна (по аналогии с существующим требованием для кромки).
- `door-configuration-catalog`: структура `liner_dimension_option` дополняется полем `max_value`, уникальный индекс для владельца frame_type расширяется под диапазоны.

## Impact

- **Backend**: `LinerDimensionOption` (новое поле `maxValue`), `LinerDimensionOptionDto`, `DoorConfigurationCatalogService.toDto`, `DoorConfigurationPricingService` (расширение/обобщение `validateHeightWithinLeafRange`, новая ветка для `FrameType` с кодом `FT-003`, обязательность `heightOptionId` для этого кода).
- **БД**: новая колонка `liner_dimension_option.max_value`; изменение уникального индекса `uk_liner_dimension_option_frame_type`; новые данные для `FT-003` по оси высоты.
- **Frontend**: `frontend/src/App.tsx` (фильтрация высоты короба, сброс выбора при смене высоты полотна, исключение «НЕО» из каскада выбора короба при несовместимой высоте полотна — двухпроходный `buildCascadeSteps`), `frontend/src/api/types.ts` (`LinerDimensionOptionDto.maxValue`).
- **Тесты**: `DoorConfigurationPricingServiceTest` — новые кейсы по аналогии с кейсами для кромки.
- Другие типы короба (`FT-001`, `FT-002`) и все существующие данные по кромке не меняются в поведении.
