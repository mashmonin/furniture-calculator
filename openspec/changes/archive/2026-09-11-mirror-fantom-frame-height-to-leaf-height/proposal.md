## Why

Короб «Фантом» (`frame_type`, код `FT-001`) сегодня физически не участвует в оси «Высота» вообще — в каталоге у него нет ни одной `liner_dimension_option`, шаг «Высота» для него в интерфейсе не отображается (список опций пуст), и высота этого короба нигде не фиксируется. Заказчику при этом важно знать высоту короба «Фантом» — она должна всегда совпадать с высотой полотна, которую выбрал клиент (например, полотно 2100 мм → короб «Фантом» 2100 мм), а не выбираться отдельно и не ограничиваться диапазоном заранее заданных каталожных вариантов, как это сделано для коробов «НЕО»/«Компланар».

## What Changes

- Для короба «Фантом» (`FT-001`) высота перестаёт быть недоступной осью и становится обязательной величиной, автоматически равной высоте полотна (`leafHeightValue`) той же конфигурации — без отдельного выбора из каталожного списка и без диапазона допустимых значений (в отличие от «НЕО»/«Компланар», где высота короба выбирается из диапазонных `liner_dimension_option` и ограничена диапазоном высоты полотна).
- Backend: точечно ослабляется существующее ограничение «произвольное значение размера допустимо только для компонента leaf» — конкретно для высоты (`customHeightValueMm`) и конкретно для короба с кодом `FT-001`. Для этого кода высота обязательна и ДОЛЖНА (SHALL) в точности совпадать с высотой полотна той же конфигурации; несовпадение или отсутствие высоты полотна отклоняется ошибкой 400. Выбор `heightOptionId` для этого короба по-прежнему невозможен (у него нет каталожных `liner_dimension_option` — существующая общая проверка принадлежности опции компоненту это уже покрывает, без изменений).
- Цена короба «Фантом» не меняется: как и для «НЕО»/«Компланар», цена короба определяется только цветом (`colour_option`) и позициями `frame_post` — высота на цену не влияет ни до, ни после этого изменения.
- Frontend: для короба «Фантом» вместо каталожного выбора высоты (которого физически нет) отображается высота, авто-вычисленная из уже выбранной высоты полотна (как только высота полотна определена — стандартным вариантом или произвольным значением), в виде информационной строки без интерактивного элемента выбора; выбранная высота полотна передаётся в запрос расчёта стоимости как высота короба напрямую, без участия отдельного состояния выбора пользователя.
- Правило гейтится кодом `frame_type`, а не структурой данных: `FT-001` — единственный код в новом наборе; короба «НЕО»/«Компланар» (`FT-002`, `FT-003`, диапазонное ограничение) и любые другие типы короба поведение не меняют.

## Capabilities

### Modified Capabilities

- `door-configuration-api`: добавляется требование о том, что для короба «Фантом» высота обязательна и должна в точности совпадать с высотой полотна той же конфигурации; точечно расширяется требование «Произвольное значение длины и высоты полотна в запросе расчёта» — произвольное значение высоты становится допустимым также для frame-компонента с кодом `FT-001` (и только для высоты, не для длины).
- `door-configurator-ui`: добавляется требование об автоматическом отображении высоты короба «Фантом», равной уже выбранной высоте полотна, без отдельного интерактивного выбора и без ожидания действий пользователя сверх выбора высоты полотна.

`door-configuration-catalog` не меняется: новых таблиц, колонок или `liner_dimension_option`/`configuration_price` для `FT-001` не добавляется — высота короба «Фантом» не хранится и не выбирается как каталожная опция.

## Impact

- **Backend**: `DoorConfigurationPricingService` — новая константа `HEIGHT_MIRROR_FRAME_TYPE_CODES = Set.of("FT-001")`; точечное исключение в проверке «произвольное значение только для leaf» для `customHeightValueMm` и кода `FT-001`; новая проверка «высота короба должна совпадать с высотой полотна» в ветке `FrameType` (аналогичная по духу существующей `validateHeightWithinLeafRange`, но на точное равенство, а не на диапазон).
- **Frontend**: `frontend/src/App.tsx` — новая константа `HEIGHT_MIRROR_FRAME_TYPE_CODES`; для группы «Высота» короба «Фантом» рендерится информационная строка (не `OptionGroup`) с высотой полотна; при отправке запроса расчёта стоимости для frame-компонента с кодом `FT-001` в `customHeightValueMm` подставляется текущая высота полотна.
- **БД**: без изменений — новых миграций не требуется.
- **Тесты**: `DoorConfigurationPricingServiceTest` — новые кейсы (высота короба «Фантом» совпадает/не совпадает с высотой полотна, высота полотна не выбрана, попытка передать `heightOptionId` для «Фантом» отклоняется как и раньше, цена короба не зависит от высоты).
- Короба «НЕО»/«Компланар» (диапазонное ограничение высоты), кромка, наличники, добор и другие компоненты поведение не меняют.
