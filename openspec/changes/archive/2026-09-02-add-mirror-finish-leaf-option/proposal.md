## Why

Для дверей коллекций Элегант, Гармония, Свобода, Геометрия, Сияние, Сибирь фабрика предлагает исполнение полотна с зеркалом на одной из сторон — три варианта (обычное зеркало, зеркало с фацетом, зеркало серое/бронза), каждый со своей фиксированной наценкой к цене полотна (30% / 40% / 50%). Сейчас в системе нет ни справочника таких исполнений, ни места применить наценку — клиент не может оформить дверь с зеркалом через калькулятор, стоимость приходится досчитывать вручную.

## What Changes

- Добавить справочник исполнений зеркала — плоская таблица (тип исполнения, процент наценки) с тремя строками: «Глухое плоское полотно с зеркалом с одной стороны» (+30%), «Глухое плоское полотно с зеркалом с фацетом с одной стороны» (+40%), «Глухое плоское полотно с зеркалом серое/бронза с одной стороны» (+50%). Отдельно — таблица владения (какие leaf_type допускают исполнение зеркала), заполненная для всех leaf_type коллекций Элегант, Гармония, Свобода, Геометрия, Сияние, Сибирь (все три исполнения доступны одинаково для всех подходящих leaf_type; остальные три коллекции — Вертикаль, Атмосфера, Фантом — зеркало не поддерживают).
- Каталог конфигураций (`GET /api/door-configurations`) отдаёт для leaf-компонента список допустимых исполнений зеркала — аналогично тому, как уже отдаются допустимые цвета и размеры.
- В запросе расчёта стоимости для leaf-компонента добавить необязательное поле — id выбранного исполнения зеркала. Указание его для компонента, отличного от leaf, или ссылка на исполнение, не принадлежащее leaf_type конфигурации, — ошибка 400.
- В математике расчёта наценка за исполнение зеркала применяется последовательно вместе с уже существующими наценками полотна — **после** наценки за высоту и **до** надбавки за реверс: длина → высота → зеркало → реверс, с округлением после каждого шага (тот же принцип, что уже используется для длины/высоты/реверса, см. change `add-dimension-surcharge-rules`).
- Эндпоинт процентов надбавок (`GET /api/pricing-surcharges`, см. change `redesign-door-configurator-flow`) дополняется списком исполнений зеркала с их процентами — фронтенд использует его для разбивки надбавок в результате расчёта («за зеркальное исполнение: +30%» и т. п.), как уже сделано для наценок за размер и реверс.
- Frontend: выбор исполнения зеркала выносится в тот же ряд, что и переключатель «Реверс» — **первый шаг всего потока, до выбора коллекции** (не внутри карточки полотна, вместе с остальными его опциями). Варианты этого шага — три исполнения зеркала (глобально, независимо от коллекции) плюс «Без зеркала» (значение по умолчанию). Выбор конкретного исполнения зеркала сужает последующие шаги потока (в первую очередь — доступные коллекции) до тех, что его поддерживают — по аналогии с тем, как уже сужает переключатель «Реверс»; выбор «Без зеркала» не сужает ничего (зеркало — не обязательный признак самой конфигурации, а необязательная опция подходящего полотна). Изменение исполнения зеркала сбрасывает весь последующий выбор (коллекцию и далее), как и изменение реверса.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `door-configuration-catalog`: новые сущности `mirror_finish_type` (три исполнения зеркала с процентом наценки) и `mirror_finish_option` (владение — какие leaf_type допускают какие исполнения); каталог конфигураций отдаёт допустимые исполнения зеркала для leaf-компонента.
- `door-configuration-api`: запрос расчёта стоимости принимает необязательный выбор исполнения зеркала для leaf; наценка применяется последовательно между наценкой за высоту и надбавкой за реверс; эндпоинт процентов надбавок дополняется списком исполнений зеркала.
- `door-configurator-ui`: выбор исполнения зеркала — первый шаг потока, в одном ряду с переключателем «Реверс», до выбора коллекции; сужает последующие шаги до коллекций, поддерживающих выбранное исполнение; разбивка надбавок в результате расчёта дополняется строкой за зеркало.

## Impact

- **БД**: новый Liquibase changeset — таблицы `mirror_finish_type` (id, code, name, surcharge_percent) и `mirror_finish_option` (id, mirror_finish_type_id, leaf_type_id, unique по паре); начальные данные — 3 исполнения × leaf_type всех подходящих 6 коллекций.
- **Backend**: новые сущности `MirrorFinishType`/`MirrorFinishOption` + репозитории; `ComponentCatalogDto` — новое поле со списком допустимых исполнений зеркала (заполняется только для leaf); `ComponentSelectionDto` — новое опциональное поле id исполнения зеркала; `DoorConfigurationPricingService` — валидация и применение наценки в `applySequentialSurcharges` между высотой и реверсом; `PricingSurchargesDto` — новое поле со списком исполнений зеркала и их процентов.
- **Frontend**: `App.tsx` — новый пред-коллекционный псевдо-шаг выбора исполнения зеркала рядом с реверсом, сужающий каталог; `api/types.ts` — новые поля; разбивка надбавок дополняется строкой за зеркало.
- Контракт запроса `POST /api/door-configurations/{id}/price` расширяется аддитивно новым необязательным полем; существующие поля не меняются.
