## ADDED Requirements

### Requirement: Выбор исполнения зеркала в запросе расчёта
Для leaf-компонента запрос расчёта стоимости МОЖЕТ (MAY) указывать id выбранного исполнения зеркала — id строки mirror_finish_type (тот же id, что и в каталоге, и в ответе эндпоинта получения процентов надбавок; НЕ id строки mirror_finish_option). Указание исполнения зеркала для компонента, отличного от leaf, ДОЛЖНО (SHALL) отклоняться ошибкой 400. Указанный id ДОЛЖЕН (SHALL) ссылаться на mirror_finish_type, для которого существует строка mirror_finish_option, связывающая его с leaf_type данной door_configuration (т.е. исполнение допустимо для этого полотна); иначе — ошибка 400.

#### Scenario: Исполнение зеркала принимается для leaf-компонента
- **WHEN** отправляется запрос расчёта стоимости, где для leaf-компонента указан id исполнения зеркала (mirror_finish_type), допустимого для leaf_type этой конфигурации
- **THEN** запрос обрабатывается, не возвращая ошибку валидации формата запроса

#### Scenario: Исполнение зеркала для компонента, отличного от leaf, недопустимо
- **WHEN** исполнение зеркала указано для frame, edge, doorCasing или frameExtensions
- **THEN** эндпоинт отвечает ошибкой 400 и не выполняет расчёт

#### Scenario: Исполнение зеркала, не принадлежащее полотну конфигурации, недопустимо
- **WHEN** указанный id исполнения зеркала (mirror_finish_type) существует, но для leaf_type данной door_configuration нет строки mirror_finish_option, связывающей его с этим исполнением
- **THEN** эндпоинт отвечает ошибкой 400 и не выполняет расчёт

#### Scenario: Несуществующее исполнение зеркала недопустимо
- **WHEN** указанный id исполнения зеркала не существует ни в одной строке mirror_finish_type
- **THEN** эндпоинт отвечает ошибкой 400 и не выполняет расчёт

### Requirement: Место наценки за исполнение зеркала в последовательности надбавок
Если для leaf-компонента выбрано исполнение зеркала, его наценка ДОЛЖНА (SHALL) применяться к цене leaf-компонента последовательно, вместе с уже существующими наценками (см. «Последовательное применение наценок к цене полотна»), в следующем порядке: (1) наценка за длину; (2) наценка за высоту; (3) наценка за исполнение зеркала; (4) надбавка за реверс (если конфигурация реверсивная) — каждый шаг применяется к результату предыдущего, с округлением после каждого шага. Шаг наценки за зеркало пропускается (не изменяет результат предыдущего шага), если исполнение зеркала не выбрано.

#### Scenario: Наценка за зеркало применяется после высоты и до реверса
- **WHEN** отправляется запрос расчёта стоимости для реверсивной конфигурации, в котором для leaf-компонента указаны произвольное значение высоты, совпадающее с dimension_surcharge_rule, и исполнение зеркала
- **THEN** итоговая цена leaf-компонента вычисляется как: сумма₁ = округление(базовая_цена × (1 + наценка_за_высоту)); сумма₂ = округление(сумма₁ × (1 + наценка_за_зеркало)); итог = округление(сумма₂ × (1 + надбавка_за_реверс))

#### Scenario: Без выбранного исполнения зеркала шаг пропускается
- **WHEN** отправляется запрос расчёта стоимости, в котором для leaf-компонента исполнение зеркала не указано
- **THEN** итоговая цена leaf-компонента вычисляется без шага наценки за зеркало, как и до появления этого требования

### Requirement: Исполнения зеркала в ответе эндпоинта процентов надбавок
Ответ эндпоинта получения процентов надбавок (`GET /api/pricing-surcharges`) ДОЛЖЕН (SHALL), в дополнение к существующим полям, содержать список всех исполнений зеркала (mirror_finish_type) с их id, наименованием и процентом наценки.

#### Scenario: Возвращаются все исполнения зеркала с процентами
- **WHEN** запрашивается эндпоинт получения процентов надбавок
- **THEN** ответ содержит все строки mirror_finish_type с их наименованием и процентом наценки, наряду с уже существующими полями (правила наценки за размер, процент надбавки за реверс)
