## Context

Страница позиции КП (`CommercialOfferService.writePosition`) — таблица из двух ячеек 50/50: слева изображение двери (фиксированная высота 330 pt), справа вложенная таблица характеристик (`specs`). Фурнитура позиции попадает в КП как строки детализации (`DetailRow` «Фурнитура»), которые строятся из `HardwarePriceDto` (категория, тип, цвет, количество, цены) — артикула в них нет. Фото фурнитуры доступны через `HardwareImageCatalog` (change `add-hardware-option-images`): имя файла по артикулу варианта, WebP в ресурсах. Декодирование WebP для PDF уже работает для дверей (`loadDoorImage`: ImageIO + перекодирование в JPEG).

## Goals / Non-Goals

**Goals:**
- Фото фурнитуры позиции в правой колонке под характеристиками, одна страница на позицию как прежде.

**Non-Goals:**
- Подписи под фото, фото в Excel-выгрузке, фото в корзине; изменение таблицы комплектации.

## Decisions

**1. Артикул пробрасывается через `HardwarePriceDto` → `DetailRow`.** `DoorConfigurationPricingService` уже знает выбранный `HardwareOption` при сборке `HardwarePriceDto`; в запись добавляется `article` (null, если не задан), `DetailRow` получает то же поле (null для не-фурнитуры). Альтернатива — искать вариант по `(type, colourName)` в `CommercialOfferService`: лишние запросы и неоднозначность при одинаковых названиях цветов. Поле в ответе `/api/hardware/price` необязательное — фронтенд и расчёты не затрагиваются.

**2. Подбор фото — в `CommercialOfferService`.** По строкам «Фурнитура» собираются уникальные артикулы (с сохранением порядка строк), для каждого `HardwareImageCatalog.findFileName` + ресурс. Нужен метод получения `Resource` по артикулу (небольшое расширение каталога, `findResource` уже есть по имени файла). Загрузка/перекодирование — общий с дверью код (`loadDoorImage` переименовывается в нейтральный `loadImage`).

**3. Вёрстка.** Правая ячейка верхней таблицы содержит `specs` и, ниже с отступом, вложенную таблицу сетки фото: 2 колонки, ячейка — миниатюра со вписыванием в ячейку высотой ~105 pt, без границ. Не более 6 фото на позицию (2×3), чтобы верхний блок не превышал высоту двери и позиция не сдвигала таблицу комплектации; остальные не выводятся (редкий случай). Блок добавляется только при наличии хотя бы одного фото. Альтернатива — отдельная полоса фото под верхним блоком на всю ширину: не соответствует просьбе «справа от двери сразу после описания модели».

**4. Устойчивость.** Ошибка чтения отдельного фото логируется и пропускает только его (как у двери).

## Risks / Trade-offs

- Много видов фурнитуры → фото не помещаются в высоту двери → лимит 6 и миниатюры ~105 pt; при необходимости лимит/размер подправить после визуальной проверки PDF.
- Артикул нужен фурнитуре из старых прайс-листов («Эмаль и шпон»): артикула нет → фото нет, блок не выводится — ожидаемо.
- Одинаковые фото разных цветов (общее фото модели) могут дублироваться визуально → допустимо; дедупликация только по артикулу.

## Migration Plan

Миграций БД нет. Откат — удаление блока фото и поля `article`; остальное КП не затрагивается.
