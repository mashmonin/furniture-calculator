## ADDED Requirements

### Requirement: Выбор вида остекления в запросе расчёта
Для leaf-компонента запрос расчёта стоимости МОЖЕТ (MAY) указывать id выбранного вида остекления — id строки glazing_type (тот же id, что и в каталоге, и в ответе эндпоинта получения процентов надбавок; НЕ id строки glazing_option). Указание вида остекления для компонента, отличного от leaf, ДОЛЖНО (SHALL) отклоняться ошибкой 400. Указанный id ДОЛЖЕН (SHALL) ссылаться на glazing_type, для которого существует строка glazing_option, связывающая его с leaf_type данной door_configuration (т.е. вид остекления допустим для этого полотна); иначе — ошибка 400.

#### Scenario: Вид остекления принимается для leaf-компонента
- **WHEN** отправляется запрос расчёта стоимости, где для leaf-компонента указан id вида остекления (glazing_type), допустимого для leaf_type этой конфигурации
- **THEN** запрос обрабатывается, не возвращая ошибку валидации формата запроса

#### Scenario: Вид остекления для компонента, отличного от leaf, недопустим
- **WHEN** вид остекления указан для frame, edge, doorCasing или frameExtensions
- **THEN** эндпоинт отвечает ошибкой 400 и не выполняет расчёт

#### Scenario: Вид остекления, не принадлежащий полотну конфигурации, недопустим
- **WHEN** указанный id вида остекления (glazing_type) существует, но для leaf_type данной door_configuration нет строки glazing_option, связывающей его с этим видом остекления
- **THEN** эндпоинт отвечает ошибкой 400 и не выполняет расчёт

#### Scenario: Несуществующий вид остекления недопустим
- **WHEN** указанный id вида остекления не существует ни в одной строке glazing_type
- **THEN** эндпоинт отвечает ошибкой 400 и не выполняет расчёт

### Requirement: Место наценки за вид остекления в последовательности надбавок
Если для leaf-компонента выбран вид остекления, его наценка (surcharge_percent соответствующего glazing_type) ДОЛЖНА (SHALL) применяться к цене leaf-компонента последовательно, вместе с уже существующими надбавками (см. «Последовательное применение наценок к цене полотна», «Место наценки за исполнение зеркала в последовательности надбавок»), в следующем порядке: (1) наценка за длину; (2) наценка за высоту; (3) наценка за исполнение зеркала (если выбрано); (4) наценка за вид остекления (если выбран); (5) надбавка за реверс (если конфигурация реверсивная) — каждый шаг применяется к результату предыдущего, с округлением после каждого шага. Шаг наценки за вид остекления пропускается (не изменяет результат предыдущего шага), если вид остекления не выбран, а также если выбранный вид остекления — «Прозрачное» (его surcharge_percent равен нулю).

#### Scenario: Наценка за вид остекления применяется после исполнения зеркала и до реверса
- **WHEN** отправляется запрос расчёта стоимости для реверсивной конфигурации, в котором для leaf-компонента указаны произвольное значение высоты, совпадающее с dimension_surcharge_rule, и вид остекления с ненулевой наценкой
- **THEN** итоговая цена leaf-компонента вычисляется как: сумма₁ = округление(базовая_цена × (1 + наценка_за_высоту)); сумма₂ = округление(сумма₁ × (1 + наценка_за_остекление)); итог = округление(сумма₂ × (1 + надбавка_за_реверс))

#### Scenario: Без выбранного вида остекления шаг пропускается
- **WHEN** отправляется запрос расчёта стоимости, в котором для leaf-компонента вид остекления не указан
- **THEN** итоговая цена leaf-компонента вычисляется без шага наценки за остекление, как и до появления этого требования

#### Scenario: Базовое «Прозрачное» остекление не добавляет наценку
- **WHEN** для leaf-компонента указан id вида остекления «Прозрачное» (surcharge_percent = 0)
- **THEN** итоговая цена leaf-компонента вычисляется так же, как если бы вид остекления не был указан вовсе

### Requirement: Виды остекления в ответе эндпоинта процентов надбавок
Ответ эндпоинта получения процентов надбавок (`GET /api/pricing-surcharges`) ДОЛЖЕН (SHALL), в дополнение к существующим полям, содержать список всех видов остекления (glazing_type) с их id, наименованием и процентом наценки.

#### Scenario: Возвращаются все виды остекления с процентами
- **WHEN** запрашивается эндпоинт получения процентов надбавок
- **THEN** ответ содержит все строки glazing_type с их наименованием и процентом наценки, наряду с уже существующими полями (правила наценки за размер, процент надбавки за реверс, исполнения зеркала)
