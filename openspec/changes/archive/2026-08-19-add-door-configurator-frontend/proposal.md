## Why

Backend уже отдаёт каталог допустимых конфигураций дверей (`GET /api/door-configurations`) и умеет рассчитывать стоимость по выбору (`POST /api/door-configurations/{id}/price`), но у фронтенда пока нет ничего, кроме дефолтного шаблона Vite — эти эндпоинты нечем протестировать и показать вживую. Нужен минимальный UI, который позволяет пройти весь путь: выбрать конфигурацию, выбрать опции по каждому её компоненту и увидеть рассчитанную стоимость.

## What Changes

- Заменить дефолтную страницу Vite (`frontend/src/App.tsx`) на минимальный мастер-поток из трёх шагов на одном экране:
  1. Загрузка каталога конфигураций (`GET /api/door-configurations`) и динамическая отрисовка кнопок — по одной кнопке на каждую `door_configuration` из ответа.
  2. После выбора конфигурации — динамическая отрисовка групп кнопок для каждого присутствующего в ней компонента (leaf и, если заданы, frame/edge/doorCasing/frameExtensions): по группе кнопок на каждую ось размера (длина/высота/толщина, если есть допустимые значения) и на цвет (если есть допустимые цвета), с выбором ровно одного значения в группе.
  3. Кнопка «Рассчитать стоимость», которая отправляет текущий выбор в `POST /api/door-configurations/{id}/price` и показывает итоговую розничную и дилерскую цену вместе с разбивкой по компонентам, включая компоненты, для которых цена не найдена.
- Настроить проксирование `/api` с dev-сервера Vite на backend (`http://localhost:8080`), чтобы фронтенд обращался к бэкенду по относительному пути без CORS-хлопот в разработке.
- Только UI поверх уже существующих эндпоинтов — новых эндпоинтов и изменений backend/схемы БД это предложение не требует.

## Capabilities

### New Capabilities
- `door-configurator-ui`: минимальный веб-интерфейс для выбора допустимой конфигурации двери, выбора опций её компонентов и расчёта стоимости через существующее REST API.

### Modified Capabilities
(нет — существующий API `door-configuration-api` не меняется, фронтенд только потребляет его)

## Impact

- **Frontend**: замена содержимого `frontend/src/App.tsx` (и, при необходимости, вспомогательных компонентов/хуков рядом) на конфигуратор; правка `frontend/vite.config.ts` для dev-прокси на backend. UI — только компоненты `antd`.
- **Backend**: не затрагивается.
- **API**: не затрагивается, используются существующие `GET /api/door-configurations` и `POST /api/door-configurations/{id}/price`.
- **База данных**: не затрагивается.
