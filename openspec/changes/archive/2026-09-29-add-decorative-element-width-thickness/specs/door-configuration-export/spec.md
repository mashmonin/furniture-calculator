## MODIFIED Requirements

### Requirement: Содержимое строки спецификации
Каждая строка раздела 1–3 (полотно, кромка, короб, позиции состава короба, наличник, добор) ДОЛЖНА (SHALL) содержать полное наименование компонента (`name` выбранного типа — без сокращения до `short_name`, в отличие от отображения в интерфейсе калькулятора), итоговую и базовую (до применения наценок) розничную и дилерскую цену, рассчитанные теми же правилами (включая надбавки), что и в соответствующем этапном эндпоинте расчёта стоимости, — и, где для этого компонента применимо, значения его размеров в мм (длина и/или высота и/или толщина — в зависимости от того, какие из них применимы для этого типа компонента, включая высоту короба, если она выбирается из каталога или зеркалируется от высоты полотна, — объединённые в одно значение через ` × `, например `900 × 2400 × 44`) и выбранный цвет, если он выбран. Для строки полотна, если для него установлен признак двусторонней покраски и выбраны оба цвета (фронтальный и задний), ячейка цвета ДОЛЖНА (SHALL) содержать оба наименования, объединённые через ` / ` (фронтальный слева, задний справа, например «Белый / Другой цвет из коллекции RAL и NCS»); если выбран только один из двух цветов (либо двусторонняя покраска не выбрана), ячейка цвета содержит наименование этого одного цвета, как и до этого изменения. Строки раздела «Декоративные элементы» ДОЛЖНЫ (SHALL) содержать наименование самого decorative_element_type (без наименования его категории — в отличие от строк фурнитуры ниже), его размеры в мм в столбце размеров (длина всегда, а ширина и/или толщина — если они заданы у типа, объединённые с длиной через ` × ` в порядке длина-ширина-толщина, тем же способом, что и у прочих компонентов выше; если ширина и толщина не заданы — только длина, как и до этого изменения), количество и цену (розничную и дилерскую) с учётом количества — как в ответе `POST /api/decorative-elements/price`; ячейка цвета для них всегда пуста (у decorative_element_type нет цвета). Строки раздела «Фурнитура» ДОЛЖНЫ (SHALL) содержать наименование категории и типа фурнитуры, цветовой вариант, количество и цену (розничную и дилерскую) с учётом количества — как в ответе `POST /api/hardware/price`; у фурнитуры, у декоративных элементов и у позиций состава короба базовая цена всегда совпадает с итоговой (наценки к ним не применяются). Если для строки не найдена цена (нет подходящей строки цены для указанного типа), строка ДОЛЖНА (SHALL) присутствовать в файле с прочерком вместо цены (в обеих парах колонок — базовой и итоговой), а не быть пропущена.

#### Scenario: Строка полотна содержит размеры, цвет и цену
- **WHEN** для полотна в запросе указаны длина, высота и цвет, и для них найдена цена
- **THEN** строка полотна в файле содержит наименование модели полотна, объединённые размеры в мм, наименование цвета и раздельно итоговую (с учётом применённых надбавок) и базовую розничную и дилерскую цену

#### Scenario: Двусторонняя покраска показывает оба цвета в одной ячейке
- **WHEN** для полотна в запросе установлен признак двусторонней покраски и указаны фронтальный и задний цвет
- **THEN** строка полотна в файле содержит оба наименования цвета в ячейке цвета, объединённые через « / »

#### Scenario: Двусторонняя покраска с одним указанным цветом показывает только его
- **WHEN** для полотна в запросе установлен признак двусторонней покраски, но указан только фронтальный (или только задний) цвет
- **THEN** ячейка цвета строки полотна содержит наименование только этого одного цвета

#### Scenario: Высота короба показывается, если применима
- **WHEN** короб в запросе — из числа выбирающих высоту из каталога либо зеркалирующих её от высоты полотна
- **THEN** строка короба в файле содержит эту высоту в мм

#### Scenario: Компонент без применимого размера не показывает размеры
- **WHEN** строка соответствует компоненту, для которого размер не применим (например, короб без выбираемой высоты)
- **THEN** ячейка размеров этой строки остаётся пустой, а не содержит нулевые или произвольные значения

#### Scenario: Ненайденная цена отображается прочерком
- **WHEN** для выбранных опций компонента не найдено подходящей строки цены
- **THEN** строка этого компонента присутствует в файле, а ячейки базовой и итоговой цены содержат прочерк вместо числа

#### Scenario: Позиция фурнитуры содержит категорию, тип, цвет и количество
- **WHEN** запрос содержит позицию фурнитуры с количеством больше 1
- **THEN** строка фурнитуры в файле содержит наименование категории и типа фурнитуры, цветовой вариант, указанное количество и цену с учётом количества

#### Scenario: Позиция декоративного элемента содержит категорию, тип, длину и количество
- **WHEN** запрос содержит позицию декоративного элемента, у типа которого не заданы width_mm и thickness_mm (например, плинтус), с количеством больше 1
- **THEN** строка декоративного элемента в файле содержит наименование типа (без категории), длину в мм в столбце размеров, пустую ячейку цвета, указанное количество и цену с учётом количества

#### Scenario: Позиция декоративного элемента с шириной и толщиной показывает объединённые размеры
- **WHEN** запрос содержит позицию декоративного элемента, у типа которого заданы length_mm, width_mm и thickness_mm (например, «Блок А» — 90/90/30)
- **THEN** столбец размеров строки декоративного элемента содержит `90 × 90 × 30` — длину, ширину и толщину, объединённые через ` × ` в этом порядке
