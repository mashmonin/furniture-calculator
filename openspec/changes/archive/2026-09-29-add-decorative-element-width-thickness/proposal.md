## Why

У decorative_element_type сейчас есть только одна геометрическая характеристика — длина (length_mm). Для позиций категории «Блок и база» (`DEC-002`: «Блок А», «База А», «Блок В», «База В», «База В КОМПЛАНАР») фабрика также ведёт ширину и толщину — их негде хранить.

## What Changes

- В decorative_element_type добавляются два новых необязательных поля: width_mm и thickness_mm (nullable — не у всех типов, например у плинтуса, есть эти размеры).
- Заполняются значения для пяти существующих типов категории «Блок и база»:
  - «Блок А» — ширина 90 мм, толщина 30 мм
  - «База А» — ширина 90 мм, толщина 30 мм
  - «Блок В» — ширина 91 мм, толщина 30 мм
  - «База В» — ширина 91 мм, толщина 31 мм
  - «База В КОМПЛАНАР» — ширина 91 мм, толщина 31 мм
- Для «Плинтус Модо» и «Плинтус Модо облегчённый» width_mm/thickness_mm остаются NULL — у категории «Плинтус» таких размеров не ведётся.
- Каталог-эндпоинт (`/api/decorative-elements-catalog`) и UI конфигуратора эти поля по-прежнему не показывают. Но выгрузка (спецификация и заказ целиком) теперь показывает полный размер декоративного элемента: если у типа заданы width_mm и/или thickness_mm, колонка «Измерения, мм» объединяет длину, ширину и толщину через ` × ` (например, «90 × 90 × 30» для «Блок А»), тем же способом, что уже используется для полотна/короба (длина-высота-толщина). Для типов без width_mm/thickness_mm (плинтус) колонка по-прежнему показывает только длину.
- Разделитель измерений в выгрузке меняется с `*` на ` × ` не только для декоративных элементов, а для всех размеров во всех разделах (полотно, короб, наличник) — это общий форматирующий хелпер, и разделитель должен быть единым по всему файлу; например, «900*2400*44» становится «900 × 2400 × 44».

## Capabilities

### New Capabilities
_(нет)_

### Modified Capabilities
- `decorative-element-catalog`: у decorative_element_type появляются необязательные width_mm и thickness_mm; заданы значения для пяти типов категории «Блок и база».
- `door-configuration-export`: колонка «Измерения, мм» декоративного элемента в выгрузке спецификации показывает длину × ширину × толщину, если ширина/толщина заданы у типа, иначе только длину; разделитель измерений во всех разделах файла меняется с `*` на ` × `.
- `order-export-api`: строка декоративного элемента в разворачиваемой детализации позиции заказа показывает те же объединённые измерения, тем же разделителем ` × `.

## Impact

- Backend: новый Liquibase changeset — `addColumn` (width_mm, thickness_mm, nullable) в decorative_element_type + `update` значений для DET-003…DET-007. Domain-класс `DecorativeElementType` получает два новых nullable-поля. `DecorativeElementPriceDto` прокидывает widthMm/thicknessMm дальше в расчёт стоимости; `SpecificationExportService` форматирует их вместе с length_mm через уже существующий хелпер `formatDimensions` (длина × ширина × толщина, пропуская отсутствующие) — использован в обоих местах, где строится строка декоративного элемента (детализация под строкой заказа и раздел «Декоративные элементы» спецификации). Этот же хелпер используется и для полотна/короба/наличника, поэтому смена разделителя применяется ко всему файлу выгрузки, а не только к декоративным элементам.
- Frontend: изменений нет — формат выгрузки (Excel) меняется только на backend.
- Данные: значения ширины/толщины — по значениям, указанным пользователем.
