## Why

Каталог согласованных конфигураций дверей (`door_configuration`) и цены на компоненты (`configuration_price`) уже есть в базе данных, но никакого API поверх них нет — весь backend пока состоит только из точки входа Spring Boot приложения. Фронтенду и другим клиентам нужен способ узнать, какие конфигурации допустимы, и рассчитать стоимость изделия по выбранным опциям (модель полотна, коробка, наличники/добор, удлинители, размеры, цвет).

## What Changes

- Добавить `GET`-эндпоинт, возвращающий все допустимые конфигурации двери (`door_configuration`) вместе с допустимыми для каждого их компонента размерами (`liner_dimension_option`) и цветами (`colour_option`), чтобы клиент мог построить форму выбора опций.
- Добавить `POST`-эндпоинт расчёта стоимости изделия: клиент передаёт id выбранной `door_configuration` и для каждого присутствующего в ней компонента (leaf/frame/edge/door_casing/frame_extensions) — id выбранных `liner_dimension_option` (длина/высота/толщина, где применимо) и `colour_option`. Эндпоинт для каждого компонента ищет наиболее специфичную подходящую строку `configuration_price` (чем больше совпавших не-NULL размерных/цветовых ссылок, тем выше приоритет), суммирует `retail_price` и `dealer_price` найденных строк и возвращает итоговую сумму, разбивку по компонентам и список компонентов, для которых подходящая цена не найдена (частичный расчёт вместо ошибки).
- Ввести JPA-сущности и репозитории поверх существующих таблиц item-configuration-schema/door-configuration-catalog (`door_configuration`, `liner_dimension_option`, `colour_option`, `configuration_price`, соответствующие `*_type` справочники) — первый Java-код поверх схемы БД в этом проекте.
- Изменений схемы БД (Liquibase) это предложение не требует — используются уже существующие таблицы.

## Capabilities

### New Capabilities
- `door-configuration-api`: REST API для получения каталога допустимых конфигураций дверей (со связанными опциями размеров и цветов) и для расчёта стоимости изделия по выбранной конфигурации и опциям.

### Modified Capabilities
(нет — таблицы и их инварианты, описанные в `item-configuration-schema` и `door-configuration-catalog`, не меняются)

## Impact

- **Backend**: новый код в `backend/src/main/java/com/example/furniturecalculator/` — JPA-сущности, репозитории (Spring Data), сервисы и REST-контроллеры для каталога конфигураций и расчёта цены. Подключение `spring-boot-starter-data-jpa` уже есть в `build.gradle`.
- **API**: два новых публичных REST-эндпоинта (JSON), без затрагивания существующих (их пока нет).
- **База данных**: изменений не требуется, используются существующие таблицы из changelog'ов `0001`–`0009`.
- **Frontend**: не затрагивается в рамках этого изменения (эндпоинты создаются для последующего использования UI).
