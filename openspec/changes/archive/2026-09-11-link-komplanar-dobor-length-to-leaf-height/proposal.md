## Why

Длина добора «КОМПЛАНАР» (`frame_extensions_type`, коды `FET-008`–`FET-013`, ширины 100/140/190/400/600/800 мм) физически зависит от высоты полотна — по тому же принципу, что и длина добора «ТС» (`link-dobor-ts-length-to-leaf-height`): одному диапазону высоты полотна соответствует одна допустимая длина, а для части диапазонов добор вообще недоступен. Сейчас в каталоге у всех шести ширин добора «КОМПЛАНАР» есть только одна опция длины (2170 мм, без диапазона), без привязки к высоте полотна, поэтому клиент может собрать физически невозможную конфигурацию.

## What Changes

- Backend: уже обобщённое правило «длина обязательна + совместима с диапазоном высоты полотна» (`requireLengthWithinLeafRange`) распространяется на добор «КОМПЛАНАР» — множество `LENGTH_RANGE_FRAME_EXTENSIONS_TYPE_CODES` расширяется кодами `FET-008`–`FET-013` (к уже входящим `FET-004`–`FET-007` добора «ТС»). Сообщение об обязательности длины обобщается с «для добора «ТС» необходимо выбрать длину» на «для этого добора необходимо выбрать длину» — по аналогии с уже обобщённым сообщением для наличников (`link-modo-onda-casing-length-to-leaf-height`); поведение для добора «ТС» не меняется, меняется только текст сообщения.
- Для добора «КОМПЛАНАР» длина становится обязательной и ограничивается диапазоном высоты полотна:
  - 1900–2100 → длина 2170 мм (все 6 ширин)
  - 2150–2250 → длина 2400 мм (все 6 ширин)
  - 2300 (точка) → длина 2400 мм (все 6 ширин)
  - 2350–2550 → длина 2700 мм (все 6 ширин)
  - 2600–2850 → длина 2950 мм для ширин 400/600/800 (`FET-011`, `FET-012`, `FET-013`); длина 3000 мм для ширин 100/140/190 (`FET-008`, `FET-009`, `FET-010`)
  - 2900–2950 → добор «КОМПЛАНАР» недоступен (опций нет), все 6 ширин
  - Высота полотна вне перечисленных диапазонов (например, 2101–2149, 2251–2299, 2551–2599, 2851–2899, от 2951) не покрывается ни одной опцией длины — как и для добора «ТС»/наличников, это означает недоступность добора при такой высоте (ошибка валидации при расчёте, исчезновение из каскада на фронтенде), а не отдельный особый случай.
- Новая Liquibase-миграция: единственная существующая опция длины (value=2170, без диапазона) для каждого из 6 кодов переиспользуется под первый диапазон (диапазон [1900, 2100], значение не меняется — уже равно 2170); добавляются новые опции длины по правилам выше — три диапазона (2150–2250, 2300, 2350–2550) одинаковы для всех 6 кодов, диапазон 2600–2850 — раздельно для двух групп ширин со своим значением длины. Уникальный индекс `uk_liner_dimension_option_frame_extensions_type` уже расширен диапазонными колонками в `link-dobor-ts-length-to-leaf-height` (миграция 0065) — менять не требуется.
- Цена добора «КОМПЛАНАР» перестаёт зависеть от выбранной длины — по тому же принципу, что и добор «ТС» (длина только гейтит допустимость выбора, а не формирует цену; текущие строки `configuration_price` ссылаются на length_option_id единственной существующей опции — без обнуления этой ссылки после появления новых опций длины расчёт с любой длиной, кроме исходной 2170, перестал бы находить цену). Новая миграция обнуляет `length_option_id` в существующих строках `configuration_price` для этих 6 кодов.
- Frontend: список доступных длин добора «КОМПЛАНАР» фильтруется по высоте полотна через уже обобщённые `lengthRangeOptions`/`lengthRangeCoversHeight` (переименовывается только константа `DOBOR_TS_FRAME_EXTENSIONS_TYPE_CODES` → осе-нейтральное `LENGTH_RANGE_FRAME_EXTENSIONS_TYPE_CODES`, состав расширяется шестью новыми кодами); выбор длины сбрасывается при смене высоты полотна; добор исключается из каскадного выбора, если высота полотна уже выбрана и не покрывается ни одним диапазоном длины этого конкретного добора.
- Правило гейтится исключительно кодом `frame_extensions_type`, без проверки короба: в сегодняшнем каталоге коды `FET-008`–`FET-013` встречаются только в связке с коробом «Компланар» (`FT-002`, включая конфигурации с `is_reverse = true`) — короб определяет, какой добор доступен, а не наоборот; правило по-прежнему применяется по коду добора, как и для добора «ТС».

### Modified Capabilities

- `door-configuration-api`: добавляется требование о совместимости диапазона длины добора «КОМПЛАНАР» с высотой полотна и требование об обязательности длины для этого добора — по аналогии с уже существующими требованиями для добора «ТС». Точечно корректируются существующие требования для добора «ТС» («Совместимость диапазона длины добора «ТС» с высотой полотна», «Обязательность длины для добора «ТС»») — их сценарии, использующие добор «КОМПЛАНАР» как пример типа ВНЕ диапазонного набора, перестают быть верны и заменяются на актуальный пример (после этого изменения оба реально достижимых семейства добора — «ТС» и «КОМПЛАНАР» — входят в диапазонный набор).
- `door-configurator-ui`: добавляется требование об условной фильтрации длины добора «КОМПЛАНАР» по высоте полотна и об исключении его из каскада при несовместимой высоте полотна — по аналогии с уже существующим требованием для добора «ТС».

`door-configuration-catalog` не меняется на уровне спецификации: требования «Атрибуты liner_dimension_option» и «Структура configuration_price» уже сформулированы универсально для любого владельца и оси — новые данные и обнуление `length_option_id` укладываются в уже описанное поведение без изменения текста требований.

## Impact

- **Backend**: `DoorConfigurationPricingService` — расширение константы `LENGTH_RANGE_FRAME_EXTENSIONS_TYPE_CODES` шестью новыми кодами (`FET-008`–`FET-013`); обобщение текста сообщения об обязательности длины (было специфично для добора «ТС»).
- **БД**: обновление существующих строк `liner_dimension_option` (диапазон [1900, 2100] для value=2170) и `configuration_price` (`length_option_id = NULL`) для 6 кодов добора «КОМПЛАНАР»; новые строки `liner_dimension_option` под диапазоны 2150–2250, 2300, 2350–2550 (все 6 кодов) и 2600–2850 (раздельно по значению для двух групп ширин).
- **Frontend**: `frontend/src/App.tsx` — переименование `DOBOR_TS_FRAME_EXTENSIONS_TYPE_CODES` → `LENGTH_RANGE_FRAME_EXTENSIONS_TYPE_CODES` (обновление всех использований), расширение состава кодов; остальной код (`lengthRangeOptions`, `lengthRangeCoversHeight`, фильтрация каскада, сброс выбора) переиспользуется без изменений.
- **Тесты**: `DoorConfigurationPricingServiceTest` — новые кейсы по аналогии с кейсами добора «ТС», включая проверку разных допустимых длин для двух групп ширин добора «КОМПЛАНАР» (100/140/190 против 400/600/800) в диапазоне 2600–2850, точки 2300, разрыва между диапазонами, обязательности длины; регрессия для существующих тестов добора «ТС» (обновлённое сообщение об ошибке, если оно проверяется явно, — иначе без изменений).
- Наличники, короба «НЕО»/«Компланар» (высота) и другие компоненты поведение не меняют.
