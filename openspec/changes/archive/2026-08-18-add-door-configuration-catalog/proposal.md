## Why

Калькулятору нужно знать, какие межкомнатные двери фабрика вообще может произвести — какие сочетания типов полотна/коробки/кромки/добора/удлинителей согласованы, и какие размеры и цвета допустимы для каждого из этих типов, — ещё до того, как пользователь начинает собирать конкретный заказ. Существующая схема `item-configuration-schema` хранит только фактические экземпляры (`item`, `leaf`, `frame`, ...) с их конкретными размерами и цветом; она остаётся как есть для будущего хранения реальных заказов, но не подходит для хранения самого каталога допустимых вариантов — там нет понятия «эта комбинация типов вообще существует» или «для этой модели полотна допустимы вот такие размеры».

## What Changes

- Новая таблица `door_configuration` — согласованная с фабрикой связка типов компонентов одной двери: обязательный `leaf_type`, и опциональные `frame_type`, `edge_type`, `door_casing_type`, `frame_extensions_type`. Если `door_casing_type` или `frame_extensions_type` заданы, `frame_type` тоже обязателен (добор/удлинитель не существуют без коробки — как и в текущей схеме экземпляров, где они принадлежат `frame`).
- Одна и та же комбинация типов не может быть занесена в каталог дважды.
- Новая таблица `liner_dimension_option` — каталог допустимых значений размера (по `liner_dimension_type`: длина/высота/толщина) для типа компонента (`leaf_type`, `frame_type`, `edge_type`, `door_casing_type` или `frame_extensions_type`). Списки размеров по разным `liner_dimension_type` независимы друг от друга (не хранятся как связанные тройки).
- Новая таблица `colour_option` — каталог допустимых `colour_type` для типа компонента, по тому же принципу владения, что и `liner_dimension_option`.
- Ценообразование и логика самого расчёта («что происходит при нажатии рассчитать») в это изменение не входят.
- Наполнение каталога реальными данными (конкретные конфигурации, размеры, цвета для моделей ВЕРТИКАЛЬ и др.) — отдельная задача после того, как эта схема будет реализована.

## Capabilities

### New Capabilities
- `door-configuration-catalog`: каталог согласованных с фабрикой комбинаций типов компонентов межкомнатной двери и допустимых для каждого типа размеров/цветов — отдельно от хранения фактических экземпляров и заказов.

## Impact

- Новый Liquibase changeset в `backend/src/main/resources/db/changelog/changes/` (createTable × 3 + CHECK-констрейнты single-owner + уникальные индексы), подключённый в `db.changelog-master.yaml`.
- Существующая схема `item-configuration-schema` (item/leaf/frame/edge/...) не меняется.
- Java-слой (entity/repository/controller) пока не существует в проекте — этот changeset готовит только схему БД.
