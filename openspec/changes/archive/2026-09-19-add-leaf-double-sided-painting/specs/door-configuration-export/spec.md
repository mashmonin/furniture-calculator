## MODIFIED Requirements

### Requirement: Эндпоинт выгрузки спецификации
Система ДОЛЖНА (SHALL) предоставлять эндпоинт `POST /api/specification/export`, принимающий: id существующего `leaf_type` (обязательно) с его опциями (размеры, цвет — включая, опционально, второй (задний) цвет и признак двусторонней покраски, исполнение зеркала, вид остекления); опционально — id вида кромки с её опциями, явный признак реверса, id короба с его опциями, id наличника с его опциями, id добора с его опциями, значение высоты полотна (для диапазонных проверок короба/наличника/добора — как в этапном расчёте короба и обрамления), список позиций фурнитуры. Состав и правила валидации этих полей ДОЛЖНЫ (SHALL) быть теми же, что и у существующих этапных эндпоинтов расчёта стоимости (`POST /api/leaf-types/{id}/price`, `POST /api/frame-types/{id}/price`, `POST /api/hardware/price`) — те же коды ошибок (404 для несуществующего `leaf_type`/`frame_type`, 400 для недопустимых или чужих id опций, включая задний цвет без установленного признака двусторонней покраски и задний цвет, не принадлежащий указанному `leaf_type`).

#### Scenario: Запрос без обязательного leaf_type отклоняется
- **WHEN** отправляется запрос без указания id `leaf_type` или с id, которого не существует
- **THEN** эндпоинт отвечает ошибкой 404 и не генерирует файл

#### Scenario: Недопустимая опция отклоняется так же, как в расчёте стоимости
- **WHEN** в запросе id выбранной опции (размер, цвет — фронтальный или задний, кромка, наличник, добор) ссылается на компонент, отличный от указанного, либо не существует
- **THEN** эндпоинт отвечает ошибкой 400 и не генерирует файл — тем же кодом и по тем же условиям, что и соответствующий этапный эндпоинт расчёта

#### Scenario: Минимальный запрос — только полотно
- **WHEN** отправляется запрос с указанием только id `leaf_type` (без кромки, короба, наличника, добора и фурнитуры)
- **THEN** эндпоинт возвращает файл, содержащий только раздел «Полотно и опции полотна»

### Requirement: Содержимое строки спецификации
Каждая строка раздела 1–3 (полотно, кромка, короб, позиции состава короба, наличник, добор) ДОЛЖНА (SHALL) содержать полное наименование компонента (`name` выбранного типа — без сокращения до `short_name`, в отличие от отображения в интерфейсе калькулятора), итоговую и базовую (до применения наценок) розничную и дилерскую цену, рассчитанные теми же правилами (включая надбавки), что и в соответствующем этапном эндпоинте расчёта стоимости, — и, где для этого компонента применимо, значения его размеров в мм (длина и/или высота и/или толщина — в зависимости от того, какие из них применимы для этого типа компонента, включая высоту короба, если она выбирается из каталога или зеркалируется от высоты полотна, — объединённые в одно значение через `*`, например `900*2400*44`) и выбранный цвет, если он выбран. Для строки полотна, если для него установлен признак двусторонней покраски и выбраны оба цвета (фронтальный и задний), ячейка цвета ДОЛЖНА (SHALL) содержать оба наименования, объединённые через ` / ` (фронтальный слева, задний справа, например «Белый / Другой цвет из коллекции RAL и NCS»); если выбран только один из двух цветов (либо двусторонняя покраска не выбрана), ячейка цвета содержит наименование этого одного цвета, как и до этого изменения. Строки раздела 4 (фурнитура) ДОЛЖНЫ (SHALL) содержать наименование категории и типа фурнитуры, цветовой вариант, количество и цену (розничную и дилерскую) с учётом количества — как в ответе `POST /api/hardware/price`; у фурнитуры и у позиций состава короба базовая цена всегда совпадает с итоговой (наценки к ним не применяются). Если для строки не найдена цена (нет подходящей `configuration_price`), строка ДОЛЖНА (SHALL) присутствовать в файле с прочерком вместо цены (в обеих парах колонок — базовой и итоговой), а не быть пропущена.

#### Scenario: Строка полотна содержит размеры, цвет и цену
- **WHEN** для полотна в запросе указаны длина, высота и цвет, и для них найдена цена
- **THEN** строка полотна в файле содержит наименование модели полотна, объединённые размеры в мм, наименование цвета и раздельно итоговую (с учётом применённых надбавок) и базовую розничную и дилерскую цену

#### Scenario: Двусторонняя покраска показывает оба цвета в одной ячейке
- **WHEN** для полотна в запросе установлен признак двусторонней покраски и указаны фронтальный и задний цвет
- **THEN** строка полотна в файле содержит оба наименования цвета в ячейке цвета, объединённые через « / »

#### Scenario: Двусторонняя покраска с одним указанным цветом показывает только его
- **WHEN** для полотна в запросе установлен признак двусторонней покраски, но указан только фронтальный (или только задний) цвет
- **THEN** ячейка цвета строки полотна содержит наименование только этого одного цвета

#### Scenario: Высота короба показывается, если применима
- **WHEN** короб в запросе — из числа выбирающих высоту из каталога либо зеркалирующих её от высоты полотна
- **THEN** строка короба в файле содержит эту высоту в мм

#### Scenario: Компонент без применимого размера не показывает размеры
- **WHEN** строка соответствует компоненту, для которого размер не применим (например, короб без выбираемой высоты)
- **THEN** ячейка размеров этой строки остаётся пустой, а не содержит нулевые или произвольные значения

#### Scenario: Ненайденная цена отображается прочерком
- **WHEN** для выбранных опций компонента не найдено подходящей строки `configuration_price`
- **THEN** строка этого компонента присутствует в файле, а ячейки базовой и итоговой цены содержат прочерк вместо числа

#### Scenario: Позиция фурнитуры содержит категорию, тип, цвет и количество
- **WHEN** запрос содержит позицию фурнитуры с количеством больше 1
- **THEN** строка фурнитуры в файле содержит наименование категории и типа фурнитуры, цветовой вариант, указанное количество и цену с учётом количества

### Requirement: Надбавки к цене полотна в файле
Если к цене полотна применена хотя бы одна надбавка (за нестандартную длину/высоту, исполнение зеркала, вид остекления, реверс, двусторонняя покраска), файл ДОЛЖЕН (SHALL) содержать отдельный завершающий раздел «Надбавки к цене полотна» — под всеми разделами компонентов, а не внутри раздела полотна — с отдельной строкой на каждую применённую надбавку: наименованием и процентом, теми же формулировками, что и в разбивке «Надбавки к цене полотна» результата расчёта на фронте (в том числе строка «За двустороннюю покраску», если она применена). У строки надбавки нет собственной цены (сама надбавка уже учтена в цене строки полотна) — ячейки цены и размеров ДОЛЖНЫ (SHALL) оставаться пустыми, не содержать прочерк (прочерк означает именно ненайденную цену компонента, а не неприменимость поля). Раздел ДОЛЖЕН (SHALL) НЕ содержать строку заголовков колонок (Наименование/Измерения/Цвет/Количество/цены), применимую к разделам с компонентами, — она не несёт смысла для строк, у которых есть только наименование и процент; строки надбавок идут сразу за заголовком раздела.

#### Scenario: Применённые надбавки перечислены в завершающем разделе
- **WHEN** к цене полотна применены надбавка за нестандартный размер и надбавка за реверс
- **THEN** под всеми разделами компонентов файл содержит раздел «Надбавки к цене полотна» с двумя строками — по одной на каждую надбавку, с её названием и процентом

#### Scenario: Надбавка за двустороннюю покраску показана в завершающем разделе
- **WHEN** для полотна установлен признак двусторонней покраски
- **THEN** раздел «Надбавки к цене полотна» содержит строку «За двустороннюю покраску» с применённым процентом, наряду с прочими применёнными надбавками (за цвет, размер, исполнение зеркала, остекление, реверс)

#### Scenario: Без надбавок завершающий раздел отсутствует
- **WHEN** к цене полотна не применена ни одна надбавка
- **THEN** файл не содержит раздела «Надбавки к цене полотна»
