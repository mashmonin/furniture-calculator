## MODIFIED Requirements

### Requirement: Наценка за выбранный цвет полотна
Если для leaf-компонента выбран colour_option (фронтальный цвет), чей colour_type имеет ненулевой surcharge_percent, система ДОЛЖНА (SHALL) применить этот процент как наценку к цене leaf-компонента. Если для этого же leaf-компонента установлен признак двусторонней покраски (см. «Второй цвет и признак двусторонней покраски полотна в запросе расчёта») и указан задний colour_option, чей colour_type тоже имеет ненулевой surcharge_percent, система ДОЛЖНА (SHALL) сложить проценты наценки фронтального и заднего цвета и применить результат как единую наценку одним шагом — а не последовательно перемножать множители каждой стороны друг на друга. Если наценку даёт только одна из двух сторон (при двусторонней покраске), либо единственный выбранный цвет (без двусторонней покраски), наценка равна проценту этой стороны — без изменений по сравнению с прежним поведением. Если ни фронтальный, ни (при двусторонней покраске) задний цвет не дают наценки, либо цвет для leaf-компонента не выбран вовсе, шаг наценки за цвет пропускается, не изменяя цену.

#### Scenario: Выбран цвет с ненулевой наценкой
- **WHEN** отправляется запрос расчёта стоимости, в котором для leaf-компонента (без двусторонней покраски) выбран colour_option, ссылающийся на colour_type с surcharge_percent = 20 (например, «Другой цвет из коллекции RAL и NCS»)
- **THEN** к цене leaf-компонента применяется наценка 20%

#### Scenario: Выбран цвет без наценки
- **WHEN** отправляется запрос расчёта стоимости, в котором для leaf-компонента выбран colour_option, ссылающийся на colour_type с surcharge_percent = 0
- **THEN** цена leaf-компонента вычисляется без наценки за цвет, как и до появления этого требования

#### Scenario: Цвет не выбран
- **WHEN** отправляется запрос расчёта стоимости, в котором для leaf-компонента цвет не указан
- **THEN** цена leaf-компонента вычисляется без шага наценки за цвет

#### Scenario: Двусторонняя покраска — наценки за оба цвета суммируются, а не перемножаются
- **WHEN** отправляется запрос расчёта стоимости, в котором для leaf-компонента установлен признак двусторонней покраски, фронтальный цвет ссылается на colour_type с surcharge_percent = 20, а задний цвет — на другой colour_type, тоже с surcharge_percent = 20
- **THEN** к цене leaf-компонента на шаге наценки за цвет применяется единая наценка 40% (20% + 20%), а не 44%, которые дало бы последовательное умножение множителей 1.2 × 1.2

#### Scenario: Двусторонняя покраска — наценку даёт только одна сторона
- **WHEN** отправляется запрос расчёта стоимости, в котором для leaf-компонента установлен признак двусторонней покраски, фронтальный цвет ссылается на colour_type с surcharge_percent = 20, а задний цвет — на colour_type с surcharge_percent = 0
- **THEN** к цене leaf-компонента на шаге наценки за цвет применяется наценка 20%, как если бы двусторонняя покраска не была выбрана

#### Scenario: Двусторонняя покраска — ни одна сторона не даёт наценки
- **WHEN** отправляется запрос расчёта стоимости, в котором для leaf-компонента установлен признак двусторонней покраски, а оба выбранных цвета (фронтальный и задний) ссылаются на colour_type с surcharge_percent = 0
- **THEN** шаг наценки за цвет пропускается, не изменяя цену (надбавка за саму двустороннюю покраску, см. «Наценка за двустороннюю покраску полотна», при этом всё равно применяется)

## ADDED Requirements

### Requirement: Второй цвет и признак двусторонней покраски полотна в запросе расчёта
Для leaf-компонента запрос расчёта стоимости МОЖЕТ (MAY) указывать признак двусторонней покраски (булево значение) и, независимо от него, id второго (заднего) colour_option — в дополнение к уже существующему id цвета этого компонента (см. «Допустимые опции размеров и цвета для каждого компонента конфигурации»), который при этом трактуется как цвет фронтальной стороны. Задний цвет учитывается в расчёте (см. «Наценка за выбранный цвет полотна») только если признак двусторонней покраски установлен в true; если признак не установлен или равен false, а задний цвет указан, эндпоинт ДОЛЖЕН (SHALL) отклонить запрос ошибкой 400. Указание заднего цвета или признака двусторонней покраски для компонента, отличного от leaf, ДОЛЖНО (SHALL) отклоняться ошибкой 400. Указанный id заднего цвета, если он передан, ДОЛЖЕН (SHALL) ссылаться на colour_option, принадлежащий leaf_type данной door_configuration, — по тому же правилу, что и для фронтального цвета; иначе — ошибка 400. Признак двусторонней покраски, установленный без указанного заднего цвета, допустим: наценка за двустороннюю покраску (см. «Наценка за двустороннюю покраску полотна») всё равно применяется, а наценка за цвет учитывает только фронтальную сторону.

#### Scenario: Двусторонняя покраска с обоими цветами принимается
- **WHEN** отправляется запрос расчёта стоимости, где для leaf-компонента установлен признак двусторонней покраски, указан фронтальный цвет и задний цвет, оба принадлежащие leaf_type этой конфигурации
- **THEN** запрос обрабатывается, не возвращая ошибку валидации формата запроса

#### Scenario: Задний цвет без двусторонней покраски отклоняется
- **WHEN** отправляется запрос расчёта стоимости, где для leaf-компонента указан задний цвет, но признак двусторонней покраски не установлен (или равен false)
- **THEN** эндпоинт отвечает ошибкой 400 и не выполняет расчёт

#### Scenario: Двусторонняя покраска или задний цвет для компонента, отличного от leaf, недопустимы
- **WHEN** признак двусторонней покраски или задний цвет указаны для frame, edge, doorCasing или frameExtensions
- **THEN** эндпоинт отвечает ошибкой 400 и не выполняет расчёт

#### Scenario: Задний цвет, не принадлежащий полотну конфигурации, недопустим
- **WHEN** отправляется запрос расчёта стоимости с установленным признаком двусторонней покраски, в котором id заднего цвета ссылается на colour_option, принадлежащий типу компонента, отличному от leaf_type этой конфигурации (либо не существует)
- **THEN** эндпоинт отвечает ошибкой 400 и не выполняет расчёт

#### Scenario: Двусторонняя покраска без указанного заднего цвета допустима
- **WHEN** отправляется запрос расчёта стоимости, где для leaf-компонента установлен признак двусторонней покраски, указан только фронтальный цвет (или цвет не указан вовсе), а задний цвет не передан
- **THEN** запрос обрабатывается: наценка за цвет учитывает только фронтальную сторону, а надбавка за двустороннюю покраску применяется

### Requirement: Наценка за двустороннюю покраску полотна
Если для leaf-компонента установлен признак двусторонней покраски (см. «Второй цвет и признак двусторонней покраски полотна в запросе расчёта») в true, система ДОЛЖНА (SHALL) применить к цене leaf-компонента дополнительную надбавку 50% — независимо от того, выбраны ли цвета (фронтальный и/или задний) и дают ли они собственную наценку за цвет (см. «Наценка за выбранный цвет полотна»). Эта надбавка не отменяет и не заменяет наценку за выбранный цвет — обе применяются одновременно, если применимы. Если признак двусторонней покраски не установлен (или false), шаг этой надбавки пропускается, не изменяя цену.

#### Scenario: Двусторонняя покраска без выбранных цветов всё равно даёт надбавку
- **WHEN** отправляется запрос расчёта стоимости, в котором для leaf-компонента установлен признак двусторонней покраски, а фронтальный и задний цвет не выбраны
- **THEN** к цене leaf-компонента применяется надбавка 50%

#### Scenario: Надбавка за двустороннюю покраску сочетается с наценкой за цвет
- **WHEN** отправляется запрос расчёта стоимости, в котором для leaf-компонента установлен признак двусторонней покраски и выбран фронтальный цвет с ненулевой наценкой
- **THEN** к цене leaf-компонента применяются и наценка за цвет, и надбавка 50% за двустороннюю покраску — ни одна из них не отменяет другую

#### Scenario: Без двусторонней покраски надбавка не применяется
- **WHEN** отправляется запрос расчёта стоимости, в котором для leaf-компонента признак двусторонней покраски не установлен
- **THEN** цена leaf-компонента вычисляется без шага надбавки за двустороннюю покраску, как и до появления этого требования

### Requirement: Место надбавки за двустороннюю покраску в последовательности надбавок
Надбавка за двустороннюю покраску полотна (см. «Наценка за двустороннюю покраску полотна») ДОЛЖНА (SHALL) применяться к цене leaf-компонента последовательно, вместе с уже существующими наценками (см. «Последовательное применение наценок к цене полотна», «Место наценки за исполнение зеркала в последовательности надбавок», «Место наценки за вид остекления в последовательности надбавок», «Место наценки за цвет в последовательности надбавок»), в следующем порядке: (1) наценка за длину; (2) наценка за высоту; (3) наценка за цвет (если применяется — с учётом суммирования по фронтальной и задней стороне при двусторонней покраске, см. «Наценка за выбранный цвет полотна»); (4) надбавка за двустороннюю покраску (если применяется); (5) наценка за исполнение зеркала (если выбрано); (6) наценка за вид остекления (если выбран); (7) надбавка за реверс (если конфигурация реверсивная) — каждый шаг применяется к результату предыдущего, с округлением после каждого шага.

#### Scenario: Надбавка за двустороннюю покраску применяется после цвета и до исполнения зеркала
- **WHEN** отправляется запрос расчёта стоимости для реверсивной конфигурации, в котором для leaf-компонента указаны цвет с ненулевой наценкой, признак двусторонней покраски и исполнение зеркала
- **THEN** итоговая цена leaf-компонента вычисляется как: сумма₁ = округление(базовая_цена × (1 + наценка_за_цвет)); сумма₂ = округление(сумма₁ × (1 + 0.5)); сумма₃ = округление(сумма₂ × (1 + наценка_за_зеркало)); итог = округление(сумма₃ × (1 + надбавка_за_реверс))

### Requirement: Надбавка за двустороннюю покраску в ответе эндпоинта процентов надбавок
Ответ эндпоинта получения процентов надбавок (`GET /api/pricing-surcharges`) ДОЛЖЕН (SHALL), в дополнение к существующим полям, содержать процент надбавки за двустороннюю покраску полотна, применяемый при расчёте стоимости (см. «Наценка за двустороннюю покраску полотна»).

#### Scenario: Возвращается процент надбавки за двустороннюю покраску
- **WHEN** запрашивается эндпоинт получения процентов надбавок
- **THEN** ответ содержит процент надбавки за двустороннюю покраску, наряду с уже существующими полями (правила наценки за размер, процент надбавки за реверс, исполнения зеркала, виды остекления, цвета)

#### Scenario: Значение совпадает с фактически применяемым при расчёте
- **WHEN** запрашивается эндпоинт получения процентов надбавок
- **THEN** возвращённый процент надбавки за двустороннюю покраску равен проценту, который `POST /api/door-configurations/{id}/price` фактически применяет к цене leaf-компонента с установленным признаком двусторонней покраски
