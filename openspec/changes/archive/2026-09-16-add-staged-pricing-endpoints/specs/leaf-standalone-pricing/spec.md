## MODIFIED Requirements

### Requirement: Расчёт стоимости отдельного полотна по его типу
Система ДОЛЖНА (SHALL) предоставлять эндпоинт расчёта стоимости, принимающий id существующего `leaf_type` и набор выбранных клиентом опций полотна: id `liner_dimension_option` для длины и высоты (либо произвольное значение для соответствующей оси, как и при расчёте по `door_configuration`), id `colour_option`, id `mirror_finish_type`, id `glazing_type`, явный признак реверса (булево значение; отсутствие ДОЛЖНО (SHALL) трактоваться как false) — и, независимо от полотна, список позиций фурнитуры. Дополнительно эндпоинт МОЖЕТ (MAY) принимать id вида кромки (`edge_type`) и опции кромки (id `liner_dimension_option` для высоты, id `colour_option`) — кромка считается и добавляется в разбивку результата наравне с полотном. Указанный id `edge_type` ДОЛЖЕН (SHALL) ссылаться на вид кромки, для которого существует хотя бы одна строка `door_configuration` с этим `leaf_type` и этим `edge_type` (т.е. кромка допустима для этого полотна, независимо от короба/наличника/добора этой строки); иначе — ошибка 400. Короб, наличник и добор эндпоинтом не рассматриваются, даже если присутствуют в запросе (см. frame-group-standalone-pricing).

#### Scenario: Расчёт стоимости полотна без дополнительных опций
- **WHEN** отправляется запрос расчёта с id существующего `leaf_type` без выбранных опций размеров, цвета, исполнения зеркала, вида остекления и кромки
- **THEN** эндпоинт возвращает результат с найденной (если есть подходящая строка `configuration_price`) или не найденной ценой полотна, без ошибки

#### Scenario: Несуществующий тип полотна
- **WHEN** отправляется запрос расчёта с id `leaf_type`, которого не существует
- **THEN** эндпоинт отвечает ошибкой 404 и не выполняет расчёт

#### Scenario: Опция не принадлежит указанному полотну
- **WHEN** в запросе id выбранной `liner_dimension_option` или `colour_option` ссылается на компонент, отличный от указанного `leaf_type`
- **THEN** эндпоинт отвечает ошибкой 400 и не выполняет расчёт

#### Scenario: Надбавки за размер и исполнение зеркала применяются так же, как при расчёте по конфигурации
- **WHEN** в запросе указано произвольное значение длины или высоты полотна, совпадающее с правилом наценки, и/или id допустимого для этого полотна исполнения зеркала, и/или (см. добавленную наценку за остекление) id допустимого для этого полотна вида остекления
- **THEN** итоговая цена полотна включает соответствующие надбавки, рассчитанные по тем же правилам и в том же порядке, что и в расчёте стоимости по `door_configuration`

#### Scenario: Надбавка за реверс применяется по явному признаку в запросе
- **WHEN** в запросе передан явный признак реверса со значением true
- **THEN** к цене полотна применяется та же надбавка за реверс, что и при расчёте по `door_configuration` с `is_reverse = true`, по тем же правилам последовательного применения надбавок

#### Scenario: Без явного признака реверса надбавка не применяется
- **WHEN** в запросе признак реверса не передан либо передан со значением false
- **THEN** к цене полотна надбавка за реверс не применяется

#### Scenario: Признак реверса не влияет на расчёт по door_configuration
- **WHEN** признак реверса передан в запросе к эндпоинту расчёта по `door_configuration` (а не к расчёту отдельного полотна)
- **THEN** он игнорируется — надбавка за реверс для этого эндпоинта по-прежнему определяется исключительно значением `is_reverse` самой `door_configuration`

#### Scenario: Позиции фурнитуры учитываются так же, как при расчёте по конфигурации
- **WHEN** запрос содержит одну или несколько позиций фурнитуры (см. hardware-catalog)
- **THEN** их стоимость рассчитывается и суммируется с ценой полотна так же, как при расчёте стоимости по `door_configuration`

#### Scenario: Кромка принимается и считается вместе с полотном
- **WHEN** в запросе указан id вида кромки, для которого существует door_configuration с этим leaf_type и этим edge_type, и (опционально) её опции цвета и высоты
- **THEN** запрос обрабатывается без ошибки валидации формата запроса, и кромка учитывается в расчёте по тем же правилам, что и при расчёте по door_configuration (включая проверку высоты кромки в диапазоне высоты полотна)

#### Scenario: Без указанного вида кромки кромка не считается
- **WHEN** в запросе id вида кромки не указан
- **THEN** расчёт выполняется без кромки, как и до появления этой возможности — в разбивке результата запись о кромке отсутствует

#### Scenario: Кромка, недопустимая для указанного полотна, отклоняется
- **WHEN** указанный id вида кромки существует, но не существует ни одной строки door_configuration с этим leaf_type и этим edge_type
- **THEN** эндпоинт отвечает ошибкой 400 и не выполняет расчёт

#### Scenario: Несуществующий вид кромки недопустим
- **WHEN** указанный id вида кромки не существует ни в одной строке edge_type
- **THEN** эндпоинт отвечает ошибкой 400 и не выполняет расчёт

### Requirement: Состав ответа расчёта стоимости отдельного полотна
Ответ эндпоинта расчёта стоимости отдельного полотна ДОЛЖЕН (SHALL) иметь тот же состав, что и ответ расчёта стоимости по `door_configuration`: итоговую розничную и дилерскую цену (полотно, опциональная кромка и фурнитура вместе), разбивку с записью для полотна (найденная цена либо отметка, что не найдена), разбивку для кромки (если её id был указан в запросе; найденная цена либо отметка, что не найдена) и разбивку по позициям фурнитуры.

#### Scenario: Успешный расчёт полотна с фурнитурой
- **WHEN** для указанного `leaf_type` найдена подходящая цена, и запрос содержит позиции фурнитуры
- **THEN** ответ содержит итоговую сумму (цена полотна плюс сумма позиций фурнитуры), запись о цене полотна и разбивку по каждой позиции фурнитуры

#### Scenario: Полотно без найденной цены
- **WHEN** для указанного `leaf_type` и выбранных опций не найдено подходящей строки `configuration_price`
- **THEN** эндпоинт отвечает кодом 200, запись о полотне в разбивке отмечена как без найденной цены, а итоговая сумма учитывает только фурнитуру (если она есть)

#### Scenario: Успешный расчёт полотна с кромкой
- **WHEN** в запросе указан допустимый id вида кромки, и для него найдена подходящая цена
- **THEN** ответ содержит запись о цене кромки в разбивке, а итоговая сумма включает цену кромки наравне с ценой полотна

#### Scenario: Кромка без найденной цены
- **WHEN** в запросе указан допустимый id вида кромки, но для выбранных опций не найдено подходящей строки `configuration_price`
- **THEN** эндпоинт отвечает кодом 200, запись о кромке в разбивке отмечена как без найденной цены, а итоговая сумма не включает цену кромки
