## MODIFIED Requirements

### Requirement: Каскадный выбор компонента конфигурации
Система ДОЛЖНА (SHALL) проводить пользователя через последовательность шагов выбора по типам компонентов в порядке: полотно (leaf) → короб (frame) → наличник (doorCasing) → кромка (edge) → удлинители (frameExtensions). Для каждого шага, кроме первого, набор предлагаемых вариантов ДОЛЖЕН (SHALL) ограничиваться значениями этого типа компонента, встречающимися среди door_configuration, согласованных со всеми выборами, сделанными на предыдущих шагах — а не полным справочником данного типа компонента.

Если среди текущих согласованных door_configuration часть содержит этот тип компонента, а часть — нет (присутствие компонента не одинаково для всех согласованных конфигураций), система ДОЛЖНА (SHALL) наравне с реальными вариантами предложить явный дополнительный вариант «без этого компонента». Выбор этого варианта сужает согласованные конфигурации до тех, где компонент отсутствует, точно так же, как выбор конкретного варианта сужает их до конфигураций с этим значением.

#### Scenario: Первый шаг показывает все модели полотна
- **WHEN** каталог загружен и пользователь ещё не сделал ни одного выбора
- **THEN** шаг выбора полотна показывает все модели leaf_type, встречающиеся хотя бы в одной door_configuration

#### Scenario: Второй шаг ограничен выбранным полотном
- **WHEN** пользователь выбрал модель полотна
- **THEN** шаг выбора короба показывает только те frame_type, что встречаются в door_configuration с этим leaf_type

#### Scenario: Третий шаг ограничен полотном и коробом
- **WHEN** пользователь выбрал модель полотна и короб
- **THEN** шаг выбора наличника показывает только те door_casing_type, что встречаются в door_configuration с этой парой leaf_type и frame_type

#### Scenario: Выбор на шаге можно изменить
- **WHEN** пользователь нажимает на другой вариант того же шага, отличный от ранее выбранного
- **THEN** выбор этого шага заменяется на новый, а этот вариант отображается как выбранный вместо предыдущего

#### Scenario: Часть конфигураций без компонента предлагает явный вариант «без»
- **WHEN** среди согласованных door_configuration для текущего частичного выбора есть конфигурации с заданным типом компонента (например, frame_extensions_type) и конфигурации без него
- **THEN** шаг этого компонента показывает реальные варианты и дополнительный вариант «без <компонента>»

#### Scenario: Выбор «без компонента» продолжает каскад
- **WHEN** пользователь нажимает на вариант «без <компонента>»
- **THEN** согласованные конфигурации сужаются до тех, где этот компонент отсутствует, а каскад продолжается на следующий применимый шаг

#### Scenario: Все конфигурации без компонента не предлагают выбор
- **WHEN** ни одна согласованная door_configuration для текущего частичного выбора не содержит этот тип компонента
- **THEN** шаг этого компонента не отображается вовсе (см. требование «Скрытие неприменимого шага»), вариант «без <компонента>» не показывается отдельно от скрытого шага
