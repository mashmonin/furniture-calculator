## Why

Для наличников «Модо» (`DoorCasingType`, код `DCT-003`) и «Онда» (`DCT-004`) длина физически зависит от выбранной высоты полотна — по тому же принципу, что и длина добора «ТС» (`2026-09-09-link-dobor-ts-length-to-leaf-height`): одному диапазону высоты полотна соответствует ровно одна допустимая длина наличника, а для некоторых диапазонов высоты полотна наличники «Модо»/«Онда» вообще недоступны. Сейчас в каталоге у обоих типов наличника есть только одна опция длины (2100 мм, на оси «Длина» — см. `2026-09-09-general-fixes-leaf-step-colour-casing-length`, перенёсший наличник на эту ось) без какой-либо привязки к высоте полотна, поэтому клиент может собрать физически невозможную конфигурацию.

## What Changes

- Backend: правило «длина компонента ограничена диапазоном высоты полотна» (`validateHeightWithinLeafRange`, уже обобщённое по оси в `link-dobor-ts-length-to-leaf-height`) распространяется на `DoorCasingType` с кодом из набора `DCT-003`, `DCT-004`. Общий (не-`FrameType`) код проверки «обязательность длины + диапазон», сейчас дублирующийся для добора «ТС», выносится в приватный метод и переиспользуется для наличников «Модо»/«Онда» — без изменения поведения для добора «ТС».
- Для наличников «Модо» и «Онда» (`DoorCasingType` с кодом из набора `DCT-003`, `DCT-004`) длина становится обязательной и ограничивается диапазоном высоты полотна:
  - 1900–2100 → длина 2250 мм
  - 2150–2250 → длина 2400 мм
  - 2300 (точка) → длина 2700 мм
  - 2350–2550 → длина 2700 мм
  - 2600–2850 и 2900–2950 → наличники «Модо»/«Онда» недоступны (опций нет)
- Новая Liquibase-миграция: единственная существующая опция длины (value=2100, без диапазона) для `DCT-003`/`DCT-004` переиспользуется под первый диапазон (`min_value=1900, max_value=2100`, `value` меняется на 2250); добавляются новые опции для value=2400 (диапазон [2150, 2250]), value=2700 (диапазон-точка [2300, 2300]) и value=2700 (диапазон [2350, 2550]) — по одной на каждый из 2 кодов.
- Существующий уникальный индекс `uk_liner_dimension_option_door_casing_type` расширяется дополнительными колонками диапазона (по аналогии с индексами короба «НЕО» и добора «ТС»), чтобы разрешить две опции наличника с одинаковой длиной (2700 мм), но непересекающимися диапазонами высоты полотна (2300–2300 и отдельно 2350–2550).
- Цена наличников «Модо»/«Онда» перестаёт зависеть от выбранной длины — по тому же принципу, что и цена добора «ТС» (длина только гейтит допустимость выбора). Новая миграция обнуляет `length_option_id` в существующих строках `configuration_price` для `DCT-003`/`DCT-004`.
- Frontend: список доступных длин наличников «Модо»/«Онда» фильтруется по высоте полотна (переиспользуется уже обобщённая геометрия диапазона, введённая для добора «ТС»), выбор длины сбрасывается при смене высоты полотна; наличники «Модо»/«Онда» дополнительно исключаются из списка доступных типов наличника на шаге каскадного выбора, если высота полотна уже выбрана и не покрывается ни одним их диапазоном длины (аналог исключения добора «ТС»/короба «НЕО» из каскада).
- Правило применяется одинаково ко всем конфигурациям, где доступны наличники «Модо»/«Онда» (гейтится кодом `DoorCasingType`, а не конкретной комбинацией короба/коллекции/leaf_type — в каталоге сегодня это исключительно конфигурации с коробом «НЕО», `FT-003`, но правило не привязывается к этому факту явно).

### Modified Capabilities

- `door-configuration-api`: добавляется требование о совместимости диапазона длины наличников «Модо»/«Онда» с высотой полотна и требование об обязательности длины для этих наличников (по аналогии с существующими требованиями для добора «ТС»).
- `door-configurator-ui`: добавляется требование об условной фильтрации длины наличников «Модо»/«Онда» по высоте полотна и исключении их из каскада при несовместимой высоте полотна (по аналогии с существующим требованием для добора «ТС»).

`door-configuration-catalog` не меняется на уровне спецификации: требования «Атрибуты liner_dimension_option» и «Структура configuration_price» уже сформулированы универсально для любого владельца и оси — новые данные наличников «Модо»/«Онда» и обнуление `length_option_id` укладываются в уже описанное поведение без изменения текста требований (тот же вывод, что и для `door-configuration-catalog` в `link-dobor-ts-length-to-leaf-height`).

## Impact

- **Backend**: `DoorConfigurationPricingService` — новая константа `LENGTH_RANGE_DOOR_CASING_TYPE_CODES`; общий код «обязательная длина + диапазон» (сейчас — блок для `FrameExtensionsType`) выносится в приватный метод и переиспользуется для `DoorCasingType` с кодом из этого набора.
- **БД**: обновление существующих строк `liner_dimension_option` (value 2100→2250, диапазон) и `configuration_price` (`length_option_id = NULL`) для `DCT-003`/`DCT-004`; новые строки `liner_dimension_option` для value=2400 и value=2700 (×2); изменение уникального индекса `uk_liner_dimension_option_door_casing_type` (+ H2/desktop-параллельная миграция).
- **Frontend**: `frontend/src/App.tsx` — переименование `doborTsLengthOptions`/`doborTsCoversHeight` в осе-нейтральные `lengthRangeOptions`/`lengthRangeCoversHeight` (переиспользуются и для добора «ТС», и для наличников «Модо»/«Онда»); новая константа `LENGTH_RANGE_DOOR_CASING_TYPE_CODES`; фильтрация длины наличника, сброс выбора при смене высоты полотна, исключение из каскада — расширение существующего двухпроходного `buildCascadeSteps`.
- **Тесты**: `DoorConfigurationPricingServiceTest` — новые кейсы по аналогии с кейсами добора «ТС»; `TestEntities` — новый оверлоад `doorCasingType(id, code)` по аналогии с `frameExtensionsType(id, code)`.
- Остальные наличники (`DCT-001`, `DCT-002`, `DCT-005`–`DCT-009`), добор «ТС»/«КОМПЛАНАР» и другие компоненты не меняют поведение.
