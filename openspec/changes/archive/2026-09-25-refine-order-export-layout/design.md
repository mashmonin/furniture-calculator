## Context

См. proposal.md — Why. `OrderLineExportRequestDto` (frontend `api/types.ts` и backend `dto/`) уже передаёт `displayName` — отображаемое, вычисленное на фронте значение, которому backend доверяет без пересчёта (не цена, не влияет на расчёт). `CartItem.attributeTags` (см. change add-cart-configuration-attribute-tags, уже архивирован) уже хранит нужный список тегов в том же виде, в каком он показывается в столбце «Конфигурация» на экране корзины.

## Goals / Non-Goals

**Goals:**
- Теги в файле заказа визуально совпадают с тегами атрибутов на экране корзины, без дублирования логики их вычисления на backend.
- Итоговая строка листа — компактная, ровно три ячейки.

**Non-Goals:**
- Backend не валидирует и не пересчитывает `attribute_tags` по каталогу — они полностью доверяются фронтенду, тем же принципом, что и `displayName`.
- Не переносится вычисление тегов на backend (например, через анализ `SpecificationComponents`) — усложнило бы код без выгоды, раз фронтенд их уже вычисляет и хранит.
- Фиксированные теги сервиса/вида изделия («ЭМАЛЬ И ШПОН», «МЕЖКОМНАТНАЯ ДВЕРЬ») в файл не добавляются — решение уже зафиксировано в proposal.md.

## Decisions

- **`attributeTags: string[]`/`List<String> attributeTags`** — новое опциональное поле `OrderLineExportRequestDto` (и фронтенд, и backend), по умолчанию пустой список, если отсутствует в запросе (обратная совместимость со старыми клиентами/уже открытыми вкладками, не требующая версионирования API).
- **Формат ячейки**: `displayName` + (если теги не пусты) `" — " + String.join(", ", tags)`. Тире выбрано как визуальный разделитель между «что это» (модель) и «чем она примечательна» (атрибуты), запятая — между самими тегами, тем же принципом, что и построчный текст в разбивке результата на фронте (`ComponentBreakdownList`, где похожие уточнения идут через отдельные текстовые фрагменты).
- **Стиль ячеек**: ячейка наименования (`row.createCell(1)`) в `OrderExportService.writeConfigurationRow` больше не получает `mainRowStyle` (жирный, 12pt) — остаётся с обычным стилем книги по умолчанию; ячейка «№» (`row.createCell(0)`) стиль не меняет. Итоговая строка заказа: `mainRowStyle` (или отдельный `boldStyle` без увеличенного размера — на усмотрение реализации) применяется только к ячейке с текстом «Итого по заказу», ячейки сумм — без стиля.
- **Порядок и позиция ячеек итоговой строки**: три ячейки подряд, начиная с колонки A (индексы 0, 1, 2) — «Итого по заказу», дилерская сумма, клиентская сумма — независимо от того, что колонки 0/1/2 в остальных строках листа означают «№»/«Конфигурация»/«Параметры»; последняя строка не следует общей раскладке колонок, это отдельная сводная строка (решение зафиксировано, а не открытый вопрос).

## Risks / Trade-offs

- [Клиент (уже открытая вкладка со старым кодом) отправляет запрос без `attribute_tags`] → Поле опционально с значением по умолчанию — пустой список, файл формируется как раньше (просто без тегов в ячейке), без ошибки.
