## Why

Для короба «Компланар» (`FrameType`, код `FT-002`) высота короба, как и для уже реализованного короба «НЕО» (`2026-09-05-link-frame-neo-height-to-leaf-height`), физически зависит от выбранной высоты полотна: одному диапазону высоты полотна соответствует ровно одна допустимая высота короба, а для одного диапазона высоты полотна («дыры» между определёнными диапазонами) короб «Компланар» вообще недоступен. Механизм для этого уже есть в системе (диапазон [min_value, max_value] у `liner_dimension_option`, валидация на бэкенде, условная фильтрация на фронтенде) — этот change переносит его на второй тип короба, не дублируя логику под каждый код заново.

## What Changes

- Механизм «диапазон высоты полотна ограничивает доступную высоту компонента», сейчас жёстко завязанный на код `FT-003` (короб «НЕО»), обобщается на набор кодов коробов, для которых это правило действует. В набор добавляется `FT-002` (короб «Компланар»); поведение для `FT-003` не меняется.
- Новая Liquibase-миграция с диапазонами высоты полотна → высота короба «Компланар» (владелец — тот же `frame_type_id` = id `FT-002`, ось высоты `DT-002`):
  - 1900–2100 → 2170 мм
  - 2150–2250 → 2400 мм
  - 2300 (точка) → 2400 мм
  - 2350–2550 → 2700 мм
  - 2600–2850 → 3000 мм
  - 2900–2950 → короб «Компланар» недоступен (опций нет)
- В отличие от короба «НЕО», у «Компланар» диапазон 2600–2850 **покрыт** (маппится на высоту 3000 мм) — недоступен только диапазон 2900–2950. Механизм уже поддерживает произвольное число диапазонов на тип короба, поэтому дополнительных изменений в логике не требуется — только данные.
- Правило действует для короба «Компланар» независимо от модели полотна и независимо от признака `is_reverse` конфигурации — короб «Компланар» используется и в обычных, и в реверсивных `door_configuration`, а проверка выполняется по коду `frame_type`, не по `leaf_type`/`is_reverse`.
- Backend: высота становится обязательной для frame-компонента и с кодом `FT-002` (по аналогии с уже действующим правилом для `FT-003`) — без выбранной высоты для диапазона 2900–2950 расчёт с этим коробом невозможен ни при каком запросе.
- Frontend: условная фильтрация группы «Высота» и исключение типа короба из каскада при несовместимой высоте полотна (уже реализованные для «НЕО») распространяются и на «Компланар».

### Modified Capabilities

- `door-configuration-api`: существующие требования «Совместимость диапазона высоты короба «НЕО» с высотой полотна» и «Обязательность высоты для короба «НЕО»» обобщаются на список кодов коробов (включая `FT-002`), либо дополняются аналогичными требованиями для `FT-002` — формулировка уточняется в specs.
- `door-configurator-ui`: аналогично обобщаются существующие требования «Условное отображение высоты короба «НЕО» по высоте полотна» и «Исключение короба «НЕО» из каскада при несовместимой высоте полотна».

## Impact

- **Backend**: `DoorConfigurationPricingService` — обобщение проверки кода типа короба (константа `NEO_FRAME_TYPE_CODE` заменяется/дополняется набором кодов, требующих диапазонной валидации высоты).
- **БД**: новая Liquibase-миграция с данными высоты короба «Компланар» (`frame_type_id` = id `FT-002`). Схема (`max_value`, уникальный индекс) не меняется — уже подготовлена предыдущим change.
- **Frontend**: `frontend/src/App.tsx` — обобщение фильтрации высоты и исключения из каскада на список кодов коробов вместо одного `FT-003`.
- **Тесты**: `DoorConfigurationPricingServiceTest` — новые кейсы для `FT-002` по аналогии с кейсами `FT-003`, включая кейс с реверсивной `door_configuration`.
- Короб «Фантом» (`FT-001`) и уже реализованное поведение для короба «НЕО» (`FT-003`) не меняются.
