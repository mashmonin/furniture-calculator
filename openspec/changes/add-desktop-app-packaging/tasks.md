## 4. Упаковка и идентификация версий

- [x] 4.1 Таск `desktopJlinkRuntime` в `backend/build.gradle` — `jlink` с набором модулей (`java.base`, `java.desktop`, `java.sql`, `javafx.controls`, `javafx.web` и т.д.; список подобран эмпирически — `jdeps` на полном дереве зависимостей Spring Boot давал противоречивые/неполные результаты из-за конфликтов автоматических модулей, поэтому взят заведомо достаточный набор и проверен реальным запуском). Итоговый runtime — 104 МБ. JavaFX-модули берутся из maven-jar'ов JavaFX (не из отдельного jmods-дистрибутива) — jlink принимает их напрямую как module-path.
- [x] 4.2 Таск `desktopAppImage` (`jpackage`, тип `dmg`) — стабильный `--mac-package-identifier com.example.furniturecalculator`. Classpath собирается через стандартный `installDist` (плагин `application`). По пути пришлось решить два не описанных в design.md нюанса: (1) современный JavaFX требует module-path — если просто положить javafx-jar'ы в classpath вместе с backend'ом, падает `"JavaFX runtime components are missing"`; JavaFX-jar'ы вынесены отдельно через `jpackage --app-content` и подключаются в рантайме через `--java-options "--module-path $APPDIR/../fxlibs ..."` (`--app-content` кладёт директорию рядом с `Contents/app`, а не внутрь неё — отсюда `..`); (2) `jpackage` прописывает в classpath лаунчера только сами jar-файлы из `--input`, россыпь файлов (голая `static/`-директория) он не подхватывает — прод-сборка фронтента (`npm run build`) поэтому упаковывается в отдельный jar (`desktopFrontendJar`) перед вложением.
- [x] 4.3 `CFBundleVersion`/`CFBundleShortVersionString` берутся из `project.version` (без `-SNAPSHOT`). macOS требует первую цифру версии ≥ 1 — пока `project.version` ("0.0.1-SNAPSHOT") даёт "0.x", ведущая цифра автоматически заменяется на 1 (например, `1.0.1`). Конкретную версию сборки можно задать через `-PappVersion=X.Y.Z` (не `-Pversion` — у `project.version` уже есть встроенное значение по умолчанию ("unspecified"), из-за которого `-Pversion` тихо не сработал бы).
- [x] 4.4 Собраны и проверены две последовательные версии (`1.0.1` → `1.0.2`) с одинаковым `--mac-package-identifier`: `.app` версии 1.0.2 скопирован поверх версии 1.0.1 (эмуляция переустановки, без изменений в реальной `/Applications`) — файл БД в `~/Library/Application Support/FurnitureCalculator/data/` не изменился (совпадение MD5 до/после), реальный запуск версии 1.0.2 корректно обнаружил существующую схему (`Liquibase: Run: 0, Previously run: 226` — ни один changeset не выполнился повторно) и продолжил работу с теми же данными. Сквозная проверка HTTP (`/`, `/assets/*.js`, `/api/door-configurations`) — везде 200 на обеих версиях.
